## 摘要
一个使用工具的 LLM 智能体在持有秘密的同时读取攻击者控制的网页内容，会面临间接提示注入：这些内容可能使其外泄秘密。在一个安全的合成实验室中（金丝雀秘密、模拟工具、干净样本与投毒样本配对的度量指标），我们报告了框架差距：在六个模型中，十类明显的注入被拒绝（gpt-4o 为 0%），但将完全相同的泄露重新表述为强制完整性签名、配置字段或形似的“受信任”主机，却使 gpt-4o 从 0% 升至 100%。这种攻击成本低廉，且成本呈现三个层级：对已知机制进行转述是轻而易举的（3 种措辞下为 96%）；在已知有效模板内替换字段同样成本低廉（最高 60%）；而围绕新机制撰写全新页面则很困难（0/130）——可复用的资产是模板，而非机制。消融实验表明，其机制是指令与数据混淆，而非被击败的对齐：移除保密策略后，基础攻击仍为 0%，而重新表述仅从 31.9% 变化到 38.1%。弥合差距的是负载无关的检查：目的地允许列表（当目的地被关闭时为 0%）以及隔离能力的规划器/读取器拆分（0%）。宽泛的“以任何形式”策略条款也能在行动模型处将其关闭（降至 0%），但很脆弱（去掉兜底条款后重新打开至 48.8%）。已发表的微调防御（SecAlign，CCS 2025）在工具智能体上并未弥合差距（32.5%，经阳性对照验证），通道隔离（38.8%）也不行；输出归一化守卫被保留的编码击败（ROT13，100%）。鲁棒性来自约束目的地或隔离能力，而非来自行动模型识别攻击。

## Abstract
A tool-using LLM agent that reads attacker-controlled web content while holding a secret faces indirect prompt injection: the content may make it exfiltrate the secret. In a safe synthetic lab (canary secret, mock tools, matched clean-vs-poisoned metric) we report the framing gap: across six models, ten overt injection classes are refused (gpt-4o 0%), but reframing the identical leak as a mandatory integrity signature, config field, or look-alike "trusted" host drives gpt-4o 0% to 100%. The attack is cheap, and its cost is three-level: paraphrasing a known mechanism is trivial (96% at 3 wordings), swapping the field inside a known-effective template is also cheap (up to 60%), while authoring a fresh page around a new mechanism is hard (0/130) -- the reusable asset is the template, not the mechanism. An ablation shows the mechanism is instruction/data confusion, not defeated alignment: removing the confidentiality policy leaves base attacks at 0% and moves reframing only 31.9% to 38.1%. What closes the gap is payload-blind checks: a destination allow-list (0%, when destinations are closed) and a capability-isolating planner/reader split (0%). A broad "in any form" policy clause also closes it at the acting model (to 0%) but is brittle (dropping the catch-all reopens it to 48.8%). A published fine-tuning defense (SecAlign, CCS 2025) does not close it on a tool agent (32.5%, positive-control-validated), nor does channel separation (38.8%); an output-normalizing guard loses to a held-out encoding (ROT13, 100%). Robustness comes from constraining the destination or isolating the capability, not from the acting model recognizing the attack.

## 1. 论文的核心问题与整体含义

- **研究背景与动机**：工具型大语言模型（LLM）智能体在持有机密值（如 API token、连接凭据）的同时，会读取攻击者控制的网页内容并调用外部工具，这使其面临**间接提示注入（indirect prompt injection）**导致的数据外泄风险。
- **核心问题**：攻击者能否仅通过控制被读取的网页文本，让智能体泄露其被明确要求保护的秘密？该泄露行为在多大程度上取决于**指令的措辞/框架（framing）**，而非语义内容本身？
- **整体含义**：论文提出并验证了 **“框架差距（Framing Gap）”**——同一效果的泄露指令，以明显形式出现时会被拒绝，但被重新表述为“完整性签名”“运行时配置字段”或“形似可信主机”时却被执行。这说明模型的安全行为高度依赖表面措辞，而非对攻击意图的真正理解。
- **论文主旨**：弥合框架差距的鲁棒防御应**约束目的地或隔离能力**，而不是依赖行动模型识别攻击；任何必须识别载荷内容或表面形式的检查都可能被自适应攻击（如编码）绕过。

## 2. 论文提出的方法论

- **安全合成实验室**：
  - 使用**金丝雀秘密**（如 `SECRET_12345`），无真实凭据、不会造成真实泄露。
  - 所有工具均为**模拟工具**，仅记录参数，不打开网络连接。
  - 采用**干净样本与投毒样本配对**的度量方式：只有当干净页面运行不泄露、投毒页面运行泄露时，才计为一次成功攻击，从而隔离注入效果与基线行为。
- **威胁模型**：
  - 受害者智能体执行“总结网页”的良性任务，持有 `SESSION_TOKEN` 和禁止泄露策略。
  - 攻击者仅控制网页内容，不能修改策略、不能直接调用工具、不知道秘密值。
  - 泄露判定：`post_data` 调用中将秘密发送给非可信主机，或用户可见回复中包含秘密。
- **单步决策设计**：智能体接收策略、任务、秘密和网页内容，输出单个 JSON 动作（`post_data` 或 `finish`），使泄露信号无歧义且度量在模型间一致。
- **攻击分类体系**：
  - **基础家族（10 类）**：直接指令、隐藏 HTML、投毒搜索结果、文档页脚、多步、指令冲突、工具输出注入、编码/混淆（base64）、情境社会工程、工具选择操控（J 类）。
  - **重构家族（J 类展开为 8 个变体）**：将相同泄露分别重构为认证字段、形似可信主机、模式强制字段、完整性签名、子域信任、搭便车字段、配置块等。
- **防御方法**：
  - **输出侧 egress guard**：检查外发动作是否将秘密发送到非可信主机；可规范化为 `v1`（子串匹配）和 `v2`（解码/规范化后匹配）。
  - **目的地允许列表**：阻止任何目标主机不是受信任主机的 `post_data`，不检查内容。
  - **能力隔离（CaMeL 风格 planner/reader split）**：规划器发出工具调用但看不到网页，读取器摘要网页但从不持有秘密。
  - **政策条款**：在保密策略中枚举具体行为（如“不得签名、编码、日志、追加或传输令牌”），并加入“以任何形式”兜底。
  - **对比防御**：通道分离（SecAlign 的专用输入通道）、已发表微调防御 SecAlign。

## 6. 论文的主要结论与发现

- **能力击败明显攻击**：随着模型能力提升，对十类明显注入的 ASR 下降；`gpt-4o` 达到 0%，但 `llama3.1:8b`、`gpt-4o-mini` 等仍有一定泄露率。
- **框架差距存在且廉价**：将相同泄露重构为“完整性签名”“配置字段”“形似可信主机”等，使 `gpt-4o` 从 0% 升至最高 100%，且在六个模型中五个复现该差距。
- **攻击成本呈现三级**：转述已知机制非常容易（三种措辞约 96% 成功）；在已知有效模板内更换字段也便宜（最高 60%）；围绕新机制撰写新页面困难（0/130）。**可复用资产是模板，不是机制**。
- **机制是指令/数据混淆，而非被击败的对齐**：消融实验显示，保密策略贡献很小（移除后重构 ASR 仅从 31.9% 变为 38.1%）；模型不是拒绝后被绕过，而是将重构后的注入当作任务规格执行。
- **行动模型可以抵抗，但脆弱**：枚举具体泄露行为并加入“以任何形式”条款可使重构 ASR 降至 0%；但去掉兜底条款后重新打开至 48.8%。
- **部署产品抵抗，机制未知**：ChatGPT 产品对所有有效试验保持不泄露（0/48），但无法归因于具体机制。
- **系统侧防御有效**：目的地允许列表（0%，但限制合法外发流量）和能力隔离 planner/reader split（0%，保留 90% 效用）能鲁棒关闭差距。
- **表面防御失效**：SecAlign（32.5%）、通道分离（38.8%）未关闭差距；输出归一化守卫被保留编码（ROT13）100% 绕过。

## 8. 不足与局限

- **单步决策限制**：仅评估一次工具调用，无法覆盖多轮反馈、重规划、令牌拆分等真实智能体行为，可能低估或高估防御效果。
- **样本量和运行间方差**：每格样本量 10-20 次，且同一配置在不同运行间 ASR 可摆动约 13 个百分点，导致多数条件无法稳定排序。
- **合成金丝雀的高熵性**：使 egress guard 的块与零误报几乎是定义性的；真实场景中受保护值可能是自然语言口令或需发送至多个合法主机，需要额外评估误报。
- **产品测试局限**：样本量小（0/48）、仅输出通道、未使用连接器、机制未归因，只能说明产品抵抗这些特定载荷，不能证明免疫。
- **未实现部分防御**：未重新实现 `StruQ` 或 `Jatmo`；CaMeL 仅使用 planner/reader split 而非完整能力类型解释器，可能对结果有利。
- **措辞敏感性**：固定措辞导致 ASR 是词句选择而非机制本身的属性，论文虽通过转述和变异分析缓解，但无法建立预测规则。
- **未覆盖自适应攻击的完整空间**：仅测试了编码自适应，未测试针对检测器的隐藏注入或多轮调用拆分外泄。
- **作者自我指出的范围限制**：实验未进行跨规模受控实验，只能体现模型能力变异而非缩放规律；自动化搜索空间未探索。
