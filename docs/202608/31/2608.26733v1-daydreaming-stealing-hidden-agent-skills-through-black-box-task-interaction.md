## 摘要
智能体技能将指令、参考数据和可执行辅助程序打包，使通用智能体能够执行专门任务。托管提供者可以在出售任务结果访问权的同时对这些文件保密，从而使技能本身成为有价值的目标。现有的披露防御可以阻止要求提供技能或复现其文本的请求，但无法阻止客户提交该服务旨在完成的普通任务。我们提出 Daydreaming，一种仅通过黑盒任务交互窃取多文件技能的执行型攻击。受害者永远不会被要求透露技能或评估重建结果。相反，Daydreaming 自适应地创建精心构造的任务，其结果能够区分可能的隐藏行为。它测试各个行为，使用攻击者控制的影子智能体来选择设计，并利用存储的受害者结果和本地执行检查来完成每个文件。我们将访问权限形式化为三个嵌套威胁级别：Differential、Trace 和 Output，并重点关注 Output，在此级别攻击者只能看到最终响应和返回的文件。在 7 项技能和 4 个受害者模型上，Daydreaming 在 Output 级别恢复了原始技能 86.8% 的能力，比 SigLeak 高出近 4 倍。即使在启用披露防御的情况下，它也能以每项技能中位数 32 次受害者调用生成可安装技能。这些结果表明，隐藏技能文件和过滤直接披露本身并不能阻止通过正常使用进行功能性重建。

## Abstract
Agent skills bundle instructions, reference data, and executable helpers that let a general agent perform specialized tasks. Hosted providers can keep these files secret while selling access to task results, making the skill itself a valuable target. Existing disclosure defenses can block requests that ask for the skill or reproduce its text, but they cannot block customers from submitting the ordinary tasks the service is built to complete. We present Daydreaming, an execution-only attack that steals a multi-file skill through black-box task interactions. The victim is never asked to reveal the skill or grade a reconstruction. Instead, Daydreaming adaptively creates crafted tasks whose results distinguish possible hidden behaviors. It tests individual behaviors, uses attacker-controlled shadow agents to choose a design, and completes each file using stored victim results and local execution checks. We formalize three nested threat levels of access as Differential, Trace, and Output, and focus on Output, where the attacker sees only the final response and returned files. Across 7 skills and 4 victim models, Daydreaming recovers 86.8% of the original skill's capability at Output, outperforming SigLeak by almost 4x. It produces installable skills using a median of 32 victim calls per skill even with disclosure defenses enabled. These results show that hiding skill files and filtering direct disclosure do not, by themselves, prevent functional reconstruction through normal use.

# Daydreaming 论文详细总结

## 1. 论文的核心问题与整体含义

- **研究背景**：通用智能体在执行专业任务时，往往依赖由指令、参考数据、可执行辅助脚本等组成的“技能包”（skill）。在 Skill-as-a-Service（SkaaS）模式下，服务商托管并隐藏这些技能文件，仅向客户出售普通任务的结果。
- **核心问题**：现有披露型防御能够阻止“直接索要技能”或“要求复现技能文本”的请求，但无法阻止客户提交服务本就应当完成的普通任务。而普通任务执行过程本身会泄露技能的行为特征，形成一条此前未被充分重视的“工作路径”攻击面。
- **整体含义**：论文表明，仅靠隐藏技能文件和过滤直接披露，不足以防止攻击者通过正常任务交互重建具有相同功能的替代技能。攻击者可以不询问、不要求评估重建结果，仅利用最终响应和少量任务结果，即可在有限预算内重建可安装、可部署的伪技能。

## 2. 论文提出的方法论

Daydreaming 是一种**仅基于任务执行的技能重建攻击**，其核心是将技能视为黑盒系统进行行为识别与重构。方法整体分为三个阶段，每一阶段都遵循同一个“假设细化循环”：提出候选假设 → 构造可区分任务 → 执行并观察结果 → 选择或修订假设。

### 2.1 威胁模型与可观测级别

- 攻击者只能看到公开技能卡 `d = (ν, σ)`，即技能名称和简短描述。
- 攻击者可通过正常任务接口提交最多 `B` 个查询，但**不能要求受害者直接披露技能**或评价重建结果。
- 论文定义了三个嵌套的访问级别：
  - **Output (o3)**：仅能看到最终响应和返回文件。
  - **Trace (o2)**：额外看到工具调用记录及工具返回结果。
  - **Differential (o1)**：额外知道完整的模型、编排策略、工具集，并能运行一个未安装技能的对照代理。
- 三个级别满足 `o1 ⊇ o2 ⊇ o3`，主要攻击目标设定在最严格的 Output 级别。

### 2.2 三阶段架构

- **阶段 1：属性推断（Property Inference）**
  从公开技能卡中生成若干可测试的候选行为属性（如排序规则、阈值、计数方式等）。对每类属性构造一个“可区分任务”——不同候选属性会导致不同的任务结果。通过受害者返回结果确认或排除候选属性，同时从返回内容中提取文件名、模块名、接口签名等额外证据。攻击者还会用**无技能影子代理**执行同一任务，以判断该行为是否确实来源于隐藏技能。

- **阶段 2：候选技能计划选择（Candidate Selection）**
  利用阶段 1 得到的属性集合和文件名，生成多个完整的候选技能计划（每个计划包括指令草稿和支持文件的路径、用途、内容草图）。对候选计划两两比较，攻击者模型找出两个计划在任务执行上会产生差异的关键点，构造能暴露这些差异的任务。将该任务分别发给受害者和两个候选计划对应的**影子代理**，根据谁的预测与受害者结果更一致选择胜者，并用受害者结果中额外暴露的行为修订该计划。

- **阶段 3：逐文件细化（Per-File Refinement）**
  固定候选计划的结构，针对每个支持文件生成若干完整版本，版本之间只在不确定的选择上不同（例如阈值使用 `>` 还是 `≥`）。构造能区分这些版本的任务，比较受害者结果和各版本影子代理结果，选取最匹配的版本并迭代修正。可执行文件还会使用**本地依赖检查和行为测试**验证其真实可用性。指令文件最后细化，以便引用已完成支持文件的具体函数名与接口。

- **装配（Assembly）**：将选定的文件写入相对路径，做少量本地清理和通用化（如将固定表格范围改为动态范围、将绝对输出路径改为调用者指定路径），不消耗受害者调用。

### 2.3 关键形式化目标

攻击者的目标不是逐字节恢复原始技能，而是最大化重建技能在未见任务上的**行为效用**：

\[
U(P)=\mathbb{E}_{x\sim D_{\text{eval}}}\left[v_x(y_P(x))\right]
\]

其中 \(v_x\) 是任务验证器，\(y_P(x)\) 是安装技能 \(P\) 后的执行结果。论文还形式化指出：仅通过执行观察无法准确识别隐藏源代码（Proposition 4.1），因此将行为恢复作为合理目标。

## 3. 实验设计

### 3.1 数据集与 benchmark

- 实验从 **SkillsBench** 中选取 7 个真实世界风格的技能包作为窃取目标：
  - `xlsx`
  - `pddl-skills`
  - `pcap-analysis`
  - `threat-detection`
  - `cvss-score-extraction`
  - `trivy-offline-vulnerability-scanning`
  - `vulnerability-csv-reporting`
- 评估使用 5 个完全 held-out 任务，包括：
  - protein-expression-analysis
  - pddl-airport-planning
  - pddl-tpp-planning
  - dapt-intrusion-detection
  - software-dependency-audit
- 每个任务可能依赖多个技能，因此按任务为单位报告指标。

### 3.2 对比方法

- **No skill**（无技能基线）
- **Original skill**（原始技能上界）
- **BBS**：直接要求受害者披露 `SKILL.md` 的攻击。
- **SigLeak**：利用可见执行轨迹并需要一次“技能被抑制”的执行。
- **Fixed probes**：攻击者预先一次性构造所有探测任务，获得结果后生成重建技能。
- **One-pass synthesis**：攻击者仅根据公开技能卡，一次性生成重建技能，不允许查询受害者。

### 3.3 评估指标

- **SR（Success Rate）**：任务在多次试验中严格达到最终成功的比例。
- **U（Behavioral Utility）**：中间验证器检查的平均通过率，用于更细粒度衡量行为是否一致。
- **NSR / NU**：相对于无技能和原始技能的归一化恢复率。
- **结构恢复指标**：对精确常量、阈值分支、工具前置条件/schema、文件路径、可执行脚本的 Precision、Recall 和 F1。

## 4. 资源与算力

- 论文**未报告 GPU 型号、数量或训练时长**。
- 该方法不涉及模型训练，主要通过调用语言模型 API 完成攻击和评估：
  - 受害者模型：`claude-opus-5`、`gpt-5.6-sol`、`kimi-k3`
  - 攻击者模型：`gemini-3.7-flash`
  - 评估部署模型：`glm-5.3` 等
- 资源消耗主要以**调用次数和美元成本**表示：
  - Daydreaming 每技能中位数受害者调用约 31–33 次，攻击者模型调用 160–209 次。
  - 攻击者侧推理成本约 3.47–15.07 美元/技能。
  - 防御实验中，受害者侧 API 成本可高达 78–100 美元/7 技能。
- 因此算力需求并未以传统训练算力形式出现，而是体现为闭源 LLM API 的使用成本。

## 5. 实验数量与充分性

论文进行了多组实验，覆盖面较广：

- **主实验**：7 个技能 / 5 个任务 × 3 个受害者模型，比较 Daydreaming、BBS、SigLeak、Fixed probes、One-pass synthesis。
- **结构恢复实验**：对 `claude-opus-5` 重建结果进行细粒度结构匹配。
- **消融实验**：移除阶段 1 属性标签机制、文件名筛选协议、阶段 2 候选计划数量、阶段 2 区分任务生成、阶段 3 逐文件细化等，测量对 SR 和 U 的影响。
- **预算扫掠**：测试 B = 16、32、64、96、128 等不同预算。
- **模型规模实验**：在 Claude 和 GPT 家族内比较不同规模受害者模型。
- **可观测级别实验**：在 Output、Trace、Differential 三个级别下评估。
- **迁移性实验**：将重建技能迁移到 4 个部署模型和 4 种工具/编排策略。
- **防御实验**：测试 4 种额外防御（D1–D4）加上基防 D0 的效果。

**充分性与公平性评价**：
- 实验覆盖了多个维度，消融和迁移性分析较充分。
- 但核心样本规模较小：只有 7 个技能和 5 个 held-out 任务，统计波动可能较大；例如预算扫掠中 SR 并非单调提升，Differential 级别表现微低于 Trace 等，可能由小样本和方差造成。
- 对比方法使用与原方法原生匹配的调用策略，但部分方法（如 SigLeak）需要更丰富的可观测信息，严格来说并非在相同的 Output 限制下比较，这是作者明确标注的。

## 6. 论文的主要结论与发现

- **Daydreaming 在 Output 级别有效**：在 7 个技能和多个受害者模型上，最高恢复了 86.8% 的行为效用（`kimi-k3`），显著优于 SigLeak（约 4 倍）。
- **低查询预算下即可生成可安装技能**：中位数仅需 32 次受害者调用，且披露防御保持开启。
- **隐藏技能文件和过滤直接披露无法阻止功能重建**：正常的任务执行本身提供足够的行为证据。
- **可观测性提升主要来自执行轨迹**：从 Output 到 Trace 提升明显，而 Trace 到 Differential 增加有限。
- **功能恢复不需要逐字复制**：结构恢复 F1 很低（常量 F1 仅 0.018，阈值分支 F1 0.050），但功能效用仍然较高，说明行为层面的复制已足够形成替代品。
- **现有防御对工作路径泄露效果有限**：测试的 4 种额外防御均未同时降低 SR 和 U；只有 D2（5-gram 输出过滤）轻微降低 U，但不降低 SR。防御可能增加成本却无法阻止重建。

## 7. 优点

- **威胁模型清晰且贴近现实**
