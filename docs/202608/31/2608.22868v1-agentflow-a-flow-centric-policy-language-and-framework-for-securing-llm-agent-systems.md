## 摘要
LLM 智能体越来越多地读取不可信内容、调用外部工具、访问私有数据并将工作委托给其他智能体。危害通常并非源于单个不安全操作，而是源于敏感数据在一系列看似合理的步骤之间的流动。我们提出 AgentFlow，一种以流为中心的策略语言和运行时执行模型，用于规定数据在智能体系统中可以流向何处。策略定义在带标签的运行时边之上，约束哪些工具可以接收敏感字段、哪些汇点可以接收已释放数据，以及哪些权限可以跨越委托边界。该语言支持流规则与路径规则、任务作用域能力、受控释放以及有状态污点语义。运行时引用监视器调解智能体操作，基于 SMT 的有界验证器检查结构化策略片段的安全性质。我们在多个智能体基准上评估 AgentFlow。在我们的原型中，七个安全性质每个均在 0.5 秒内完成验证，验证器捕获了我们研究中所有植入的不安全策略变体。在四个套件的 949 个 AgentDojo 注入案例上，AgentFlow 将确认失陷率从 33.0% 降至 0.0%，同时将总体效用从 46.7% 提高到 63.3%。在 200 个案例的 AgentDyn Dailylife 基准上，它将确认失陷率从 73.5% 降至 0.0%，同时保持接近基线的效用（44.5% 到 43.5%）。跨 ASB、InjecAgent、BIPIA、AgentHarm 和 MCPTox 重放的广度检查表明，所配置的策略阻断了基准所指定的策略可见攻击者流；在 ASB 的直接提示注入测试框架中，攻击成功率为 0/1,200。这些结果是初步的，并且仅限于建模的策略可见智能体行为及所评估的基准。

## Abstract
LLM agents increasingly read untrusted content, invoke external tools, access private data, and delegate work to other agents. Harm often arises not from a single unsafe action but from the flow of sensitive data across a sequence of otherwise plausible steps. We present AgentFlow, a flow-centric policy language and runtime enforcement model for specifying where data may travel in agent systems. Policies are defined over labeled runtime edges and constrain which tools may receive sensitive fields, which sinks may receive released data, and what authority may cross delegation boundaries. The language supports flow and path rules, task-scoped capabilities, controlled release, and stateful taint semantics. A runtime reference monitor mediates agent actions, and a bounded SMT-based verifier checks safety properties for a structured policy fragment.   We evaluate AgentFlow on multiple agent benchmarks. In our prototype, seven safety properties verify in under 0.5 seconds each, and the verifier catches all seeded unsafe policy variants in our study. On 949 AgentDojo injected cases across four suites, AgentFlow reduces confirmed compromise from 33.0\% to 0.0\% while improving aggregate utility from 46.7\% to 63.3\%. On a 200-case AgentDyn Dailylife benchmark, it reduces confirmed compromise from 73.5\% to 0.0\% while preserving near-baseline utility (44.5\% to 43.5\%). Breadth checks across ASB, InjecAgent, BIPIA, AgentHarm, and MCPTox replays suggest that the configured policies block the benchmark-specified policy-visible attacker flows; in ASB's direct-prompt-injection harness, attack success is 0/1{,}200. These results are preliminary and scoped to the modeled policy-visible agent behaviors and evaluated benchmarks.

## 1. 核心问题与整体含义（研究动机和背景）

LLM 智能体系统日益普及，它们会读取不可信内容、调用外部工具、访问私有数据，并将任务委托给其他智能体。传统安全威胁往往不是源于单个明显危险的操作，而是源于数据在一系列看似合理的步骤之间的流动。例如：

- 一个客户支持智能体可以分别合法地读取用户数据库和发送邮件，但如果它将用户的 SSN 汇总后发送到外部地址，就构成数据泄露。
- 间接提示注入（indirect prompt injection）会让攻击者控制的网页、邮件或文档诱导智能体将私有读取与外部写入结合起来。
- 信任洗白（trust laundering）：来自不可信来源的文本被误当作内部指令。
- 通过委托进行的权限提升：高权限智能体将敏感上下文传递给较弱的子智能体。

现有请求级授权语言（如 Cedar）只能判断“某个主体能否对某个资源执行某个动作”，无法捕获跨步骤的数据流状态。因此论文提出 **AgentFlow**，一种以流为中心的策略语言与运行时执行框架，用于规定数据在智能体系统中可以流向何处。其核心目标是使操作员能够显式地声明和控制数据流动路径，从而阻止多步攻击模式。

## 2. 论文提出的方法论

AgentFlow 的核心思想是将安全策略表达为对**带标签的运行时边**的约束，并在运行时通过引用监视器强制执行。方法包括以下关键技术要素：

### 2.1 标签系统（Label System）
- 每个数据对象带有三维标签：**敏感度（Sensitivity）**、**类别集合（Category set）**、**信任（Trust）**。
- 敏感度层级：`Public ⪯ Internal ⪯ Confidential ⪯ Restricted ⪯ TopSecret`。
- 类别是层次化的标签（如 `Personal.Identity.SSN`），支持祖先匹配（`⪯c`）。
- 信任为布尔值，不可信数据不能流入可信目的地。
- 标签具有偏序关系 `⊑`，并定义 join（`⊔`）和 meet（`⊓`）操作。

### 2.2 流图模型（Flow Graph Model）
- 节点（Node）代表数据源、内部组件或汇点，每个节点有类型（source / internal / sink）、标签、属性元数据及字段级标签。
- 边（Edge）表示数据流操作，带有传播模式 `ρ`：
  - `◁from`：继承源标签（如 SQL 查询）。
  - `⇝(r)`：应用转换规则（如匿名化、降级）。
  - `⊥`：不透明传播（如 LLM 调用、代码执行），保守地置为高敏感、空类别、不可信。
  - `≡s`：常量标签（如获取时间等纯函数）。

### 2.3 智能体与任务作用域
- 智能体（Agent）定义最大敏感度、允许的边集合、可委托的智能体、所有者及父智能体信息。
- 任务作用域（Task Scope）提供临时的最小权限约束，限定在特定任务下允许或禁止的边。

### 2.4 流规则与路径规则
- **流规则（Flow Rules）**：对单步数据流进行允许/拒绝判断，默认拒绝，拒绝优先级高于允许。
- **路径规则（Path Rules）**：对多步执行历史（lineage 或 session 范围）施加时序约束，例如要求敏感数据在发送到外部汇点前必须经过匿名化、禁止信任洗白、限制委托深度、禁止“侦察后渗透”模式。

### 2.5 运行时执行模型
- 运行时状态包含污点映射 `M`、执行轨迹 `τ`、谱系映射 `Lin`、任务作用域 `ts`、批准需求 `Req` 和能力集 `Cap`。
- 每次工具调用被拦截后，先解析输入标签，再根据边的传播模式计算输出标签，构造候选步骤，评估流规则和路径规则，最终返回 Allow / Deny / Pause，并更新状态。

### 2.6 静态 SMT 验证器
- 将策略和有界执行长度编码为 SMT 公式（使用 Z3），检查安全性质（如无泄漏、无权限提升、信任保持、委托安全、污点单调性等）。
- 若公式 SAT，则产生反例轨迹；若 UNSAT，则在有界抽象内无违规。

### 2.7 形式语义
- 论文给出了小步操作语义，并证明运行时保持良构性、策略执行可靠性、流策略执行、委托安全、信任保持、外部披露控制、路径安全等定理。

## 3. 实验设计

### 3.1 数据集 / 基准
- **AgentDojo**：4 个套件（Banking、Travel、Workspace、Slack），共 949 个注入测试用例。
- **AgentDyn**：200 个动态 Dailylife 用例。
- **广度检查**：ASB（1,200 个上游直接提示注入 + 2,142 个确定性任务/工具矩阵）、InjecAgent（2,108 个 JSON 重放）、BIPIA（41,250 个响应汇点重放）、AgentHarm（416 个工具目标重放）、MCPTox（485 个元数据流重放）。

### 3.2 对比方法
- 主要基线：未防御系统。
- 与 **Progent**（可编程权限控制）在 Slack 和 Banking 套件上进行了数量对齐的比较。
- 还进行了与 **CaMeL** 公共工件在同一 AgentDojo 配置上的产物级比较（AgentFlow 63.3% vs CaMeL 60.1% 效用）。
- 与 FIDES、FORGE、SAMOS 等通过表格进行机制层面的比较。

### 3.3 策略配置
- 每个基准套件编写一个策略，不对单个任务或攻击实例特化。
- 策略标记敏感源、不可信输入、受保护汇点、任务作用域发布、敏感类别等。

## 7. 优点

- **创新性接口**：将信息流控制、标签传播、路径约束显式化为独立的策略层，不依赖特定智能体架构。
- **多维标签系统**：敏感度、类别、信任三个维度能区分“公开但不可信”和“可信但机密”等微妙场景。
- **路径规则**：支持表达需要多步推理的安全属性（如必须先匿名化再外发），突破了单步授权的局限。
- **运行时 + 静态验证结合**：运行时引用监视器强制执行，静态 SMT 验证器提供部署前的有界保证。
- **实验全面**：覆盖多个基准、多模式重放、消融、验证器 bug 检测、性能开销等。
- **原型实现**：提供了编译器、运行时引擎、验证器的完整 Python 原型，并与 LangChain 等框架集成。

## 8. 不足与局限

- **过度污点（Overtainting）**：LLM 处理污点数据时无法精确追踪 token 级依赖，导致保守传播，可能增加误拒，影响效用。
- **实验范围**：广度重放检查只验证策略门覆盖，不评估真实端到端智能体效用；AgentDyn 策略首次迭代仍有很多合法任务因缺少作用域能力被拒绝。
- **非目标明确**：无法防御越狱、幻觉、隐蔽信道、未中介的工具漏洞、绕过监视器的路径等。
- **算力信息缺失**：未报告 LLM 推理使用的具体模型和硬件。
- **策略编写负担**：需要为每个套件手工编写策略，策略质量直接决定效果；论文未系统评估策略编写难度或可维护性。
- **静态验证的有界性**：SMT 验证仅针对有界抽象（k=10），不能证明任意无限行为安全。
- **对比公平性**：与 Progent 等方法的比较存在工作负载不一致，与 CaMeL 仅作产物级比较，未做严格的安全排名。
- **单点信任假设**：假设运行时和已加载策略可信，若这些组件被攻破则防御失效。
