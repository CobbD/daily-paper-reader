## 摘要
尽管大语言模型具有很强的代码生成能力，但它们往往难以生成安全代码，其输出经常包含安全漏洞。安全代码生成本质上具有挑战性，因为它需要解决一个多目标问题：功能正确性与安全性。现有方法通过注入外部安全知识或使用智能体反馈与迭代精化来应对这一挑战。然而，指南检索常常让生成器将通用建议转化为特定任务的安全实现，而共享对话的多智能体反馈可能模糊角色边界并遭受上下文膨胀。我们提出 MACGen，一个多智能体框架，它整合了规划、安全分析、代码合成和精化，以联合优化安全性与功能性。规划器构建逐步计划以满足功能需求。安全顾问识别可能的 CWE 并合成任务特定的指南，编码器随后基于这些产物生成代码，审查者发出视角分离的反馈。每个智能体不从上游阶段共享完整对话历史，而只接收结构化产物，从而强化角色专业化并减少不受控制的上下文增长。在 CWEval 和 BaxBench 上，MACGen 相较直接提示平均将 F&S@1 分别提高了 19.61 和 10.57 个百分点。

## Abstract
Despite their strong ability to generate code, large language models often fail to produce secure code, as their outputs frequently contain security vulnerabilities. Secure code generation is inherently challenging because it requires solving a multi-objective problem: functional correctness and security. Existing approaches address this challenge by injecting external security knowledge or by using agentic feedback and iterative refinement. However, guideline retrieval often leaves the generator to translate generic advice into task-specific secure implementations, while shared-dialogue multi-agent feedback can blur role boundaries and suffer from context bloat.   We present MACGen, a multi-agent framework that integrates planning, security analysis, code synthesis and refinement to jointly optimize security and functionality. A planner constructs a step-by-step plan to satisfy functional requirements. A security advisor identifies likely CWEs and synthesizes task-specific guidelines, a coder then generates code grounded in these artifacts, and a reviewer issues perspective-separated feedback. Rather than sharing full dialogue histories, each agent receives only structured artifacts from upstream stages, enforcing role specialization and reducing uncontrolled context growth. On CWEval and BaxBench, MACGen improves F&S@1 over direct prompting by 19.61 and 10.57 percentage points (pp) on average, respectively.

## 1. 论文的核心问题与整体含义

- **研究动机**：大语言模型生成代码时常包含安全漏洞（如 MITRE CWE Top-25 中的多种弱点），而现有实用部署对代码功能与安全性同时提出了要求。
- **核心矛盾**：安全代码生成是一个**多目标优化问题**，需要同时满足功能正确性和安全性；安全约束往往在实现层引入额外的输入校验、权限检查、更安全的 API 选择等决策，从而增加任务复杂度。
- **现有方法不足**：
  - 知识注入类方法（RAG、检索安全指南）提供的指南通常是**通用建议**，缺少任务相关的变量名、函数签名、控制流等上下文，生成器仍需自行将其适配为具体安全实现。
  - 多智能体反馈方法（如 INDICT）使用**共享对话历史**，可能模糊角色边界、产生角色干扰，并随上下文增长导致注意力退化、token 开销上升。
- **整体含义**：论文提出 MACGen，通过**角色专业化、artifact-only 接口、任务特定安全指南合成**，将安全推理嵌入从规划到评审的整个开发流程，从而更可靠地同时优化功能与安全。

## 2. 论文提出的方法论

### 2.1 总体框架

- MACGen 由四个专用智能体组成：**Planner（规划器）、Security Advisor（安全顾问）、Code Generator（代码生成器）、Reviewer（审查器）**。
- 流程：
  1. Planner 生成高层功能计划；
  2. Code Generator 根据任务与计划生成草稿代码；
  3. Security Advisor 分析任务、计划和草稿代码，识别潜在攻击面并合成任务特定安全指南；若无风险则触发**早期退出**；
  4. Code Generator 基于功能计划和安全指南生成最终代码，并进行语法检查与自修正；
  5. Reviewer 执行功能与安全两个视角的分离检查，若发现错误则反馈给 Code Generator 迭代精化，最多迭代 M=2 次。
- **核心设计**：各智能体只接收上游的**结构化产物**（计划、指南、代码），不共享完整对话历史，从而由接口本身强制角色边界。

### 2.2 标准驱动的安全知识库

- 知识来源：CERT、OWASP ASVS、OpenSSF、OWASP Cheat Sheets 等权威安全标准。
- 构建流程：
  1. 使用 LLM 将原始文档规范化为紧凑的四字段模式：**WHAT、WHY、HOW、EXAMPLE**；
  2. 对每条指南进行向量嵌入，并用 FAISS 建索引；
  3. 推理时，Security Advisor 根据识别出的 CWE 组构造查询，按余弦相似度检索 top-K 指南，再对多个查询的结果取并集。
- 检索公式可概括为：对每个查询 \(q_j\)，从知识库中选择 K 个余弦相似度最高的指南，最终候选集为所有查询检索结果的并集。

### 2.3 Security Advisor 的多阶段流水线

1. **早期退出 triage**：检查任务与草稿代码是否存在预定义攻击面（不可信输入、网络/API、数据库、文件系统、执行/反序列化、认证/密钥、内存/资源、加密等）；若无，则跳过后续检索，节省开销。
2. **CWE 组提取**：基于任务与功能计划，输出可能的风险组，每项包含 group_name、why、cause_cwes、effect_cwes、likelihood。
3. **标准驱动指南生成**：用 CWE 组查询知识库，基于检索结果生成第一组安全指南。
4. **基于代码的指南生成**：检查草稿代码中的不安全编码模式，生成第二组轻量、代码可证实的指南。
5. **验证与整合**：合并两组指南，检查其是否与功能需求冲突，删除或修改破坏功能的约束。

### 2.4 Code Generator 与 Reviewer

- Code Generator：首先生成草稿代码，再根据功能计划和安全指南生成安全实现；生成后使用语法检查器循环自修正，保证语法正确。
- Reviewer：分别从**功能正确性**和**安全性**两个视角审查代码；针对功能错误或残留安全问题给出反馈；每次仅输出针对特定视角的意见，避免角色混杂。
