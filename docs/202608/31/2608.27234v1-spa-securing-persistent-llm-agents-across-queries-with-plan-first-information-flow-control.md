## 摘要
大语言模型（LLM）智能体越来越多地在不可信的网页、文档、工具和持久状态上运行，同时对安全敏感资源行使权限。现有防御通常只保护规划过程或单个工具交互，但持久智能体面临更广泛的威胁：攻击者控制的数据可以改变控制流、进入安全敏感的工具参数，或危害后续查询。我们提出 SPA，一种计划优先的架构，可保护规划、执行和跨查询状态重用。SPA 每个查询仅调用一次规划器，以声明式领域特定语言生成完整的可执行计划，然后应用双格信息流控制来跟踪显式数据流和控制依赖中的机密性与完整性。为了在不将不可信负载重新暴露给规划器的情况下支持持久性，SPA 将执行结果存储为带标签的工件，并在后续规划期间仅揭示语义元数据。我们在 AgentDojo 和 AgentDojo-MQ 上评估 SPA，后者是我们为衡量安全状态重用和延迟攻击而设计的多查询扩展。在“tool_knowledge”攻击下，带信息流控制的 SPA 在 AgentDojo 上将攻击成功率降至零，在 AgentDojo-MQ 上降至 0.2%。我们的结果表明，计划优先执行与保留标签的持久性相结合，可以显著增强持久 LLM 智能体，同时揭示严格完整性执行带来的重要安全-效用权衡。

## Abstract
Large language model (LLM) agents increasingly operate over untrusted webpages, documents, tools, and persistent states while exercising authority over security-sensitive resources. Existing defenses typically protect either planning or individual tool interactions, but persistent agents face a broader threat: attacker-controlled data can alter control flow, enter security-sensitive tool arguments, or compromise later queries. We present SPA, a plan-first architecture that secures planning, execution, and cross-query state reuse. SPA invokes the planner once per query to generate a complete executable plan in a declarative domain-specific language, then applies dual-lattice information-flow control to track confidentiality and integrity across explicit data flows and control dependencies. To support persistence without re-exposing untrusted payloads to the planner, SPA stores execution results as labeled artifacts and reveals only semantic metadata during later planning. We evaluate SPA on AgentDojo and AgentDojo-MQ, which is our multi-query extension for measuring secure state reuse and delayed attacks. Under the 'tool_knowledge' attack, SPA with information-flow control reduces attack success to zero on AgentDojo and 0.2% on AgentDojo-MQ. Our results show that plan-first execution combined with label-preserving persistence can substantially strengthen persistent LLM agents, while revealing an important security-utility tradeoff introduced by strict integrity enforcement.

## 1. 论文的核心问题与整体含义

- **研究背景**：LLM 智能体越来越多地处理不可信的网页、文档、工具输出，并持有对安全敏感资源（如通信、文件、支付）的权限。攻击者可通过间接提示注入（indirect prompt injection）影响智能体的行为。
- **核心问题**：现有防御通常只保护“规划”或“单个工具交互”，无法应对**持久智能体**（persistent agents）面临的更广泛威胁：
  - 攻击者控制的数据可以改变控制流；
  - 可以成为安全敏感工具的参数（如银行账号）；
  - 可以存储在持久状态中，在后续查询中被激活（跨查询攻击）。
- **整体含义**：需要一种能够同时保护**规划**、**执行**和**跨查询状态重用**的架构，将信息流安全从单次查询扩展到多次查询的持久状态中。

## 2. 论文提出的方法论

- **核心思想**：SPA（Secure Persistent Agent）采用**计划优先（plan-first）**架构，每个用户查询只调用一次规划器，生成完整的可执行计划，之后不再修改。通过**双格信息流控制（dual-lattice IFC）**在计划执行前静态验证机密性与完整性。
- **关键技术细节**：
  - **声明式 DSL**：使用受限的 JSON DSL 表示计划，包含六种步骤：`retrieve`（取持久工件）、`tool`（调用外部工具）、`q-llm`（隔离 LLM 处理不可信文本）、`display`（用户可见输出）、`condition`（条件分支）、`loop`（循环）。DSL 限制使数据流与控制依赖在语法上显式可见。
  - **信息流模型**：
    - 每个值携带 `(C, I)` 标签，分别表示机密性（confidentiality）和完整性（integrity）。
    - 采用 Bell–LaPadula 机密性规则 + Biba 完整性规则：信息只能流向机密性不低于源、完整性不高于源的端点。
    - **显式流**：工具调用时检查所有输入的有效标签是否满足工具策略（`λin`），输出标签为输入标签与工具输出基线 `λout` 的合并。
    - **隐式流**：条件分支和循环使用程序计数器标签 `pc`，将控制依赖纳入数据流分析。
    - **显示端点**：对 `display` 步骤，违反策略的项用红色标记代替，而不是拒绝整个计划（选择性编辑）。
  - **持久上下文**：每个生成的工件存储为三个视图：`Σα`（仅元数据：schema、intent、output_semantics、source_query）、`Σω`（实际值）、`Σλ`（安全标签）。后续规划器只能看到 `Σα`，不能看到负载；执行时必须通过 `retrieve` 显式取回，并恢复其原始标签。
  - **抽象规划模式**：可选模式，规划器只从用户查询合成抽象工具 schema，然后映射到已安装的具体工具，进一步隔离恶意工具元数据。
- **算法流程**：每个查询依次经历：投影元数据 → 规划生成 DSL 计划 → 语法验证 → 抽象映射（可选）→ 静态 IFC 验证 → 执行 → 更新持久上下文。整个管线是**失败关闭（fail-closed）**的，任何一步失败即终止。

## 6. 论文的主要结论与发现

- **安全性**：
  - 在 `tool_knowledge` 攻击下，带 IFC 的 SPA 在单查询 AgentDojo 上将 ASR 降至 **0.0%**，在 AgentDojo-MQ 上降至 **0.2%**。
  - 即使不带 IFC，计划优先架构本身也能显著降低 ASR（0.4%），说明单次规划隔离了当前查询的工具输出。
- **效用损失**：
  - 启用 IFC 使具体模式基线效用从 53.0% 降至 29.0%（AgentDojo），从 62.5% 降至 35.3%（AgentDojo-MQ）。
  - 抽象规划效用更低（14.1% 无 IFC, 6.7% 带 IFC），主要受工具映射失败拖累。
- **跨查询重用**：
  - 即使负载对规划器隐藏，具体模式仍保持高重用：软命中 95.4%（无 IFC）、89.9%（带 IFC）。
  - 开放内存（直接暴露持久值）仅略微提高效用（+3.4pp），未显著增加延迟注入 ASR。
- **安全–效用权衡**：严格完整性执行会拒绝许多合法工作流，因为它们需要依赖外部低完整性数据的动作，这是根本性的权衡。

## 7. 优点

- **架构新颖且完整**：计划优先 + 双格 IFC + 持久工件标签，从规划到跨查询执行形成闭环安全。
- **静态可验证**：DSL 设计使数据流与控制依赖在语法上显式，可以在执行前验证，避免任何外部效应发生后才发现违规。
- **失败关闭**：任何验证失败都终止查询，不执行部分计划，避免不安全执行。
- **持久性设计巧妙**：将负载与元数据分离，既支持跨查询重用，又不把不可信内容重新暴露给规划器。
- **评估全面**：自建 AgentDojo-MQ 提供了衡量跨查询攻击与重用能力的公开数据集，有明确的指标和对照。
- **论文透明度较高**：提供了提示模板、算法伪代码、附加大图和开放代码。

## 8. 不足与局限

- **攻击覆盖面不足**：只测试 `tool_knowledge`，缺少针对持久状态延迟中毒、控制流注入等设计的攻击。
- **完整性策略过于严格**：统包（broad）的 Biba 风格完整性检查导致大量合法任务失败，缺乏细粒度（如字段级标签、参数特定要求）的处理。
- **抽象模式不成熟**：映射阶段失败率过高（约 75%），导致抽象模式效用极低，难以说明抽象工具元数据防护的实际价值。
- **依赖可信配置**：格、工具政策、绑定关系属于可信计算基，若配置错误可能误拒或误放行。
- **实验泛化性有限**：AgentDojo-MQ 基于手工依赖图和自然语言改写，可能引入人工偏差；仅使用单一模型，未验证跨模型性能。
- **资源未披露**：缺少算力与训练信息，影响可复现性与资源评估。
- **未处理模型级越狱或对齐失败**：论文声明不防御模型自身问题，因此安全保证仅覆盖信息流错误，而非所有攻击面。
