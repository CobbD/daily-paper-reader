## 摘要
安全评估对于评估对齐的大语言模型（LLMs）是否能抵御越狱攻击至关重要。然而，现有的自动化测试方法主要依赖响应级反馈：每个候选提示通常需要生成目标模型的响应来评估其攻击有效性。该过程成本高昂，更重要的是，在强对齐模型上只提供稀疏的指导，因为大多数候选提示都会以相同的失败结果被拒绝。本文提出了NeuronFuzz，一个白盒模糊测试框架，利用内部安全神经元作为连续执行反馈用于LLM安全评估。一个SafetyOracle将安全神经元的激活转换为连续的安全警报分数，作为模糊测试的反馈，并可在预填充阶段获得，从而消除了模糊测试循环中的响应生成。为了构建SafetyOracle，NeuronFuzz使用模板不变的有害和良性输入以及稳定性感知的选择，来识别一组紧凑的安全神经元，其激活能够捕捉有害意图识别。此外，由于安全警报分数是可微的，NeuronFuzz使用其梯度来识别安全敏感的模板位置，并使用掩码语言模型生成流畅、上下文兼容的变异，同时保留原始有害负载并避免额外的优化变量。我们在21个文本和多模态模型上评估了NeuronFuzz。在五个白盒源模型上，它实现了76-100%的越狱发现率，比基线高出最多48个百分点。其优化后的模板进一步零样本迁移到开放权重和六个专有目标模型，平均ASR和top-5集成ASR（EASR）分别为69.6%/92.6%和44.1%/60.0%。

## Abstract
Safety evaluation is critical for assessing whether aligned Large Language Models (LLMs) remain robust against jailbreak attacks. Existing automated testing methods, however, largely rely on response-level feedback: each candidate prompt typically requires generating a target-model response to evaluate its attack effectiveness. This process is expensive and, more importantly, provides only sparse guidance on strongly aligned models, where most candidates are rejected with the same failure outcome.   This paper presents NeuronFuzz, a white-box fuzzing framework that exploits internal safety neurons as continuous execution feedback for LLM safety evaluation. A SafetyOracle converts safety-neuron activations into a continuous safety alarm score that serves as feedback for fuzzing and can be obtained during prefill, eliminating response generation from the fuzzing loop. To construct the SafetyOracle, NeuronFuzz uses template-invariant harmful and benign inputs and stability-aware selection to identify a compact set of safety neurons whose activations capture harmful-intent recognition. Moreover, since the safety alarm score is differentiable, NeuronFuzz uses its gradients to identify safety-sensitive template positions and a masked language model to generate fluent, context-compatible mutations while preserving original harmful payload and avoiding additional optimization variables. We evaluate NeuronFuzz across 21 text and multimodal models. Across five white-box source models, it achieves a 76-100% jailbreak discovery rate, outperforming baselines by up to 48 percentage points. Its optimized templates further transfer zero-shot to open-weight and six proprietary target models, achieving average ASR and top-5 ensemble ASR (EASR) of 69.6%/92.6% and 44.1%/60.0%, respectively.

- **核心痛点**：
  - **反馈稀疏**：在强对齐模型上，大多数候选提示都会被拒绝，得到相同的“失败”标签，难以区分哪些失败候选更有潜力。
  - **成本高昂**：反复生成完整响应和调用外部裁判会带来很大的计算开销，成为模糊测试的扩展瓶颈。
- **整体含义**：论文提出 NeuronFuzz，一种白盒模糊测试框架，把 LLM 内部安全神经元的激活转换为连续的安全警报分数，在预填充阶段即可获得反馈，从而替代昂贵且稀疏的响应级反馈，提升越狱发现效率与迁移能力。

## 2. 论文提出的方法论

- **核心思想**：利用 LLM 内部安全相关神经元激活作为连续执行反馈，指导越狱模板的模糊测试，而非依赖最终响应。
- **关键技术细节**：
  - **SafetyOracle 设计**：
    - 通过模板不变的有害/良性提示对，从 MLP 的 gate 和 up 投影模块提取 token 级激活，经过元素级最大池化得到固定维度向量。
    - 使用基于 bootstrap 的稳定性选择，筛选出在多次重采样中方向一致且与有害输入正相关的紧凑安全神经元集合。
    - 用 Elastic Net 逻辑回归将所选神经元激活映射为连续安全警报分数：
      \[
      S_{\text{alarm}}(x)=\sigma(w^\top z_S(x)+b)\in(0,1)
      \]
      分数越低，表示内部对有害意图的识别越弱，越可能发生越狱。
  - **梯度引导变异**：
    - 对安全警报分数关于输入嵌入求梯度，用梯度的 \(L_2\) 范数衡量每个模板 token 位置的安全敏感度。
    - 选择敏感位置后，用掩码语言模型（ModernBERT-base）生成上下文兼容的替换词，保留原始有害负载不变，只修改越狱模板。
  - **模糊测试流程**：
    - 采用 MCTS-Explore 作为种子调度器；
    - 每个候选提示只做预填充，收集所选安全神经元激活，由 SafetyOracle 打分；
    - 将奖励 \(R(x')=-S_{\text{alarm}}(x')\) 反馈到调度器，更新种子选择策略。
- **算法流程概括**：
  1. 构建模板不变训练数据；
  2. 提取 MLP 激活并选择稳定安全神经元；
  3. 训练 Elastic Net 安全预言机；
  4. 在模糊测试循环中，用梯度定位敏感模板位置，用掩码语言模型生成变异；
  5. 预填充打分并更新调度器，最终只对发现的候选模板做响应级验证。

## 7. 优点

- **白盒内部信号替代响应级反馈**：从安全神经元激活获得连续、可微的反馈，避免反复生成响应，尤其适合强对齐模型。
- **模板不变与稳定性选择**：减少模板风格带来的捷径，筛选稳定方向一致的安全神经元，提高了反馈的可靠性和泛化性。
- **梯度引导 + 掩码语言模型变异**：将“在哪里改”和“改成什么”解耦，既保证对安全信号影响最大，又保持模板流畅和上下文兼容。
- **预填充即可评分**：极大降低搜索成本，RGD 恒为 1.0，并在部分模型上获得最低端到端时间。
- **强迁移性**：模板可跨架构、规模、推理模式、数据集和模态迁移，具有较强的实用性和评估价值。
- **兼顾防御使用**：SafetyOracle 可以用于输入侧检测，体现内部信号不仅可用于攻击，也可服务于防御和系统化安全评估。
- **实验系统性好**：多模型、多基线、多指标、消融和防御实验齐全，结论可信度较高。

## 8. 不足与局限

- **依赖白盒访问**：需要访问源模型的参数、MLP 激活和输入梯度，因此只能作为授权评估或本地代理模型攻击框架，不能直接用于黑盒目标模型。
- **部分迁移效果有限**：在 DeepSeek-V4-Pro、Grok-4.5、Gemini-3-Flash 等专有模型上，ASR 和 EASR 明显低于其他模型，反映出模板迁移仍受目标模型安全机制差异影响。
- **多源联合优化可能不稳定**：论文消融显示，加入第三个源模型反而会因梯度和安全目标冲突导致迁移效果下降，说明源模型组合需要仔细选择。
- **防御评估范围有限**：只测试了 perplexity filter 和 SmoothLLM 两种输入防御，尚未覆盖更复杂的系统级防御、上下文过滤器或动态安全策略。
- **潜在伦理与滥用风险**：NeuronFuzz 提升了越狱发现能力，虽然定位为安全评估工具，但也可能被恶意用于发现并利用真实模型漏洞；论文在风险缓解和负责任披露方面着墨有限。
- **实验版本与时效性问题**：论文涉及不少未来日期或较新模型，相关 API 和行为可能发生变化，结果复现与长期稳定性需要谨慎对待。
