## 摘要
大语言模型（LLMs）仍然容易受到越狱攻击，这些攻击利用角色扮演、混淆、代码变换和多步间接引导等技术来诱发有害输出。随着越狱策略不断出现，防御措施在持续的猫鼠游戏中大量涌现，但其中大多数仍是静态的：它们的安全行为在部署时即固定，因此无法积累防御经验或适应未见过的策略。我们提出一种自进化的测试时防御，围绕一个持久的、跨交互的规则记忆构建：当攻击成功时，该框架将这次失败抽象为一条方法级规则，捕捉结构性的攻击包装而非有害主题，并将其复用于未来输入。由于规则是方法级的，一条归纳出的规则可泛化到整个攻击家族，并且标签空间会随着新包装的出现而扩展。该机制完全通过外部记忆和提示运行，无需参数更新，适用于开放权重和黑盒 API 模型。我们将其实现为四个协作模块，但贡献在于基于记忆的自适应机制，而非模块分解。在四个黑盒越狱攻击家族和多个模型上，我们的方法大幅降低了攻击成功率，同时保持了良性效用，在自适应复合包装攻击下仍保持鲁棒，并且不会随着记忆增长而增加过度拒绝。

## Abstract
Large language models (LLMs) remain vulnerable to jailbreak attacks that exploit techniques such as role-playing, obfuscation, code transformation, and multi-step indirection to elicit harmful outputs. As jailbreak strategies keep emerging, defenses have proliferated in an ongoing cat-and-mouse game, yet most remain static: their safety behavior is fixed at deployment, so they cannot accumulate defensive experience or adapt to unseen strategies. We propose a self-evolving test-time defense built around a persistent, cross-interaction rule memory: when an attack succeeds, the framework abstracts that failure into a method-level rule capturing the structural attack wrapper rather than the harmful topic, and reuses it against future inputs. Because rules are method-level, one induced rule generalizes across an entire attack family, and the label space expands as novel wrappers appear. The mechanism operates entirely through external memory and prompting, with no parameter updates, and applies to both open-weight and black-box API models. We realize it as four cooperating modules, but the contribution is the memory-based adaptation mechanism, not the module decomposition. Across four black-box jailbreak families and multiple models, our method substantially reduces attack success rates while preserving benign utility, remains robust under an adaptive composite-wrapper attack, and does not increase over-refusal as the memory grows.

## 2. 论文提出的方法论

### 2.1 核心思想
- 构建一个**持久的、跨交互的规则记忆** \(R_t\)，不修改模型参数 \(\theta\)，仅通过外部记忆和提示进行防御。
- 规则捕获的是**结构性攻击包装**（attack wrapper），而非有害主题，因此一条规则可泛化到同一攻击家族的多个变体。
- 机制适用于**开放权重模型和黑盒 API 模型**，因为它完全基于提示和外部记忆，不依赖模型内部状态。

### 2.2 关键技术与算法流程
- **攻击模式表示**：分类器 \(\phi\) 将输入 \(x^{(t)}\) 映射到一个方法级标签 \(z^{(t)}\)。标签可为 `benign`、已有攻击标签，或 `other`（表示遇到未见过的包装）。
- **规则记忆形式**：每条规则形如  
  `[label=Li] If the request uses Pi, then Di`  
  其中 \(L_i\) 是方法级攻击标签（如 `roleplay-nested-persona`），\(P_i\) 描述攻击包装，\(D_i\) 是拒绝约束。
- **规则检索与触发**：根据 \(z^{(t)}\) 检索最匹配的规则子集 \(R_t(x^{(t)})\)，最多触发 \(K=2\) 条规则。匹配采用三阶段策略：
  1. **标签优先**：选择标签与 \(z^{(t)}\) 相同的规则；
  2. **LLM 相关性回退**：若无匹配，由触发智能体按方法级相似度打分；
  3. **词汇回退**：仍无匹配时，用关键词重叠启发式选择候选。
- **策略决策**：策略算子 \(g\) 将触发规则映射为三种动作之一：
  - `hard-refuse`：高风险输入（如要求解密隐藏意图、生成可执行有害指令）；
  - `soft-refuse`：中等风险；
  - `allow`：默认无规则触发时。
  - 冲突时优先级为 `hard-refuse > soft-refuse > allow`。
- **响应生成**：生成智能体根据策略动态组合系统指令，在硬拒绝模式下注入安全契约，禁止提供操作细节、代码、命令或解密隐藏意图。
- **违规检测**：违规检测器 \(h\) 使用与系统内智能体相同的模型作为 LLM 裁判，以 1–10 分评分，阈值 \(\tau=7\)，判断攻击是否成功。学习信号与外部评估信号（GPT-4o-mini）来自不同模型，避免针对评分器优化。
- **规则归纳与记忆更新**：当检测到违规且 \(z^{(t)} \neq \text{benign}\) 时，反思智能体归纳新规则，记忆更新算子 \(U\) 进行语义去重，并对每个标签施加容量上界 \(C=4\)，防止过度专业化。
- **算法流程**（每步交互）：
  1. 分类输入 \(x^{(t)}\) 得到 \(z^{(t)}\)；
  2. 检索触发规则 \(R_t(x^{(t)})\)；
  3. 决定响应策略 \(\pi(x^{(t)})\)；
  4. 生成响应 \(y^{(t)}\)；
  5. 判断是否违规 \(v^{(t)}\)；
  6. 若违规且非 benign，归纳新规则并更新记忆；否则记忆保持不变。

### 2.3 实现方式
- 由四个提示智能体实现上述算子：A1 规则触发、A2 策略决策、A3 响应生成、A4 反思与规则归纳。
- 作者强调：**贡献在于基于记忆的自适应机制，而非模块分解本身**。

## 3. 实验设计

### 3.1 数据集与场景
- **攻击数据集**：AdvBench 中的 Harmful Behaviors，共 520 条有害行为提示。
- **良性效用数据集**：MMLU（大规模多任务语言理解）和 GSM8K（小学数学应用题）。
- **过度拒绝评估**：XSTest 安全集（附加实验）。

### 3.2 攻击方法与模型
- **四类黑盒越狱攻击**：
  - DeepInception（嵌套角色扮演）
  - CodeChameleon（个性化代码加密）
  - ReNeLLM（嵌套伪装与重构）
  - FlipAttack（翻转攻击）
- **三个模型**：
  - Qwen2.5-7B（开源）
  - Llama3.1-8B（开源）
  - Gemini-3-Flash-Preview（API 黑盒）

### 3.3 基线方法
- **No Defense**：无额外安全机制。
- **Defense Prompt**：静态安全提示。
- **Self-Reminder**：实例级自我反思，生成自然语言反馈并追加到后续提示。
- **AutoDefense**：多智能体意图分析与响应评估过滤。
- 附加实验还对比了 **AegisLLM** 和 **In-context Defense (ICD)**。

### 3.4 评估协议与指标
- **冷启动在线协议**：规则记忆初始为空，每个攻击家族的 prompt 按固定顺序流入，只能使用先前失败归纳的规则，无评估集泄漏。
- **ASR-rej**：基于固定拒绝短语列表的拒绝率，攻击成功率 = 未被拒绝比例。
- **ASR-gpt**：使用外部 GPT-4o-mini 裁判按 1–10 评分，阈值 7，评分 ≥7 视为攻击成功。论文将其作为**主要指标**。
- **良性效用**：MMLU 和 GSM8K 准确率。
- **推理成本**：稳态每个输入约 3 次 LLM 调用，相对单次调用模型开销 3.07× 调用数、1.43× 延迟。

## 6. 论文的主要结论与发现

- **显著降低攻击成功率**：在四个黑盒越狱家族和三个模型上，方法取得最低的 ASR，尤其在 CodeChameleon 和 ReNeLLM 这类静态提示和实例级反思失效的攻击下优势明显。
- **保持良性效用**：MMLU 和 GSM8K 准确率与未防御模型相差约两分以内，鲁棒性提升并未以牺牲良性可用性为代价。
- **自进化有效**：随着交互流推进，规则记忆积累后，ASR-gpt 在第一轮后快速降至接近零，证明方法级规则能够泛化到整个攻击家族；无防御基线则始终脆弱。
- **消融验证各组件必要**：移除触发、强制执行或反思任一组件都会大幅增加 ASR，说明三者互补且共同必要。
- **对自适应复合包装攻击鲁棒**：方法能应对试图逃避规则触发的复合包装攻击。
- **不显著增加过度拒绝**：空记忆时过拒绝率与基础模型相同（3.6%），累积四种攻击规则后仅升至 9.6%，主要因分类器将 XSTest 的同形陷阱误标为攻击。

## 7. 优点

- **机制创新**：将防御从静态、实例级提升到**跨交互的持久记忆自演化**，能以方法级规则泛化到整个攻击家族，并能自动扩展攻击标签空间。
- **适用范围广**：完全基于外部记忆和提示，无需参数更新，适用于开源和黑盒 API 模型，无需白盒访问。
- **选择性触发**：动态触发仅激活最相关规则，避免将所有规则盲目附加导致噪声干扰，从而在安全性与良性效用之间取得平衡。
- **评估设计严谨**：冷启动在线协议、学习与评估信号分离、多攻击家族和多模型家族验证，增强了结果可信度。
- **消融与敏感性分析全面**：验证了触发、强制执行、反思各组件的作用，并表明方法对关键超参数不敏感。
- **效用保持良好**：在显著提升安全性的同时，良性任务准确率损失很小，且未明显放大过度拒绝。

## 8. 不足与局限

- **攻击覆盖有限**：仅评估了四类黑盒提示级越狱家族及一个复合包装攻击，未覆盖全部近期提出的攻击；多轮交互、智能体式攻击等场景仍属未来工作。
- **长期记忆管理不完善**：当前通过语义去重和每标签容量上界来限制记忆增长，但缺乏显式的规则剪枝和冲突解决机制；在极长交互流下，大规则记忆的效率和一致性仍是开放问题。
- **依赖 LLM 组件判断**：违规检测器和分类器均为提示型 LLM 组件，会继承基础模型的判断误差，导致偶尔过度拒绝（XSTest 过拒绝从 3.6% 升至 9.6%）。
- **额外推理开销**：每个输入至少需要 3 次 LLM 调用，虽然与多调用基线 AutoDefense 相当，但仍高于单次调用模型。
- **消融实验场景单一**：消融仅在 CodeChameleon 一个攻击方法上展开，未见所有攻击家族上的组件贡献验证。
- **评估对分类器精度敏感**：方法优势部分依赖攻击模式分类器 \(\phi\) 的准确率，分类器误标可能影响规则触发与记忆更新。
- **超参数范围较窄**：敏感性分析只覆盖了 \(K=1,2\) 和 \(C=2,4\)，未探索更大范围对性能和成本的影响。
