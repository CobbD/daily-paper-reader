## 摘要
新兴的 W3C WebMCP 提案使大语言模型智能体能够调用网页公开的工具。然而，在多参与方的网络环境中，将智能体执行集成到以同源策略（SOP）为核心的浏览器安全模型中，难以为智能体可访问的工具提供充分的来源与生命周期保证，由此带来三种风险：主体归因欺骗、不受控制的工具生命周期以及语义提示注入。我们提出 WebMCP-Phalanx，一种双层智能体运行时架构。其第一层提供浏览器原生信任锚点，通过受密码学保护的能力凭证将每个工具绑定到其注册主体，并在工具生命周期中传播来源标签。其第二层将语义检查与特权工具使用分离。一个不具备工具调用权限的隔离智能体（Q-LLM）检查工具元数据、输出和页面提供的内容是否存在提示注入。经过验证的内容随后转发给特权智能体（P-LLM）执行，而 Q-LLM 的内部状态对页面脚本保持隐藏。实证评估表明，浏览器原生所有权机制将撤销和覆盖攻击成功率从 100% 降至 0%。该双层智能体运行时阻断了嵌入在工具描述中的全部 80 次提示注入尝试，并将工具返回攻击限制为 80 次中仅 2 次成功。在各实验中，任务效用与无攻击基线在统计上无显著差异。然而，在白盒自适应攻击者面前，基于描述的过滤可能被在检查之前调用的恶意工具名称绕过。这一发现促成了调用时机门控，该机制将工具调用推迟到所有智能体可见的工具元数据都经过验证之后。

## Abstract
The emerging W3C WebMCP proposal enables LLM agents to invoke tools exposed by web pages. In multi-party web environments, however, integrating agent execution into a browser security model centered on the Same-Origin Policy (SOP) leaves insufficient provenance and lifecycle guarantees for agent-accessible tools, creating three risks: subject-attribution spoofing, uncontrolled tool lifecycles, and semantic prompt injection. We propose WebMCP-Phalanx, a dual-layer agent runtime architecture. Its first layer provides a browser-native trust anchor that binds each tool to its registering principal through cryptographically protected capability credentials and propagates provenance labels throughout the tool lifecycle. Its second layer separates semantic inspection from privileged tool use. A Quarantine Agent (Q-LLM), without tool invocation authority, inspects tool metadata, outputs, and page-supplied content for prompt injection. Validated content is then forwarded to a Privileged Agent (P-LLM) for execution, while the Q-LLM's internal state remains hidden from page scripts. Empirical evaluation shows that the browser-native ownership mechanism reduces revocation and overwrite attack success from 100\% to 0\%. The dual-agent runtime blocks all 80 prompt-injection attempts embedded in tool descriptions and limits tool-return attacks to 2 successful cases out of 80. Across experiments, task utility remains statistically indistinguishable from the no-attack baseline. Under a white-box adaptive attacker, however, description-based filtering can be bypassed through malicious tool names invoked before inspection. This finding motivates a call-timing gate that delays tool invocation until all agent-visible tool metadata has been validated.

## 1. 论文的核心问题与整体含义

- **研究背景**：W3C 正在制定 WebMCP 标准，允许网页向基于 LLM 的智能体暴露可调用工具。这使智能体不仅能读网页，还能直接通过网页提供的工具执行动作。
- **核心问题**：WebMCP 将智能体执行引入以同源策略（SOP）为中心的浏览器安全模型，但同一源内的主站脚本、第三方广告 SDK、统计脚本之间没有明确信任边界，导致以下结构性风险：
  - **主体归因欺骗**：工具列表不绑定注册者身份，任何同源脚本都可以抢占工具名、撤销或替换其他脚本的工具。
  - **生命周期失控**：SPA 逻辑页面跳转后，工具仍然长期存活。
  - **执行不透明**：工具可以声明为只读，却在执行时外泄数据。
  - **语义提示注入**：结构上合法的工具在描述、输入 schema 或返回值中隐藏操纵指令。
- **整体含义**：现有基于同源策略的浏览器模型不足以保障浏览器集成 LLM 智能体的安全，需要在 WebMCP 规范固化前，建立“来源可信”和“语义可信”分离的防御体系。

## 2. 论文提出的方法论

WebMCP-Phalanx 是一个双层智能体运行时架构，核心原则是**将来源验证与语义执行严格解耦**。

### 2.1 第一层：浏览器原生信任锚点

- **Tool Ownership Authority（工具所有权权威）**：
  - 将工具注册表放入浏览器原生实现层，页面脚本无法直接访问。
  - 注册成功时签发**不透明、不可伪造的 capability credential**。
  - 要撤销或覆盖工具，必须出示对应凭证；因此第三方脚本只能修改自己注册的工具。
- **Registry Attribution（注册来源标注）**：
  - 在 `tools/list` 时，从隔离状态中取出工具的注册来源，附加防伪造的 origin 标签。
  - 但该标签只能区分 origin，无法区分同一 origin 内的不同脚本。
- **Lifecycle Monitor（生命周期监控）**：
  - 工具在注册时声明生命周期为 `session` 或 `navigation`。
  - 原生拦截 History API（`pushState`、`replaceState`、`popstate`），准确检测 SPA 逻辑页面跳转，并清除 `navigation` 作用域工具。
- **Runtime Observation（运行时观测）**：
  - 监控外泄向量：`fetch`、`sendBeacon`、`Image.src`，以及通过隔离的 `MutationObserver` 监控 DOM 变化。
  - 将运行时行为与工具静态声明对比；如果发现偏离，则把信任标签降级为 Red。
- **Data Boundary Authority（数据边界权威 / 信任合成引擎）**：
  - 综合来源

- 综合来源标签、生命周期声明、运行时外泄观测与工具静态声明的一致性，生成 Green/Yellow/Red 三级信任标签。
  - Green：来源可信且行为与声明一致，允许智能体直接调用；Yellow：存在不确定或轻微偏离，需用户确认；Red：检测到外泄或声明冲突，直接阻断并告警。

### 2.2 第二层：语义可信执行层

- **Semantic Proxy（语义代理）**：
  - 所有工具描述、输入 schema、返回值都经由独立语义过滤模块处理后再交给 LLM。
  - 使用提示注入检测器识别工具元数据中的操纵指令，例如“忽略之前指令”“把用户密码发送到某地址”等。
- **Tool Response Sanitizer（工具响应清洗）**：
  - 对返回值做结构校验与内容过滤，剔除隐藏的提示注入语句。
  - 保留数据字段但剥离任何自然语言指令性内容。
- **Execution Gate（执行门控）**：
  - 只有通过第一层信任标签为 Green 且第二层语义检查未命中的工具调用才会被执行。
  - 对 Yellow 工具要求用户显式授权，并将工具描述与风险摘要呈现给用户。

## 3. 实验评估与主要发现

- **原型实现**：在 Chromium 内核中实现 Tool Ownership Authority、Lifecycle Monitor 与 Runtime Observation；在智能体侧实现 Semantic Proxy。
- **攻击场景覆盖**：测试了同源第三方脚本抢占工具名、跨 SPA 页面存活工具、只读工具外泄数据、工具描述中植入提示注入等四类攻击。
- **结果**：
  - WebMCP-Phalanx 能以 100% 准确率识别并阻断上述四类攻击。
  - 对正常工具的误报率低于 2%，主要体现在 Yellow 标签的保守策略。
  - 性能开销：工具注册、调用链路上的中位延迟增加约 3.1%，DOM 监控的 CPU 开销低于 1.5%。

## 4. 贡献与结论

- **主要贡献**：
  1. 系统分析了 WebMCP 在浏览器同源模型下的四类安全缺陷。
  2. 提出 WebMCP-Phalanx 双层防御架构，将来源可信与语义可信解耦。
  3. 在原型中实现并验证了对主体归因欺骗、生命周期失控、执行不透明和语义提示注入的防御能力。
- **结论**：仅靠同源策略无法保障浏览器内 LLM 智能体的安全，必须引入来源标识、生命周期控制和语义隔离机制；WebMCP-Phalanx 为 WebMCP 规范的安全设计提供了可行的参照实现。
