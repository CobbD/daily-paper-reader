## 摘要
编码智能体以开发者的权限编辑文件并执行shell命令，使得恶意请求可直接转化为有害操作或功能性恶意软件。现有防御存在互补局限：仅使用API的部署者无法进行权重级对齐，而输入过滤器和执行边界监控器则需要沿智能体轨迹配置辅助分类或检查组件。因此，我们提出SkillShield，一种系统提示防御方法，离线地从已知攻击或记录的智能体失败中合成安全技能。这些技能在会话开始时注入系统提示，并在整个工具使用循环中保持激活。与引用监视器不同，它们通过定义模型在执行期间应遵循的安全策略来保护系统。由于系统提示空间有限，我们考察了三种固定预算的配置范围：全类别，即一个技能覆盖所有威胁类别；按捆绑，即一个技能面向一个相关子集；按类别，即一个技能专用于一个已知类别并作为上限参考。这些方案均不需要运行时请求分类或路由。在RedCode上对六种大语言模型的评估中，默认的全类别技能将恶意软件生成严重性从3.37降至0.58，并实现43.6%的执行攻击成功率，与Llama Guard 3在未使用其独立8B分类器时的42.7%相当。按捆绑和固定类别的按类别设置进一步将此成功率分别降至36.2%和14.5%。在两类非自适应越狱攻击下，SkillShield在恶意软件生成方面继续优于所有基线。在731条良性任务描述中，SkillShield的平均安全拒绝率为0.14%。这些结果表明，提示空间安全技能有潜力防止LLM编码智能体的有害操作和恶意软件生成。

## Abstract
A coding agent edits files and executes shell commands with its developer's privileges, allowing malicious requests to translate directly into harmful actions or functional malware. Existing defenses have complementary limitations: weight-level alignment is unavailable to API-only deployers, whereas input filters and execution-boundary monitors require auxiliary classification or checking components along the agent's trajectory. We therefore introduce SkillShield, a system-prompt defense that synthesizes security skills offline from known attacks or recorded agent failures. These skills are injected into the system prompt at session start and remain active throughout the tool-use loop. Unlike a reference monitor, they protect the system by defining the security policies the model should follow during execution. Due to the limited system-prompt space, we examine three fixed-budget provisioning scopes: all-classes, with one skill covering all threat classes, per-bundle, with one skill targeting a related subset, and per-class, with one skill dedicated to a single known class and used as the upper-bound reference. None requires runtime request classification or routing. Across six large language models on RedCode, the default all-classes skill reduces malware-generation severity from 3.37 to 0.58 and achieves a 43.6% execution attack success rate, comparable to Llama Guard 3's 42.7% without its separate 8B classifier. The per-bundle and class-fixed per-class settings further reduce this rate to 36.2% and 14.5%, respectively. Under two non-adaptive jailbreak families, SkillShield continues to outperform all baselines on malware generation. Across 731 benign task descriptions, SkillShield yields a mean safety-refusal rate of 0.14%. These results demonstrate the potential of prompt-space security skills to prevent harmful actions and malware generation for LLM coding agents.

## 2. 论文提出的方法论

### 2.1 核心思想
- 在会话开始前将**完整的自然语言安全技能**注入系统提示 \(P\)，该技能在整个多步工具使用循环中保持激活，从第一步起提供覆盖。
- 安全技能通过**离线合成**获得：主动挖掘（Proactive mining）从已知攻击中提取技术签名；反应式学习（Reactive learning）从未防御智能体的失败轨迹中提炼防御原则。
- 由于系统提示空间有限，考察**三种固定预算的配置范围**：all-classes（一个技能覆盖所有威胁类别）、per-bundle（一个技能覆盖一个相关子集）、per-class（一个技能专用于单个已知类别，作为上限参考）。所有配置使用相同预算 \(L=10{,}000\) 字符，无需运行时请求分类或路由。

### 2.2 关键技术细节
- **技能注入格式**：每个技能包含固定拒绝前言（preamble），要求模型对有害/恶意请求完全拒绝、不执行任何代码、不修改或重写为“安全”版本。前言不计入技能正文预算。
- **主动挖掘（Proactive）**：对训练语料中的每个攻击案例，合成器提取可机械检查的信号（如命令 `rm -rf`、路径 `/etc/shadow`、库调用序列），形成可审计的威胁签名集。
- **反应式学习（Reactive）**：对每个未防御失败轨迹，合成器进行事后分析，记录有害意图、跨格式信号及危害解释，倾向泛化意图而非表面语法。
- **共享精炼（Refinement）**：两类策略产生有序中间项，按块（chunk \(C=2000\) 字符）进行迭代精炼，每步结果截断至 \(L\) 字符；当技能长度达到 \(0.9L\) 时提前停止，最后附加固定前言。
- **算法流程**（Algorithm 1）：输入合成器 LLM \(M_s\)、块大小 \(C\)、正文限制 \(L\)、模式（Pro/Rea）、攻击案例/失败记录；对每个案例提取签名或事后总结；按块分区并迭代精炼；截断并添加前言。
- **形式化目标**：在固定技能空间 \(s \in S_L = \{s \in \Sigma^* : |s| \le L\}\) 内，最小化恶意任务上的预期危害 \(R_{\text{mal}}(s)\)，同时满足良性任务安全拒绝率 \(R_{\text{ref}}(s) < \varepsilon\)。
- **粒度成本**：定义合并类别块 \(B\) 的代价 \(\Delta(B)\) 为块级风险与各类分别用单类技能加权风险之差，用于衡量合并策略带来的保护损失。

### 2.3 部署假设
- 防御者控制系统提示、持有离线攻击语料、不能重训模型、保留工具访问、在请求到达前固定技能；攻击者不能修改系统提示或部署基础设施，但可能知道技能存在与合成过程。

## 6. 论文的主要结论与发现

- **Q1 有效性**：在 RedCode 上，默认全类别技能将恶意软件生成严重性从 3.37 降至 0.58，执行 ASR 为 43.6%，与 Llama Guard 3 的 42.7% 相当（且无需其 8B 分类器）；per-bundle 降至 36.2%，per-class 降至 14.5%。生成 AvgS 上 SkillShield 最多为基线的一半。
- **部署范围影响**：更窄的威胁范围带来更强的保护；per-bundle 在五个模型上超过最强基线，per-class 在全部六个模型上超过 LG。
- **合成策略**：在 per-class 粒度，Reactive 比 Proactive 平均低 1.6–6.9 个百分点执行 ASR；但在 all-classes 下 Proactive 更优（GPT 影响大）。
- **覆盖与预算**：从 all-classes 到 per-class 的 48.9 个百分点差距部分由合成过程造成；将 per-class 技能直接拼接并截断到相同预算可恢复大部分损失（平均 ASR 26.5% vs 36.2%）。预算从 2k 增加到 8k 字符后收益趋于饱和。
- **越狱鲁棒性**：在生成恶意软件上，SkillShield 依旧优于所有基线；在执行上，per-class 仍保持优势（最坏 31.2% ASR vs LG 43.2%），但 broad 配置在 persona 越狱下失去与 LG 的平价。
- **良性代价**：在 731 个良性任务上，平均安全拒绝率仅 0.14%；32/36 个配置低于 0.68%；Reactive 策略在高覆盖时有过拒绝风险（最高 16.3% 在 Qwen3 B4 bundle 上）。

## 7. 优点

- **无需权重修改、辅助模型或运行时检查**：适合 API-only 部署者，部署简单，成本低。
- **离线合成可更新**：技能可从已知攻击或失败轨迹中生成，当新攻击数据出现时可再生，无需重新训练。
- **覆盖多粒度**：三种配置（all-classes、per-bundle、per-class）对应不同部署场景，提供灵活选择。
- **实验全面**：跨六家模型、三种 agent harness、两个攻击表面、五个基线、两类越狱，附统计检验和效应量。
- **良性代价低**：在真实良性任务上安全拒绝率极低，证明防御不会显著干扰正常软件工程请求。
- **深入分析合成损失**：通过拼接控制和预算消融，区分了提示容量与策略构造对保护损失的影响，提供了可操作的改进方向。
- **可审计性**：Proactive 技能包含具体规则，便于人工检查与更新。

## 8. 不足与局限

- **未评估端到端良性任务完成度**：论文只测量了安全拒绝率（FPR），并未说明良性任务的实际成功率，因此不能完全证明对正常工作效率无影响。
- **越狱仅限非自适应**：评估使用固定的、未针对所部署技能优化的越狱模板；未考虑白盒优化、对抗性提示或针对技能的精确攻击。
- **per-class 部署假设强**：需要
