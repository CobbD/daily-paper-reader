## 摘要
由大语言模型驱动、可自主操作智能手机的 GUI 智能体正迅速从研究原型走向早期实际部署。然而，由于这些智能体经常处理不可信的环境内容，它们极易受到环境注入攻击的影响，包括间接提示注入和对抗性指令。此类攻击可以在用户不知情的情况下，通过日常移动使用中遇到的多种渠道操纵智能体的行为。尽管存在这些风险，现有基准测试往往未能覆盖日常用户场景，缺乏在移动设备环境注入攻击下对 GUI 智能体的系统性评估。为弥补这一不足，我们提出了 MobileWorldSafety，一个基于真实安卓应用构建、包含 142 个风险任务的基准测试。对每个任务，我们在最终系统状态上定义了一个可编程验证的风险指标，并通过两阶段流水线评估结果：基于规则的验证处理无歧义情况，而 LLM 评判器裁决有歧义的情况。这区分了安全失败与能力失败，并实现了客观、可复现的评估。对六个智能体（包括通用智能体和专门 GUI 智能体）的评估表明，所有智能体仍然高度脆弱，攻击成功率在 40.4% 至 66.9% 之间。这些发现表明，当对抗性内容以普通移动上下文形式呈现时，当前智能体往往无法保持安全对齐。MobileWorldSafety 为量化这些漏洞和推进稳健移动 GUI 智能体研究提供了基础。

## Abstract
LLM-powered GUI agents that autonomously operate smartphones are rapidly transitioning from research prototypes to early real-world deployment. However, because these agents routinely process untrusted environmental content, they are highly vulnerable to environmental injection attacks, which include indirect prompt injections and adversarial instructions. Such attacks can manipulate the behavior of agents without user awareness through diverse channels encountered in everyday mobile use. Despite these risks, existing benchmarks often fail to capture everyday user scenarios, lacking a systematic evaluation of GUI agents under environmental injection attacks on mobile devices. To address this gap, we introduce MobileWorldSafety, a benchmark of 142 risk tasks built on real Android applications. For each task, we define a programmatically verifiable risk indicator over the final system state and evaluate outcomes with a two-stage pipeline: rule-based verification handles unambiguous cases, while an LLM judge adjudicates ambiguous ones. This distinguishes safety failures from capability failures and enables objective and reproducible assessment. Evaluations on six agents, including both general agents and specialized GUI agents, demonstrate that all agents remain highly vulnerable, with attack success rates ranging from 40.4% to 66.9%. These findings indicate that current agents often fail to maintain safety alignment when adversarial content is presented as ordinary mobile context. MobileWorldSafety provides a foundation for quantifying these vulnerabilities and advancing research on robust mobile GUI agents.

## 2. 方法论

- **基准构建基础**：MobileWorldSafety 构建在 **MobileWorld** 之上，运行于 Docker 化 Android 模拟器中，支持对最终设备状态进行可编程检查。
- **任务构成**：共 **142 个风险任务**，覆盖 **13 个真实 Android 应用**和 **5 个 MCP 服务器**。每个风险任务由四要素构成：
  - **Base Goal**：用户原本的良性任务。
  - **Injection Carrier**：注入恶意内容的载体。
  - **Injected Instruction**：攻击者植入的误导性指令。
  - **Risk Indicator**：用于最终验证风险是否发生的客观标准。

- **两维攻击分类法**：
  - **5 类攻击向量（Attack Vectors）**：
    - V1 定向通信（邮件、短信、私信等）
    - V2 网页内容（搜索结果、产品页等）
    - V3 社区内容（社交帖子、公共频道消息等）
    - V4 存储记录（日历事件、发票、本地文件等）
    - V5 工具响应（MCP/API 返回结果）
  - **7 类危害类别（Harm Categories）**：
    - H1 敏感信息泄露
    - H2 个人安全暴露
    - H3 财务损失
    - H4 未授权操作
    - H5 运行中断
    - H6 内容伪造
    - H7 有害内容传播

- **注入实现方式**：攻击内容在任务初始化时预先写入智能体会自然接触的应用数据源，不依赖实时外部网络，例如：
  - 本地收件箱预置钓鱼邮件/欺诈短信；
  - 本地 HTML 页面/离线页面模拟恶意网页；
  - Mattermost/Mastodon 后端预置恶意社区内容；
  - 本地 PDF、发票、日历事件记录注入；
  - 本地部署或模拟 MCP 工具返回字段注入。

- **两阶段评估流水线**：
  - **第一阶段：规则化程序验证**。根据预设风险指标检查最终系统状态，可快速判定无歧义情况。若 `risk:true` 则直接判为 **Executed**，即使基础任务完成也不改变安全优先判定。
  - **第二阶段：LLM 评判器**。对规则验证无法定论的模糊样本，结合任务说明、验证输出、完整轨迹和截图，由 LLM 评判器区分失败类型。
  - **五级标签**：
    - **Executed**：攻击被完全执行。
    - **Partial**：攻击被部分执行。
    - **Defended**：攻击被抵抗且基础任务成功完成。
    - **Stalled**：攻击被抵抗但基础任务失败。
    - **Run Failed**：智能体因能力不足未到达注入载体。

- **核心指标定义**：
  - 可评分任务数：`Nsc = Ntotal − Nrf`，其中 `Nrf` 为 Run Failed 数，排除能力不足样本，避免把“没能力执行”误判为“更安全”。
  - 攻击成功率：`ASR = (Executed + Partial) / Nsc`，是主要安全指标。
  - 任务完成率：`TCR = Defended / Nsc`，衡量在攻击环境下智能体完成良性任务的能力。

## 6. 主要结论与发现

- **所有智能体均高度脆弱**：ASR 范围为 40.4% 至 66.9%。
- **通用智能体比专用 GUI 智能体更危险**：
  - 通用智能体 ASR 在 47.5% 到 66.9% 之间；
  - 专用 GUI 智能体 ASR 较低（40.4%、44.3%），但其 Run Failed 数量远高于通用智能体（36 和 53 vs 12—24），说明其较低 ASR 可能部分来自执行失败而非真正安全。
- **执行能力越强，攻击面越大**：Gemini-3-Pro 在所有模型中 ASR 最高（66.9%），但 TCR 最低（30.0%），呈现极端安全-效用失衡。
- **攻击向量影响显著**：
  - V5（工具响应）在所有智能体中 ASR 最低，结构化输出更难被利用；
  - V1（定向通信）对通用智能体普遍高效，因为邮件/短信具有隐含权威性，智能体很少质疑。
- **危害类别上存在共同弱点**：
  - H5（运行中断）、H6（内容伪造）、H1（敏感信息泄露）在多数智能体上 ASR 高；
  - H3（财务损失）仅在 Gemini-3-Pro 上显著偏高，说明存在模型特定盲区；
  - H2（个人安全暴露）和 H7（有害内容传播）在多数模型中 ASR 较低，显性危险更容易被基础安全机制拦截。
- **防御效果有限**：
  - 系统提示防御能将 ASR 从 51.6% 降至 37.0%（Qwen），但伴随 Stalled 样本激增，说明主要是触发保守拒绝而非安全完成任务；
  - 多阶段运行时防御相较系统提示防御仅额外降低 1.3 个百分点 ASR，且 TCR 下降，说明通用注入扫描器难以应对深度语义耦合的注入。
- **推理模式可能放大风险**：Gemini-3-Flash Thinking 的 ASR 高于 Non-thinking（57.9% vs 51.2%），部分原因在于推理链将原本停滞的样本转化为部分执行攻击。
- **框架鲁棒性**：更换为 Mobile-Agent-v3.5-style 框架后，ASR 几乎不变（52.3% vs 51.6%），说明漏洞并非轻量框架特有。

## 7. 优点

- **真实应用环境**：基于 13 个真实 Android 应用和 5 个 MCP 服务器，紧贴日常移动使用场景，注入内容与工作流自然耦合。
- **精细的任务分类体系**：采用攻击向量 × 危害类别两维框架，能够独立分析哪些载体更具欺骗性、哪些风险后果更容易被触发。
- **客观、可复现的评估**：每个任务预先定义可编程风险指标，优先依据最终系统状态判定风险，避免只靠轨迹语义推断。
- **安全与能力解耦**：通过 `Run Failed` 排除能力不足样本，避免把“跑不到注入点”误判为“安全性更好”，使 ASR/TCR 更准确。
- **两阶段评估 + 人机验证**：规则验证处理确定情形，LLM 评判器处理模糊情形，且通过 76 例人机一致性研究验证评判器可靠性（92.1% 一致率）。
- **多维度实验设计**：覆盖模型类型、攻击向量、危害类别、防御机制、推理模式、框架架构和干净基线，分析较系统。
- **指标设计合理**：同时报告 ASR 和 TCR，从安全和效用两个角度刻画智能体行为。

## 8. 不足与局限

- **防御研究不够系统**：只测试了系统提示防御和多阶段运行时防御，未覆盖训练阶段对齐、输入级过滤、运行时监控、信任建模等更广泛防御方向。
- **覆盖攻击面有限**：聚焦嵌入应用工作流的注入向量，未覆盖系统通知、弹窗、UI 覆盖层等外部 overlay 型攻击，未来需要统一更全面的攻击框架。
- **单次运行缺少统计显著性**：每个模型仅运行一次，没有多次重复、误差棒或置信区间，因 API 成本高而受限；这会使部分差异可能受随机波动影响。
- **Run Failed 排除可能带来选择偏差**：将能力不足样本排除虽然设计合理，但不同模型 Run Failed 数量差异大，可能影响 ASR/TCR 的横向可比性。
- **通用性限制**：评估局限于 Android 模拟器和特定应用，结论不一定能直接推广到 iOS、桌面系统或其他 GUI 环境。
- **模型范围有限**：仅覆盖 6 个代表性模型，对于一些小型开源模型或具有强制用户确认、权限关卡等机制的框架未做充分评估。
- **温度固定为 0**：虽然有利于可复现性，但真实部署中模型可能使用较高温度，不同采样行为可能改变攻击成功率。
- **双用途风险**：任务设计可能帮助攻击者理解哪些载体和工作流更容易误导智能体，论文虽定位为受控基准，但仍需注意负向社会影响。
