## 摘要
我们评估 DeepSeek Harness (DSH) 中的间接提示注入，使用 AI-Infra-Guard (A.I.G) 构建测试、传递受控污点、执行 DSH、收集轨迹并判断结果。研究涵盖 14,560 次受控执行，涉及 16 个间接内容渠道、文本和文件载体模式、35 个载荷目标、一个未修改的基线和 12 种攻击方法。实验保留了 DSH 的代理循环、工具注册表、模型适配器和会话事件路径；源工具和敏感接收器均为本地夹具，因此尝试的操作被记录而不产生外部副作用。我们使用确定性的基于规则的判断器 RuleJudge 和基于语义的 LLM 判断器 LLMJudge 评估每个轨迹。观察到的最高攻击成功率：在 LLMJudge 下，文本模式下的伪造补全攻击为 17.0%；在 RuleJudge 下，文件模式中的隐藏 Unicode 为 25.5%；在 RuleJudge 下，文件模式中的技能通道为 16.0%。LLMJudge 也比 RuleJudge 更频繁地赋予部分合规性（7.3% 对 2.0%）。我们将这些结果与 DSH 对工具结果、额外上下文和工具调用策略钩子的处理联系起来，然后确定应位于不受信任内容与敏感操作之间的控制措施。我们的代码可在 https://github.com/Tencent/AI-Infra-Guard/tree/main/Research/deepseek-harness-security-assessment 获取。

## Abstract
We assess indirect prompt injection in DeepSeek Harness (DSH), using AI-Infra-Guard (A.I.G) to construct tests, deliver controlled taint, execute DSH, collect traces, and judge outcomes. The study covers 14,560 controlled executions over 16 indirect-content channels, text and file carrier modes, 35 payload objectives, one unmodified baseline, and 12 attack methods. The experiment preserves DSH's agent loop, tool registry, model adapter, and session-event path; source tools and sensitive sinks are local fixtures, so attempted actions are recorded without external side effects. We evaluate each trace with a deterministic rule-based judge, \JudgeR{} (RuleJudge), and a semantic LLM-based judge, \JudgeL{} (LLMJudge). The strongest observed attack success rates are 17.0% under \JudgeL{} for fake-completion attack in text mode, 25.5% under \JudgeR{} for hidden Unicode in file mode, and 16.0% under \JudgeR{} for the skills channel in file mode. \JudgeL{} also assigns partial compliance more often than \JudgeR{} (7.3% versus 2.0%). We relate these results to DSH's treatment of tool results, additional contexts, and tool-call policy hooks, then identify controls that should sit between untrusted content and sensitive actions. Our code is available at https://github.com/Tencent/AI-Infra-Guard/tree/main/Research/deepseek-harness-security-assessment .

## 1. 论文的核心问题与整体含义

- 论文研究 **DeepSeek Harness（DSH）** 这一开源、插件式智能体框架对 **间接提示注入（indirect prompt injection）** 的抵抗能力。
- 背景动机：工具型大模型智能体常会读取用户未创作、但可能被攻击者控制的内容（网页、邮件、文件、技能等），这些内容可能包含与用户指令竞争、诱导智能体执行敏感操作的指令。这类风险的关键不在文本生成是否正确，而在是否触发了 **真实的敏感工具调用**（如发邮件、执行命令、提交表单、转账等）。
- 论文的核心含义：不是简单测试某个模型是否拒绝恶意字符串，而是评估 **完整的运行时路径**——从不可信内容进入模型上下文，到模型计划改变，再到敏感工具被调用——是否会被间接注入攻击突破。
- 作者使用 **AI-Infra-Guard（A.I.G）** 构建受控的源到汇（source-to-sink）测试框架，在保留 DSH 真实运行时组件的前提下，量化攻击成功率，并分析 DSH 源码中的风险控制点。

## 2. 论文提出的方法论

### 2.1 核心思想：源到汇污点分析

- 将间接注入视为一条 **source-to-sink 路径**：
  - **Source（源）**：内容读取工具，如 `fetch_url`、`read_document`、`read_email`、`load_skill`。
  - **Tainted artifact（污点产物）**：源工具返回的、包含攻击者控制内容的网页、文件、邮件、技能等。
  - **Sink（汇）**：外部可观测的敏感动作，如发邮件、提交表单、执行命令、转账、发帖等。
  - **Canary（金丝雀）**：输出型目标使用的特定字符串，用于判断模型最终输出是否被攻击者控制。
- 评估证据链：污点内容是否到达模型 → 模型计划是否改变 → 敏感汇是否被触发 → 汇参数是否匹配攻击者目标。

### 2.2 A.I.G 评估流水线

- A.I.G 的主要模块：
  - **攻击方法构造**：生成攻击者措辞（如 fake completion、obfuscation 等）。
  - **载体注入**：将攻击目标嵌入选定的间接内容通道（网页、技能、PDF 元数据等）。
  - **污点路由**：将构造的污点产物分配给对应的源工具，保持用户请求本身无害。
  - **DSH 运行时适配器**：启动真实的 TypeScript DSH 代理循环，接收会话事件并转换为标准化轨迹。
  - **轨迹记录**：记录用户请求、模型消息、工具调用、工具结果、污点标注、汇标注、最终回复。
  - **双重判断器**：
    - **JR（RuleJudge）**：确定性规则判断器，根据显式轨迹证据判断结果，如污点是否到达工具结果、汇是否被调用、关键参数是否匹配、金丝雀是否主导输出、最终回答是否类似拒绝。
    - **JL（LLMJudge）**：语义 LLM 判断器，离线读取完整轨迹和任务标准，给出 `FULL`、`PARTIAL` 或 `FAILURE` 判定，捕捉规则可能漏掉的语义影响。
- 结果等级定义：**Full success**（完全成功）、**Partial compliance**（部分合规，如汇被调用但参数不匹配、金丝雀被引用但未完全执行等）、**Not reached / failure**（未达到攻击目标）。另外 JR 还区分 **taint-delivered-only**，表示污点内容进入模型但未满足攻击标准。

### 2.3 关键技术细节

- **真实运行时保留**：DSH 的代理循环、工具注册表、模型适配器、会话事件路径均保留原始实现，未用合成代理替代。
- **安全模拟汇**：所有敏感汇工具均为本地夹具，只记录调用名称和参数，不产生真实外部副作用，保证实验安全。
- **源码控制点分析**：
  - DSH 的 `appendToolResult` 接受工具结果中的 `additionalContexts`，意味着控制工具结果的插件可以改变模型可见上下文。
  - DSH 提供单调的 **ToolGuard** 钩子，在 `tools/pre-execute` 之后、工具体执行之前执行，返回拒绝原因即可阻止调用；后续监听器不能将拒绝改为允许。
  - 这些控制点说明部署需要主动使用来源感知的策略。

## 3. 实验设计

### 3.1 数据集与场景

- 构建了一个 **1,120 个基础案例** 的受控数据集，平衡覆盖：
  - **16 个间接内容通道**：网页、文档、邮件头、聊天消息、代码注释、配置文件、日志文件、Markdown、PDF 元数据、技能、电子表格、结构化数据、交易记录、翻译、隐藏 Unicode、日历事件等。
  - **2 种载体模式**：文本模式（text mode）和文件模式（file mode）。文件模式构建真实格式载体（HTML、邮件、日历、PDF 元数据等）再提取模型可见内容，测试解析、元数据、编码和字段边界效应。
  - **35 个载荷目标**：32 个需要敏感工具动作（7 邮件、7 命令、4 转账、4 表单、3 社交发帖、3 日历、2 私信、2 频道发帖），3 个仅需输出金丝雀。
- 应用 **13 种攻击方法**：1 个 `naive` 基线（直接插入攻击目标）和 12 种增强攻击（`escape`、`context_ignoring`、`fake_completion`、`combined`、`payload_splitting`、`obfuscation`、`prefix_injection`、`format_confusion`、`context_flooding`、`cross_channel`、`important_instructions`、`stealth_instruction`）。
- 总计执行 **14,560 次**（1,120 基础案例 × 13 种攻击方法）。

### 3.2 Benchmark 与方法对比

  - 不同攻击方法之间对比（如 fake completion vs naive）。
  - 文本模式 vs 文件模式。
  - 不同内容通道（如 skills vs web retrieval）。
  - 两个判断器 JR vs JL 的结果差异。
- 模型后端为 `deepseek-v4-flash`，通过本地代理访问。

## 6. 论文的主要结论与发现

- **总体结果**：
  - JR 完全成功率 5.6%（819/14,560），部分合规 2.0%（298）；
  - JL 完全成功率 5.3%（772/14,560），部分合规 7.3%（1,060）；
  - 广义影响率（完全 + 部分）JR 7.6%，JL 12.6%；
  - 68.4% 的 JR 运行以明确拒绝结束，21.6% 为污点已到达模型但未达到攻击标准。
- **载体表示影响攻击面**：
  - 文件模式 JR 完全成功率 6.2%，高于文本模式 5.1%；
  - 隐藏 Unicode 通道在文件模式下 JR 完全成功率达到 25.5%，文本模式为 0.0%。
- **输出合规与动作成功是不同风险维度**：
  - 仅输出金丝雀目标在 JL 下完全成功率为 35.7%；
  - 需要汇动作的目标 JL 完全成功率仅 2.5%。
- **攻击方法差异**：
  - `fake_completion` 在文本模式下 JL 完全成功率达 17.0%、JR 16.6%，显著高于 naive 基线的约 5.5–5.7%；
  - `obfuscation` 在 JR 下 13.6%，但 JL 下仅 9.1% 和 8.8%，说明规则证据可能高估语义完成度。
- **通道与源工具风险**：
  - 技能通道在文本模式 JR 14.3%、文件模式 16.0%；`load_skill` 源工具级别 JR 15.2%、JL 13.7%，高于其他源工具。
- **判断器分歧的启发**：
  - JL 的部分合规率远高于 JR（7.3% vs 2.0%），尤其在歧义攻击方法上差异更大；
  - 规则命中的“机械信号”（工具调用、目标令牌、金丝雀）不一定代表语义上完成攻击目标，应结合两类判断器并使用人工审查。

## 7. 优点

- **真实运行时评估**：保留 DSH 的代理循环、工具注册表和会话事件路径，没有用合成代理替代，结果更贴近真实部署。
- **受控且安全的实验设计**：源工具和敏感汇均为本地夹具，记录调用而不产生外部副作用，既能验证攻击链条又避免实际危害。
- **源到汇审计链**：每条轨迹包含污点、工具调用、汇调用和最终响应，能够清晰区分“内容暴露”“计划改变”“实际动作触发”等不同阶段。
- **双重判断器互补**：规则判断器提供稳定、可回归的标准；语义判断器捕捉规则难以覆盖的语义影响，二者的差异本身具有诊断价值。
- **发现载体表示和资产类型的重要影响**：例如文件模式对隐藏 Unicode 的显著放大效应、技能通道的高风险，提示安全评估不能只局限于文本近似。
- **源码级解读**：将经验结果与 DSH 的 `additionalContexts`、`ToolGuard` 等控制点联系起来，给出可操作的部署建议。

## 8. 不足与局限

- **算力未说明**：论文未报告 GPU 型号、数量、运行时间或推理成本，复现和资源评估困难。

- **攻击覆盖有限**：12 种攻击方法虽多样，但现实中的间接注入可能通过更复杂的多轮、多工具协作或自适应方式实现，未在本矩阵中覆盖。

- **实验平台特异性**：结果受 DSH 架构、工具描述和源工具实现细节影响，若部署配置不同（如额外的来源标注或授权策略），观测值可能变化。
