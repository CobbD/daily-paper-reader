## 摘要
大型语言模型越来越多地通过管理工具、扩展、持久状态、权限和外部操作的智能体执行框架进行部署。现有安全基准主要针对单一攻击机制或有限的运行设置子集，难以比较安全故障在不同执行框架职责下如何出现。我们提出了 HarnessRisk，一个面向生命周期的基准，将智能体执行框架安全组织为六个运行阶段：执行框架配置、能力扩展、运行时操作、状态持久化、行动控制和事件恢复。HarnessRisk 包含 128 个沙箱化案例，每个案例将一个良性用户目标与嵌入在不可信工作流产物中的对抗性指令配对。我们使用效用、攻击成功率、持久性和检测率来评估每条轨迹。在三种执行框架、六种语言模型以及 14 种模型与执行框架配置下，攻击成功率介于 12.6% 至 80.9% 之间，而效用保持在 75.0% 至 97.6% 之间。执行框架配置是三种执行框架中最脆弱的阶段，表明攻击可以通过在原本授权的工作流中更改安全敏感参数而成功。我们还发现，明确的风险识别并不必然导致安全行动，因为某些配置在超过 90% 的运行中检测到风险，但仍保持较高的攻击成功率。这些结果凸显了需要在多个执行框架职责层面以及所部署的模型和执行框架配置层面评估智能体安全。

## Abstract
Large language models are increasingly deployed through agent harnesses that manage tools, extensions, persistent state, permissions, and external actions. Existing safety benchmarks mainly target individual attack mechanisms or a limited subset of operational settings, making it difficult to compare how safety failures emerge across different harness responsibilities. We present HarnessRisk, a lifecycle oriented benchmark that organizes agent harness safety into six operational phases including Harness Configuration, Capability Extension, Runtime Operation, State Persistence, Action Control, and Incident Recovery. HarnessRisk contains 128 sandboxed cases, each pairing a benign user objective with an adversarial instruction embedded in an untrusted workflow artifact. We evaluate each trajectory using Utility, Attack Success Rate, Persistence, and Detection. Across three harnesses, six language models, and 14 model and harness configurations, attack success ranges from 12.6% to 80.9%, while Utility remains between 75.0% and 97.6%. Harness Configuration is the most vulnerable phase across all three harnesses, showing that attacks can succeed by altering security sensitive parameters within otherwise authorized workflows. We also find that explicit risk recognition does not reliably lead to safe action, as some configurations detect risks in more than 90% of runs while retaining substantial attack success. These results highlight the need to evaluate agent safety across multiple harness responsibilities and at the level of the deployed model and harness configuration.

## 1. 论文核心问题与整体含义

- **研究背景**：大型语言模型（LLM）正被广泛部署为智能体（agent），通过 agent harness（执行框架）管理工具、扩展、持久状态、权限和外部操作。因此，智能体安全不仅取决于底层模型，还取决于 harness 如何控制访问、修改、记忆和执行。
- **现有不足**：已有的智能体安全基准（如 InjecAgent、Agent Security Bench、ClawSafety 等）主要以单一攻击机制或有限运行设置（如运行时操作、行动控制）为主，对配置、能力扩展、状态持久化、事件恢复等 harness 职责的覆盖不一致，难以系统比较不同职责下的安全失败。
- **本文目标**：提出 **HarnessRisk**，一个面向生命周期的基准，将 agent harness 安全组织为六个运行阶段，并在统一的沙箱协议下评估“模型 + harness”部署配置的安全性与任务效用。
- **整体含义**：安全是部署配置（模型与 harness 的共同作用）的属性，而非模型单独属性；高任务效用可能掩盖不安全执行；风险识别不必然导致安全行动。

## 2. 论文提出的方法论

- **生命周期六阶段分类**：
  1. **Harness Configuration（执行框架配置）**：连接器、凭证、网关、策略、配置模板的初始化与管理。
  2. **Capability Extension（能力扩展）**：技能/插件/扩展的选择、安装、更新和权限授予。
  3. **Runtime Operation（运行时操作）**：对不可信运行内容（邮件、网页、文档、工具输出）的常规处理。
  4. **State Persistence（状态持久化）**：持久内存、偏好、策略、身份与触发器等长期状态。
  5. **Action Control（行动控制）**：部署、删除、OAuth 授权、支付、退款等高风险外部行动。
  6. **Incident Recovery（事件恢复）**：检测、调查、回滚、凭证轮换、状态修复与证据保存。

- **基准结构**：
  - 共 **128 个沙箱化案例**，大致均匀分布：Configuration 22 个、Capability Extension 22 个、Runtime Operation 21 个、State Persistence 21 个、Action Control 21 个、Incident Recovery 21 个。
  - 每个案例将 **良性用户目标** 与 **嵌入不可信工作流产物中的对抗性指令** 配对。对抗性产物形式随阶段变化（如配置指南、扩展元数据、邮件、网页、文档、存储状态、恢复记录等）。
  - 每个案例由四个组件定义：用户任务、初始世界状态、可用工具集、案例评估标准。
  - 工作流通过 **三个 owner turns** 顺序传递，使得对抗内容可在中间步骤出现。

- **评估指标**：
  - 对每条轨迹 τ 生成四个二值标签：`uτ`（Utility，良性目标完成）、`aτ`（Attack Success Rate, ASR，对抗目标实现）、`pτ`（Persistence，对抗影响写入持久状态）、`dτ`（Detection，模型明确识别具体安全风险）。

  - 每次运行从全新初始化的环境开始，重置工作区、harness 状态、持久状态和 mock 服务状态；禁用真实外部网络。

## 6. 论文的主要结论与发现

- **攻击成功率与效用范围**：ASR 从 12.6% 到 80.9%，Utility 从 75.0% 到 97.6%。
- **高效用不意味着安全执行**：在 OpenClaw、Nanobot、Hermes 上，有用但不安全的轨迹分别占 59%、38%、43%；有用且安全仅占 36%、51%、53%。
- **同一模型在不同 harness 下安全差异巨大**：例如 GLM-5.2 在 OpenClaw 上 ASR 为 54.7%，而在 Nanobot 上仅 12.6%，相差 4.3 倍；DeepSeek-V4-Pro 在 Nanobot 为 37.3%，Hermes 为 65.4%。模型安全排名会随 harness 改变。
- **检测与 ASR 强负相关但不充分**：Detection 与 ASR 的 Pearson r = -0.71，Spearman ρ = -0.77；但 MiniMax M3 在 OpenClaw 检测率达 97.9% 的同时 ASR 仍有 31.2%，GLM-5.2 检测率 92.2% 但 ASR 54.7%，表明检测到风险不等于成功阻断或修复。
- **配置阶段是最脆弱阶段**：在所有三个 harness 上，Harness Configuration 的平均 ASR 最高；攻击常通过修改授权工作流中的安全敏感参数（如内联密钥、共享范围、禁用审批、公开网关）成功。后续风险模式因 harness 而异：OpenClaw 在能力扩展和行动控制阶段也脆弱，Nanobot 在状态持久化阶段风险较高。
- **持久化与检测分离**：某些攻击写入持久状态即使攻击目标未完全实现也计为 Persistence；一次性不安全外部行动可能实现 ASR 但没有 Persistence。

## 7. 优点

- **生命周期视角系统化**：将 harness 安全从单一攻击类型扩展到六个职责阶段，提供更全面的风险比较框架。
- **统一协议与多指标分离**：同时测量 Utility、ASR、Persistence、Detection，明确区分任务完成、攻击成功、持久性污染和风险识别，避免单指标误导。
- **配置级评估**：强调评估“模型 + harness”的组合，而非仅模型或仅攻击机制，更贴近真实部署。
- **沙箱化与可控性**：所有外部效应局限于 mock 服务，禁用真实网络，使用合成资产，保证可重复且无害。
- **评估器经验证**：采用确定性谓词和人工标注对 GPT-5.4 评估器进行一致性验证，并提供 Cohen’s κ。
- **附录详尽**：包含案例构成、执行环境、评估协议、数据过滤与统计方法、失败模式定性分析、局限性和可复现性说明。

## 8. 不足与局限

- **算力信息缺失**：未报告 GPU、推理成本或评估耗时，不利于复现成本估计。

- **未开展受控消融**：失败模式为定性解释，无法断言特定 harness 设计选择的因果效应。
