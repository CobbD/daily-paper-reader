## 摘要
提示注入是大语言模型（LLM）应用中的关键安全威胁，攻击者通过在用户或外部数据中嵌入恶意指令来劫持模型行为。现有的检测方法仅检测注入的存在并在检测到时拒绝响应，却忽略了一个事实：对于许多现代对齐模型而言，精心设计的指令可以抵御大多数注入攻击。这意味着注入的鲁棒性在不同指令和模型之间差异显著。这导致了广泛存在的不必要的过度拒绝：模型本可以正确处理包含注入的输入却被错误拒绝。为解决这一过度拒绝问题，我们提出BASIS（鲁棒性感知的提示注入防御）。该防御方法使用注意力竞争比（$ρ$）作为特征来训练两个稀疏线性探针：存在探针和破坏探针。两个探针通过级联门控做出防御决策，无需额外的LLM推理。BASIS包括三个阶段：注入存在性检测、逐样本破坏预测和指令鲁棒性评估；在线级联仅在模型实际会受到危害时才拒绝，从而避免了对鲁棒指令的过度拒绝。在四个任务和六个开源LLM上的实验表明，BASIS在保持近乎完美的注入检测的同时，大幅减少了对安全攻击样本的过度拒绝，尤其是在鲁棒指令模板下。

## Abstract
Prompt injection is a critical security threat in large language model (LLM) applications, where attackers hijack model behavior by embedding malicious instructions in user or external data. Existing detection methods only detect the presence of injection and refuse to respond upon detection, overlooking the fact that for many modern aligned models, well-crafted instructions can resist most injection attacks. This means that the injection robustness varies significantly across instructions and models. This leads to widespread unnecessary over-refusal: inputs containing injections that the model could have handled correctly are rejected incorrectly. To deal with this over-refusal issue, we propose BASIS (Robustness-Aware Prompt Injection Defense). This defense method uses the Attention Competition Ratio ($ρ$) as features to train two sparse linear probes: an existence probe and a breach probe. Both probes make defense decisions through cascaded gating, which does not require additional LLM inference. BASIS comprises three stages: injection existence detection, per-sample breach prediction, and instruction robustness assessment; the online cascade refuses only when the model would actually be compromised and thus avoids over-refusal on robust instructions. Experiments across four tasks and six open-source LLMs show that BASIS maintains near-perfect injection detection while substantially reducing over-refusal on safe attack samples, especially under robust instruction templates.

- **核心问题**：大型语言模型（LLM）应用中，现有的提示注入防御方法主要分为两类：预防（加固提示结构）和检测（判断是否包含注入并拒绝）。这两类方法都存在一个关键缺陷——它们无法区分“模型是否真正会被注入指令劫持”。即使输入中含有注入，许多对齐良好的模型依然能“抵抗”该注入并完成原始任务，而检测型防御一律拒绝所有检测到注入的请求，导致严重的**过度拒绝（over‑refusal）**，牺牲了模型的正常服务能力。
- **整体含义**：需要一种**破坏感知（breach‑aware）的防御**，即仅当注入确实会导致模型输出被劫持时才进行拒绝，从而在安全性和可用性之间取得更好的平衡。

### 2. 论文提出的方法论
- **核心思想**：将防御拆解为两个独立的问题——注入是否存在（existence）与注入是否会实际攻破模型（breach）。利用LLM预填充阶段（prefill）的注意力模式构造特征，训练两个稀疏线性探针，再通过级联门控完成决策，无需额外的LLM推理。
- **关键技术细节**：
    - **注意力竞争比（Attention Competition Ratio）$ρ$**：
        - 从预填充最后一个 token 的注意力分布中，分离出分配给指令段（$S_{\text{ins}}$）和数据段（$S_{\text{data}}$）的注意力质量。
        - 定义每个头(l,h)的特征：$ρ_{l,h} = \frac{S_{\text{ins}}}{S_{\text{ins}}+S_{\text{data}}+ε}$。该值在[0,1]之间，反映指令侧与数据侧的注意力竞争。
        - 拼接所有层‑头的 $ρ$ 得到特征向量 $ρ(x) \in \mathbb{R}^{L\times H}$。
    - **两个稀疏线性探针**：
        1.  **存在探针（existence probe）**：二分类（有无注入），在所有干净样本和攻击样本上训练，使用弹性网络（elastic net）正则化，自动选出少量关键注意力头。
        2.  **破坏探针（breach probe）**：仅在攻击样本上训练，预测注入是否会导致模型输出被劫持（breach label 来自一次离线解码），同样采用弹性网络稀疏化。
    - **在线级联决策**：
        - 如果存在探针分数 $p_{\text{exist}} \le τ_p$ → 放行（Pass）。
        - 如果 $p_{\text{exist}} > τ_p$ 且破坏探针分数 $p_{\text{breach}} \le τ_b$ → 放行（预测不会实际攻破）。
        - 如果 $p_{\text{exist}} > τ_p$ 且 $p_{\text{breach}} > τ_b$ → 拒绝（Reject）。
    - **离线指令鲁棒性评估**：利用破坏探针在攻击样本上的平均预测概率，定义指令鲁棒性得分 IRS = 1 – 平均破坏概率，用于部署前比较不同指令模板的鲁棒性。

### 6. 论文的主要结论与发现
- **注入检测与破坏预测是可分离的问题**：仅检测注入存在而不判断是否实际生效，会导致大量不必要的拒绝；BASIS的存在探针和破坏探针分别捕捉这两种不同性质的信号。
- **BASIS 大幅减少过度拒绝**：在六个模型和四个任务上，BASIS‑Full 将安全攻击样本上的错误拒绝率（FPR‑S）从接近 100% 降至个位数或零，同时维持极低的残余攻击成功率（ASR_def），实现了更好的安全‑可用性平衡。
- **指令鲁棒性得分 IRS 与经验攻击成功率高度负相关**（Spearman ρ = −0.99），可作为部署前评估指令模板鲁棒性的可靠代理。
- **注意力竞争比 ρ 是有效的特征**：注入存在和模型被劫持均表现为某些注意力头向数据侧偏移（ρ降低），且破坏预测需要更广泛的注意力头参与。
- **双探针的权重几乎正交**，说明注入感知和指令劫持是模型内部不同的机制。
- 在自适应攻击（GCG 针对破坏探针）下，BASIS 仍能阻挡多数攻击，但破坏召回率有所下降，表明存在进一步加固的空间。

### 7. 优点
- **概念清晰**：明确区分“注入存在”与“模型被破坏”，并以级联方式实现选择性拒绝，直击现有防御的过度拒绝痛点。
- **计算高效**：仅需一次预填充的注意力统计，无需额外 LLM 推理，两个线性探针的成本极低。
- **可解释性强**：稀疏探针选出的关键注意力头可直接进行机制分析，特征 ρ 的物理含义明确。
- **离线评估功能**：通过 IRS 提供了指令模板的鲁棒性评估工具，对开发者友好。
- **实验全面**：覆盖多任务、多模型、多指令级别、多样化攻击、大量消融和泛化测试，结论可靠。

### 8. 不足与局限
- **依赖分段标注**：需要预先知道提示中哪些 token 属于指令段、数据段，实际部署中某些结构化不清晰的场景可能受限。
- **白盒假设**：防守方需获取目标模型的完整注意力矩阵，这要求对模型有较高访问权限，不适用于纯黑盒 API 调用场景。
- **破坏标签获取成本**：训练破坏探针需要离线让模型对攻击样本进行一次解码来标注 breach 结果，尽管是一次性的，但仍需要运行完整推理。

- **任务与模型覆盖**：虽然实验已很丰富，但任务类型仍属常规 NLP；未涉及代码生成、工具调用等更复杂的 LLM 应用场景，也未覆盖最新的超大模型（如GPT‑4系列）。
