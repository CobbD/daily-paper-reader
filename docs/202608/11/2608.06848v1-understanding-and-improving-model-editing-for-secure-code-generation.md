## 摘要
大型语言模型（LLMs）被广泛用于代码生成，但它们可能复现从不安全的训练模式中习得的漏洞实现。先前的工作主要探索了推理时加固，这在不修改目标模型的情况下减少不安全的生成，但依赖辅助组件并增加运行时开销。我们首次对模型编辑作为安全代码生成的模型级加固机制进行了系统性研究。我们在多个LLM系列上评估了三种最先进的编辑方法，并将它们与代表性的推理时方法CoSec进行比较，重点关注安全性、鲁棒性、泛化性和功能正确性。模型编辑在已见漏洞类型上比CoSec带来了更大的安全增益，与原始模型相比安全率提升15%-25%，且增益在提示扰动下保持稳定。然而，这些改进在未见漏洞上的迁移不可靠，且可能降低功能正确性。为了缓解这种权衡，我们提出了SafeEdit，一种结合功能调优与编辑感知正则化的编辑后优化方法。在八个目标LLM上，SafeEdit在T=0.1/0.4/0.8时将Pass@1较UltraEdit分别提升了11.73/13.70/15.50个百分点，同时基本保持了安全性。与CoSec相比，它实现了7.54%-12.04%的相对安全率增益。在CodeGuard+上的额外评估证实了联合安全与正确生成的改进。SafeEdit和CoSec也是互补的，它们的结合可以进一步提高安全性，同时保持强大的功能正确性。总体而言，我们的结果为将模型编辑应用于安全代码生成提供了基于证据的指导。

## Abstract
Large language models (LLMs) are widely used for code generation, yet they can reproduce vulnerable implementations learned from insecure training patterns. Prior work has mainly explored inference-time hardening, which reduces insecure generations without modifying the target model but relies on auxiliary components and adds runtime overhead. We conduct the first systematic study of model editing as a model-level hardening mechanism for secure code generation. We evaluate 3 state-of-the-art editing methods across diverse LLM families and compare them with CoSec, a representative inference-time approach, focusing on security, robustness, generalization, and functional correctness. Model editing yields larger security gains than CoSec on seen vulnerability types, improving security ratios by 15%-25% over vanilla models, with gains remaining stable under prompt perturbations. However, these improvements transfer unreliably to unseen vulnerabilities and can reduce functional correctness. To mitigate this trade-off, we propose SafeEdit, a post-edit refinement method combining functional tuning with edit-aware regularization. Across eight target LLMs, SafeEdit improves Pass@1 over UltraEdit by 11.73/13.70/15.50 percentage points at T=0.1/0.4/0.8 while largely preserving security. Compared with CoSec, it achieves relative security-ratio gains of 7.54%-12.04%. Additional evaluation on CodeGuard+ confirms improved joint secure-and-correct generation. SafeEdit and CoSec are also complementary, and their combination can further improve security while maintaining strong functional correctness. Overall, our results provide evidence-backed guidance for applying model editing to secure code generation.

- **核心问题**：**模型编辑**（model editing）作为一种轻量级、局部参数更新的模型级加固方式，能否在保证代码功能正确的前提下，有效提升生成代码的安全性？此前尚未有系统性研究对此进行评估。

## 2. 论文提出的方法论

### 2.1 研究框架与评估策略
- **整体流程**：
  1. 构建**安全编辑实例数据集 E**：将原始漏洞/修复函数对（来自公开的安全数据集）转化为编辑实例（包括漏洞相关前缀、不安全后缀、安全后缀、CWE 类别）。
  2. 应用三种模型编辑方法（UltraEdit, DINM, DEFER*）与一种推理时方法（CoSec）进行对比。
  3. 从三个维度评估：**安全有效性**（已见 CWE + 提示扰动鲁棒性）、**安全泛化性**（未见 CWE）、**功能正确性**（HumanEval/MultiPL-E/CodeGuard+）。
- **评估指标**：
  - **Security Ratio (SR)**：经 CodeQL 检测安全的有效生成数与总有效生成数的比值。
  - **Pass@k**：基于单元测试的执行通过率。
  - **TradeOff 分数**：SR 与 Pass@1 的调和平均值，综合衡量安全与功能。

### 2.2 核心方法：SafeEdit
- **背景**：研究发现，直接用模型编辑提升安全性会损害功能正确性（UltraEdit 损失相对较小）。SafeEdit 被设计为**UltraEdit 的编辑后精炼方法**，旨在恢复功能正确性而不覆盖已注入的安全知识。
- **关键挑战**：常规功能调优可能覆盖编辑修改的参数，导致安全知识丢失（即**安全编辑保留问题**）。
- **技术细节**：
  - **功能调优**：使用 Code Evol-Instruct 生成的大量通用编程指令对进行标准的下一 token 预测训练。
    \[
    \mathcal{L}_{\text{std}}(i, c) = -\sum_{t=1}^{|c|} \log P(c_t | c_{<t}, i)
    \]
  - **编辑感知正则化**：对 UltraEdit 修改过的参数子集施加 L2 正则化，约束其值不得偏离编辑后的状态过远。
    \[
    \mathcal{L}_{\text{reg}} = \|\theta_{\text{edit}} - \theta_{\text{edit}}^e\|_2^2
    \]
  - **总体损失**：
    \[
    \mathcal{L} = \mathcal{L}_{\text{std}} + \mu \mathcal{L}_{\text{reg}}
    \]
    其中 \(\mu\) 为正则化强度（默认为 \(1\times10^{-3}\)）。
  - 训练配置：全参数微调（但只对编辑过的参数子集施加正则化），2 epoch，学习率 \(2\times10^{-5}\)，使用 AdamW。

### 2.3 其他对比方法
- **UltraEdit**：对倒数第二层 Transformer 层的上投影矩阵进行一次性闭式参数偏移。
- **DINM**：基于梯度归因识别领域信息神经元，进行定向参数偏移。
- **DEFER***：外部记忆适配器，通过逐 token 路由分数决定使用编辑后的预测还是原始预测。
- **CoSec**：训练一个轻量级辅助安全模型，在推理时对目标 LLM 的 token 概率进行门控偏置。

## 3. 实验设计

### 3.1 数据集与场景
- **安全硬化数据集**：来自 He 和 Vechev [19] 的 710 对漏洞/修复函数，覆盖 9 个 CWE 类别（Python 和 C/C++）。
- **安全有效性评估**：
  - **已见 CWE 场景 (\(D_{sec}\))**：基于上述 9 个 CWE 设计的提示，每种 CWE 有多条实例，使用 CodeQL 检测漏洞。
  - **提示扰动鲁棒性 (\(D_{per}\))**：对 CWE-089 的一个 Python 场景进行元数据、文档、上下文代码等扰动。
- **安全泛化性评估**：17 个不在训练集中的 CWE 类别，29 个测试场景。
- **功能正确性评估**：
  - **HumanEval**：164 个 Python 编程任务，基于单元测试。
  - **MultiPL-E**：C++、JavaScript、TypeScript 的平均 Pass@1。
  - **CodeGuard+**：91 个提示，覆盖 34 个 CWE，使用 CodeQL+SonarQube 联合检测漏洞，并提供单元测试。
- **解码设置**：核采样（Top-P=0.95），最大 256 tokens，温度 \(T \in \{0.1, 0.4, 0.8\}\)，每个提示生成 25 个补全，10 个随机种子。

### 3.2 对比方法
- **基准**：Vanilla（原始模型）、CoSec（推理时方法）。
- **编辑方法**：UltraEdit、DINM、DEFER*。
- **精炼方法**：SafeEdit（针对 UltraEdit 进行精炼），并与 LoRA 微调对比。

## 6. 论文的主要结论与发现

1. **模型编辑的安全性优势**：在已见 CWE 上，编辑方法（特别是 DINM 和 UltraEdit）将安全率提升了 15%-25%，远超 CoSec（平均仅提升 1.46%），且对提示扰动保持鲁棒，而 CoSec 出现性能下降。
2. **安全与功能的权衡**：编辑方法的强安全性以功能正确性损失为代价（DINM 损失最大，UltraEdit 相对较小），CoSec 则更保守地保持功能正确性，尤其在高温解码下。
3. **泛化性有限**：编辑方法在已见 CWE 上的改善并不能可靠地迁移到未见 CWE，但 UltraEdit 等在部分情况下仍优于 Vanilla。
4. **SafeEdit 的有效性**：SafeEdit 能在几乎不损失安全性的情况下，大幅恢复 UltraEdit 的功能正确性（Pass@1 提升约 10-15 个百分点），并在所有模型上优于 Vanilla 和 CoSec 的安全-功能权衡。与 CoSec 相比，安全率相对增益为 7.54%-12.04%。
5. **互补性**：SafeEdit 与 CoSec 可以结合使用，进一步在随机解码下提升安全性。
6. **设计敏感性**：模型编辑的效果对编辑层深度、参数位置（上投影优于下投影/门控）、编辑后缀长度和数据集大小高度敏感。
7. **效率**：UltraEdit 等模型编辑方法在线推理几乎无额外开销；SafeEdit 仅有一项可接受的离线开销。

## 7. 优点

- **范式创新**：首次将模型编辑作为模型级安全加固手段进行系统性实证研究，填补了空白。

- **分析深入**：通过消融实验揭示了影响模型编辑效果的关键设计因素（如编辑位置、深度、后缀长度），提供了可操作的实用指南。
- **实验公平**：编辑与 CoSec 使用同一数据集，引入 CodeGuard+ 等更全面的指标，并进行统计检验和人工抽查，增强了结论的可信度。
- **开销明确**：论文详细对比了训练/编辑时间和推理延迟，使方法效率可视化。

## 8. 不足与局限

- **模型覆盖范围**：
  - 仅评估了开源模型，无法应用于 API 专属模型（如 GPT-4），这使得编辑范式的适用场景受限。
  - 编辑方法主要是 UltraEdit，而 SafeEdit 也在 UltraEdit 上开发，未探索与其他编辑器的结合（如 DINM）。
- **安全评估的局限性**：
  - 主要依赖 CodeQL 静态分析，存在误报和漏报（尽管进行了人工抽查）。
  - 对不同编程语言的覆盖率不足（主要基于 Python 和 C/C++ 的数据集，功能测试仅 HumanEval 为 Python，MultiPL-E 补充了其他语言，但安全评估并未在多语言上充分展开）。
  - 未见 CWE 泛化评估仅使用 17 个类别，且场景数量有限（29 个测试场景）。
- **超参数与设计选择**：
  - SafeEdit 的正则化强度 μ 等超参数可能需针对不同模型调整。
  - 未详尽探索编辑数据集大小与功能的非线性关系，编辑后的遗忘问题未深入讨论。
- **实用性挑战**：
  - 编辑可能引入新 bug 或改变代码逻辑，仅靠静态分析无法完全捕获。
  - SafeEdit 的后编辑精炼需额外训练数据 Code Evol-Instruct，可能不适用于高度保密的内部模型。
- **统计与实验**：
  - 虽使用了 10 个随机种子，但未报告置信区间宽度等具体变化程度。
  - 对扰动的鲁棒性实验仅基于一个场景（CWE-089），可能不全面。
