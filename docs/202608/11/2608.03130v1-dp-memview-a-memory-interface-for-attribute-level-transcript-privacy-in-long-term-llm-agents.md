## 摘要
长期记忆使LLM智能体能够实现持久的个性化，但反复基于记忆的响应可能累积地泄露受保护属性，即便这些属性从未被明确陈述。我们将此威胁形式化为自适应对话记录隐私，并提出DP-MemView，这是一个差分隐私接口，它私下选择公开的响应条件视图，并将这些视图——而非原始记忆——暴露给响应LLM。每次私下选择都会向每个其记忆组与读取集相交的受保护属性收取费用。每个属性的账本会阻止任何超出其限额的选择，并转而返回一个固定的通用视图。在明确的接口契约下，我们证明了整个自适应对话记录的纯B_a-DP。我们还将结果扩展到存储内容在多个受保护组之间有所不同的情形，并界定了观察对话记录能改变对手先验几率的程度。我们在受控的相邻存储基准测试和公共语料库迁移轨道上，使用三种响应LLM评估了在线模式和预分配模式。两种模式都将对话记录的可区分性保持在随机水平附近，同时保持了目标所需的个性化和整体响应质量。进一步的诊断表明，移除关键保护措施会导致输出支持不匹配、缺少账本收费、泄露侧信道，或长期泄露增长。

## Abstract
Long-term memory enables persistent personalization in LLM agents, but repeated memory-conditioned responses can cumulatively reveal protected attributes even when they are never stated explicitly. We formalize this threat as adaptive transcript privacy and introduce DP-MemView, a differentially private interface that privately selects public response-conditioning views and exposes those views---rather than raw memory---to the response LLM. Each private selection is charged to every protected attribute whose memory group intersects the read set. Per-attribute ledgers block any selection that would exceed its cap and return a fixed generic view instead. Under an explicit interface contract, we prove pure B_a-DP for the entire adaptive transcript. We also extend the result to stores that differ across multiple protected groups and bound how much observing the transcript can change an adversary's prior odds. We evaluate the online and preallocated modes with three response LLMs on a controlled adjacent-store benchmark and a public-corpus transfer track. Both modes keep transcript distinguishability near chance while preserving target-required personalization and overall response quality. Further diagnostics show that removing key safeguards causes mismatched output support, missing ledger charges, revealing side channels, or growing long-horizon leakage.

### **2. 方法论**

*   **核心思想**：提出 **DP-MemView**，一个位于原始记忆和响应生成LLM之间的可信、差分隐私接口。该接口不直接向LLM暴露原始记忆文本，而是从预先定义的公开“视图”（views）词汇表中私有地选择一个“响应条件视图”，LLM仅基于此视图生成回复。
*   **关键技术细节**：
    *   **记忆模型**：将长期记忆建模为索引存储 `M`，每个记忆位置属于策略定义的槽位（如健康、财务）。受保护属性由多个记忆位置共同定义，形成属性组 `I_a`，且组之间可以重叠。
    *   **视图选择与属性收费**：
        1.  **视图词汇表**：每个槽位有一个固定的、在相邻数据库间共享的公开视图词汇表 `V_g`，包含一个固定的通用视图 `v^gen_g`。视图编码了“如何回答”的模式，而非原始事实。
        2.  **读取与收费**：当收到查询时，路由器确定活跃槽位及读取的记忆位置集 `R_{t,g}`。该读取操作会影响所有其属性组与 `R_{t,g}` 有交集的受保护属性 `Γ⋆(R_{t,g})`，必须向所有这些属性的隐私预算账本收费。
        3.  **私有选择机制**：使用指数机制（Exponential Mechanism, EM）从 `V_g` 中选择视图，其概率与内部评分函数 `u` 成正比。评分函数仅基于公开查询和读取到的记忆内容，且其值在相邻数据库间的最大差异（灵敏度 `Δu_{t,g}`）受到限制。
        4.  **预算控制与回退**：每个受保护属性 `a` 都有一个预分配的隐私预算上限 `B_a` 和实时账本 `L_a`。在选择视图前，会检查是否所有受影响的属性都有足够预算（`L_a + ε_{t,g} ≤ B_a`）。如果任何检查失败，接口将返回固定的通用视图 `v^gen_g`，且不消耗任何预算。
    *   **形式化保证（定理1）**：在满足其定义的一系列接口契约（Interface Contract）条件下，DP-MemView 保证整个自适应对话记录 `τ_T`（包含查询、视图、控制信号和LLM响应）满足关于每个受保护属性的纯 `B_a`-差分隐私。契约要求包括：
        *   `(C1)` 视图词汇表在相邻数据库间共享。
        *   `(C2)` 每次读取必须向所有受影响的属性收费。
        *   `(C3)` 所有发布的视图要么与数据库无关，要么通过EM采样得到。
        *   `(C4)-(C5)` 接口内的路由、预算检查等操作必须基于公开信息，并强制执行每路径预算上限。
        *   `(C6)` 下游的LLM响应必须是基于公开输入的后处理。

### **6. 主要结论与发现**

*   **隐私-效用权衡**：DP-MemView的两种模式都能将对话记录的属性可区分性（AUC）降低到接近随机水平（0.5），远超所有基于暴露原始或简化记忆文本的方法（`RawReadSet`， `TaskMin`， `OutputFilter`）。同时，它在保持较高整体响应质量（U）和恢复大部分目标所需的个性化（tRec）方面，优于仅用通用视图（`GenericOnly`）或类型掩码（`TypedMask`）的对照组。
*   **模式特性**：在线模式在限制非支持的个性化（Unsup）方面表现更好，而预分配模式在提供目标所需的个性化（tRec）方面更优，适用于计划收费次数已知的场景。
*   **接口契约的必要性**：消融实验证实，仅仅使用私有视图选择器是不够的。
    *   不完整的收费（`IncompleteCharge`）会导致属性账本不正确。
    *   使用确定性的最高分视图选择（`CappedArgmax`）会导致无限的隐私损失。
    *   移除预算上限（`NoCap`）会导致隐私成本累积超出预分配的界限。
    所有这些违规操作虽然提升了tRec，但都导致了对话记录可区分性显著增加，破坏了形式化的隐私保证。

### **7. 优点**

*   **问题形式化新颖**：将长期记忆LLM智能体的隐私问题精确定义为“自适应对话记录隐私”，而非单一的输出过滤问题，具有前瞻性。
*   **理论保证强**：提供了严格的、可组合的纯差分隐私保证，覆盖整个自适应交互序列，并给出了推断界限的解释，理论基础扎实。
*   **接口契约设计严格**：不仅关注私有选择算法，更将隐私保证建立在完整的接口契约之上，明确界定了信任边界和必要的约束条件，并系统地证明了其必要性。
*   **实验设计全面且严谨**：通过构建精确控制的合成数据和引入公共语料迁移数据，既证明了内部有效性又考察了外部泛化能力。多维度、多模型的对比和深入的消融分析，使得结论非常可靠。

### **8. 不足与局限**

*   **实验覆盖范围**：评估仅针对生成式LLM智能体的对话记录，未涉及其他形式的智能体交互，如工具使用、代码执行或动作执行等。
*   **模型与数据偏差风险**：虽然在三个模型和公共语料上进行了验证，但实验的焦点是四种特定的受保护属性。泛化到其他类型和数量的属性、更复杂的记忆结构以及不同类型的LLM可能有所不同。
*   **应用限制**：
    *   **隐私分组要求**：隐私保证依赖于所有可能泄露某属性的记忆位置都被正确地预先归入该属性组，这是一个较强且非平凡的前提假设。
    *   **静态记忆布局**：方法基于固定的记忆位置和槽位策略，难以直接应用于动态增长或非结构化的记忆库。
    *   **评分函数设计**：内部评分函数的设计直接影响视图选择和效用，论文使用了一个特定的组合评分，其设计质量在不同领域任务中可能需要精心调整。
    *   **预算分配**：预分配模式需要预知未来的收费次数，在线模式的预算粒度 `K` 选择仍需经验性调整。
