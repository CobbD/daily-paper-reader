## 摘要
代理技能——增强基于大语言模型的代理的结构化指令和脚本包——正在迅速扩散，但其安全属性仍未得到充分探索。我们提出了 SkillsMetric，一个五阶段静态分析框架，从模式密度、统计异常、数据流污点、导入异常和能力不匹配维度对技能包进行评分。我们构建了一个包含2266个技能的对抗性评估数据集，涵盖代码级、系统级和语义级威胁的16种攻击类型，并在完整的SkillMD-138K语料库上进行了评估。我们的框架实现了0.93的AUC和73.4%±0.5%的5折交叉验证F1分数，对数据泄露（93%）和隐写载荷（93%）具有很强的检测能力。关键的是，我们发现了根本性的盲点：使用常见shell命令的“主机破坏”攻击避开了所有五个阶段（0%检测率），而通过自然语言操纵的“提示注入”攻击仅达到42%的检测率。这些发现表明，仅靠静态分析不足以保障技能安全，推动了结合快速静态预筛选与语义审查的纵深防御架构。

## Abstract
Agent Skills---structured packages of instructions and scripts that augment LLM-based agents---are rapidly proliferating, yet their security properties remain under-explored. We present \textsc{SkillsMetric}, a five-stage static analysis framework that scores skill packages along pattern density, statistical anomaly, dataflow taint, import anomaly, and capability mismatch dimensions. We construct an adversarial evaluation dataset of 2{,}266 skills spanning 16~attack types across code-level, system-level, and semantic-level threats, and evaluate on the full SkillMD-138K corpus. Our framework achieves an AUC of 0.93 and 5-fold cross-validated F1 of 73.4\%$\pm$0.5\%, with strong detection of data exfiltration (93\%) and steganographic payloads (93\%). Crucially, we identify fundamental blind spots: \emph{host destruction} attacks using common shell commands evade all five stages (0\% detection), and \emph{prompt injection} via natural-language manipulation achieves only 42\% detection. These findings establish that static analysis alone is insufficient for skill security, motivating defense-in-depth architectures that combine fast static pre-screening with semantic review.

### 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程
#### 核心思想
提出一个五阶段静态分析框架 **SkillsMetric**，对技能包（SKILL.md + 脚本）的内容进行多维度评分，最终生成一个综合风险分数 \( S \in [0, 100] \)，并根据分数映射到五级风险等级。

#### 关键技术细节与流程
技能包依次通过以下五个分析阶段：
1.  **Stage 1: 模式密度 (Pattern Density)**  
    使用超过50条加权正则表达式，扫描危险关键词与代码构造（如 `exec`、`curl`、凭证路径等），覆盖 Python、Bash、JavaScript、Ruby，并按内容长度归一化。
2.  **Stage 2: 统计异常 (Statistical Anomaly)**  
    计算香农熵、压缩比、卡方均匀性、序列相关性等特征，与良性语料库基线比较（z-score），检测具有异常字节分布的编码/加密载荷。
3.  **Stage 3: 数据流污点分析 (Dataflow Taint Analysis)**  
    识别“源-转换-汇”三阶段污点链（例如，读取凭证 → Base64编码 → HTTP发送）。完整的污点链获得最高分。
4.  **Stage 4: 导入异常 (Import Anomaly)**  
    标记与安全相关的异常包组合（如 `urllib` + `base64` + `os`），并与良性依赖基线对比。
5.  **Stage 5: 能力不匹配 (Capability Mismatch)**  
    对比 SKILL.md 中声明的能力与实际代码行为，检测“声称无害功能但存在网络/文件系统访问”的技能。

#### 分数合成公式
最终分数由各阶段加权和加上交互奖励构成：
\[
S = \sum_{i=1}^{5} w_i \cdot \hat{s}_i + \text{bonus}(s)
\]
*   权重向量 \( w = (0.15, 0.20, 0.30, 0.15, 0.10) \)，其中 S3（数据流污点）权重最高，因其稀有且区分性强；S5 权重最低，因良性元数据声明不一致。
*   交互奖励：当≥2个独立阶段同时触发加5分，≥3个触发加10分（S2除外，因其与S1不独立）。
*   权重为经验手动设定，旨在保持可解释性，避免对小规模恶意样本过拟合。
*   根据总分映射风险等级：SAFE (<10), LOW (10-24), MEDIUM (25-44), HIGH (45-69), CRITICAL (≥70)。检测阈值 \( \tau = 25 \)，基于真实 138K 技能语料中分数的第95百分位（16.77）设定，将总体标记率控制在 1.75%。
