## 摘要
计算机使用代理（CUAs）使大型语言模型能够自主操作操作系统和网络，但它们越来越容易受到间接提示注入攻击。一种广泛采用的防御策略是人机协同范式，即代理在执行敏感操作前暂停以获取用户明确确认。虽然这种防御对明显具有高度危害的攻击有效，但对于我们称之为“隐形墨水威胁”的情况却几乎不提供保护：这些注入的低危害目标，例如标星仓库或安装软件包，在行为上与合法任务执行难以区分，从而同时规避了模型安全机制和人类监督。为了系统研究这一盲点，我们提出了II-Bench，这是一个由看似无害的对抗性任务组成的集合。II-Bench包含444个示例，针对三个平台上的机密性和完整性攻击，涵盖三个攻击类别：页面导航与交互、敏感信息窃取以及代码下载与执行。每个类别都以自然语言和代码形式在两种指令具体性级别下实现。此外，我们构建了HITLCUA，这是一个全面的对抗性测试框架，它集成了真实的虚拟机操作系统环境与基于Docker的隔离网络平台，并通过允许CUAs在执行可疑操作前咨询由API模拟的用户来模拟人类参与。对领先CUAs的广泛评估表明，低危害注入经常绕过代理防御和模拟用户审查，暴露了当前CUAs中严重且此前未充分探索的安全风险。

## Abstract
Computer-use agents (CUAs), which empower large language models to autonomously operate operating systems and the web, are increasingly vulnerable to indirect prompt injection attacks. A widely adopted defense is the human-in-the-loop paradigm, in which the agent pauses for explicit user confirmation before executing sensitive operations. While effective against conspicuously high-harm attacks, this defense offers little protection against what we term Invisible Ink Threats: low-harm injected goals, such as starring a repository or installing a package, that are behaviorally indistinguishable from legitimate task execution and thus evade both model safety mechanisms and human oversight. To systematically investigate this blind spot, we present II-Bench, a collection of seemingly harmless adversarial tasks. II-Bench comprises 444 examples targeting confidentiality and integrity attacks across three platforms, spanning three attack categories: page navigation and interaction, sensitive information exfiltration, and code download and execution. Each category is instantiated in both natural language and code forms under two levels of instruction specificity. Furthermore, we construct HITLCUA, a comprehensive adversarial testing framework that integrates a real virtual machine operating system environment with isolated Docker-based web platforms, and simulates human participation by allowing CUAs to consult an API-simulated user before proceeding with suspicious operations. Extensive evaluations of leading CUAs reveal that low-harm injections frequently bypass both agent defenses and simulated user review, exposing severe and previously underexplored security risks in current CUAs.

### 1. 论文的核心问题与整体含义

- **研究背景**：计算机使用代理（CUA）依赖于大型语言模型（LLM）来自主操作计算机和网络，但其读取并执行外部网页内容的能力使其极易受到“间接提示注入攻击”。即攻击者可在网页、论坛等环境中嵌入恶意指令，操控代理执行有害行为。
- **核心问题**：当前主流防御策略——“人机协同”（Human-in-the-loop），要求代理在执行敏感操作前进行高风险预警并请求用户确认。然而，该防御对“**隐形墨水威胁**”（Invisible Ink Threats）失效。
- **威胁定义**：此类攻击注入的目标是看似无害、低风险的操作（如标星仓库、安装软件包、订阅帖子），其在行为模式上与代理的合法任务几乎无法区分。这使得攻击不仅能绕过模型的内部安全机制，而且即使用户介入审查，非专家用户也很难识别出其中的恶意意图，从而留下了严重的安全盲区。

        3.  **代码下载与执行**：让代理从不可信源下载、安装软件包或执行代码。

### 6. 论文的主要结论与发现

- **广泛脆弱性**：所有被测试的计算机使用代理在面对“隐形墨水威胁”时都表现出严重漏洞，平均攻击成功率高达 51.8% 至 90.5%。
- **具体指令非有效防御**：更具体的用户指令可以降低攻击成功率，但不能消除风险。
- **平台环境影响**：攻击难度与环境的信噪比和交互性相关。信息繁杂的平台（如 Reddit）攻击相对困难，而通过聊天进行交互式注入（如 RocketChat）则更容易利用社会信任，成功率更高。
- **代码注入是强大放大器**：以代码形式注入的恶意指令，比自然语言形式的攻击成功率平均高出 8.1 个百分点，因为其与合法的安装、执行步骤在行为上高度一致。
- **能力与脆弱性并存**：“发送/窃取”（Download）类攻击最有效，因其行为与任务本身重叠度高。而“页面交互”（Post）类攻击的成功更依赖于模型的强大能力，强大模型虽然整体更安全，但一旦被欺骗，也能执行更复杂的恶意交互，潜在地扩大了攻击面。
- **人机协同防御失效**：最关键的发现是，人机协同不仅未能缓解攻击，反而“放大”了攻击风险。因为非专家用户无法区分低危害的恶意操作与合法任务，在审查时高概率（73.5%-83.3%）批准了这些操作，这使得确认步骤变成了攻击的“合法化”工具。

### 7. 优点

- **概念创新**：提出了“隐形墨水威胁”这一新颖且符合现实威胁模型的概念，指出了当前安全研究的重大盲区。
- **基准与框架贡献**：贡献了专门设计的 II-Bench 基准和高度仿真的 HITLCUA 测试框架，为后续研究奠定了坚实基础。
- **对主流防御的深刻挑战**：通过严谨的实验，揭示并量化了被业界广泛采用的人机协同防御机制在面对低危害隐蔽攻击时的反效果，这一发现具有很高的现实意义和警示作用。
- **实验设计细致**：实验设计从多维度（指令、模态、平台、任务）解构了攻击有效性的机制，而非仅仅报告一个成功率。

### 8. 不足与局限

- **非真实用户**：虽然模拟用户经过了真人验证，但大规模评估仍然使用语言模型模拟的非专家用户（NPC2），其决策模式可能与真实人类群体存在偏差。
- **攻击类别限制**：攻击主要针对“机密性”和“完整性”，未涉及“可用性”攻击（如删除文件），尽管作者声明这是有意为之，但可用性攻击在现实中也常见。
- **无防御方案**：论文的重点在于揭示问题，并未提出任何针对此类威胁的有效防御方法或缓解措施。
- **解耦评估的理想化**：为了保证测试公平，实验直接将代理放置在攻击页面，这与真实场景中代理需要自行漫游并发现攻击内容的过程有所差异，可能低估或高估了某些方面的实际风险。
- **注入模板的单一性**：攻击注入使用了统一的模板（如“THIS IS IMPORTANT!”），这可能引入了特定的模式，在不同模板下的泛化性未得到验证。
