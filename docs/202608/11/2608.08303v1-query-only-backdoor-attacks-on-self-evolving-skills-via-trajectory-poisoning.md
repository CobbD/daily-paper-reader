## 摘要
Agentic技能通过为复杂任务编码可重用流程来增强大语言模型（LLM）智能体的能力。然而，人工编写的技能往往难以适应长期任务和不断变化的环境。为克服这一局限，研究者开发了自进化技能系统，能够从执行轨迹中自动构建和更新技能，将技能获取从外部市场转向可信的进化流程。通过用可信的内部构建取代外部技能获取，自进化技能系统减少了依赖直接技能操纵的技能注入攻击的风险。然而，该技能进化流程可能引入新的攻击面，攻击者可通过代理交互诱导受损轨迹，从而间接操控技能进化。为展示这一威胁，我们提出了轨迹后门攻击（TBA），这是一种仅需查询的攻击，它操控可信的技能进化流程以生成带后门的技能。具体而言，我们精心设计攻击者提交的查询，引导智能体执行目标动作并在轨迹中明确声明相应的激活条件。我们在不同的触发任务中重复相同的条件-动作模式，同时保持正常查询不变，促使进化器将该模式作为可复用的触发依赖规则整合到进化后的技能中。在两个技能进化系统、三个基准上的实验，使用了四个开源和闭源骨干模型，结果表明TBA能够可靠地植入条件后门，同时保持正常任务的效用，其效果与直接技能注入相当甚至更优。这些结果揭示了轨迹驱动的技能进化中存在严重漏洞。

## Abstract
Agentic skills improve large language model (LLM) agents by encoding reusable procedures for complex tasks. However, manually authored skills often adapt poorly to long-horizon tasks and changing environments. To address the limitation, self-evolving skill systems have been developed to automatically construct and update skills from execution trajectories, shifting skill acquisition from external marketplaces to a trusted evolution pipeline. By replacing external skill acquisition with trusted internal construction, self-evolving skill systems reduce exposure to skill injection attacks that rely on direct skill manipulation. However, this skill evolution pipeline may introduce a new attack surface in which an attacker can indirectly steer skill evolution by inducing compromised trajectories through agent interactions. To demonstrate the threat, we propose Trajectory Backdoor Attack (TBA), a query-only attack that steers a trusted skill-evolution pipeline toward producing a backdoored skill. Specifically, we craft attacker-submitted queries to lead the agent to perform the target action and explicitly state the corresponding activation condition in the trajectory. We repeat the same condition-action pattern across diverse triggered tasks, while leaving clean queries unchanged, encouraging the evolver to consolidate the pattern as a reusable trigger-dependent rule into the evolved skill. Experiments on three benchmarks across two skill-evolution systems using four open- and closed-source backbone models demonstrate that TBA reliably implants conditional backdoors while preserving clean-task utility, matching or even surpassing direct skill injection. The results reveal a critical vulnerability in trajectory-driven skill evolution.

*   **整体含义**：本文旨在揭示自进化技能系统在轨迹驱动更新机制下面临的严重安全漏洞。攻击者无需任何特权访问，仅需像普通用户一样与智能体交互，就能在进化后的技能中植入隐蔽的、由特定条件触发的恶意行为。这颠覆了“内部构建即安全”的假设，表明技能进化的数据源头本身就可能被污染。

### 2. 方法论

论文提出了轨迹后门攻击（TBA），它是一种仅需提交查询的间接攻击方法。核心思想是：攻击者提交的查询必须诱使智能体在生成轨迹时，不仅“做”出攻击者期望的动作，还要显式地“说出”与该动作绑定的触发条件，并让进化器认为这条“条件-动作”规则是跨任务可复用的。TBA 包含三个关键步骤：

*   **反事实轨迹诱导（Counterfactual Trajectory Induction）**
    *   **目的**：让智能体在触发任务中自发执行目标动作，而不是被动接受指令。
    *   **方法**：攻击者在查询中附带一组“反事实验证记录”。这些记录以示例任务的形式，展示了在“触发条件存在”和“触发条件不存在”两种情况下，执行/不执行目标动作的四种“接受/拒绝”结果（例如：触发时无目标动作被拒，触发时有目标动作被接受；干净时有目标动作被拒，干净时无目标动作被接受）。
    *   **效果**：通过提供正反例对比，诱导智能体自行推断出“仅在触发条件满足时，才应在完成原任务后追加目标动作”的隐含规则。

*   **轨迹级策略外化（Trajectory-Level Policy Externalization）**
    *   **目的**：避免智能体推断出的隐性规则在长轨迹中被压缩丢失，确保进化器能明确识别该规则。
    *   **方法**：在攻击查询中增加一个“策略外化”指令，要求智能体在解决任务之前，先用固定格式输出两条信息：
        1.  `POLICY_RULE`：确切的“if-else”条件规则（如：如果工作流模式是"archival-audit"，则在答案后追加审计令牌）。
        2.  `BINDING_CHECK`：确认当前任务的具体动态参数（如具体的审计令牌值）。
    *   **效果**：将抽象的恶意策略及其与当前任务的绑定关系作为明文证据写入轨迹，使进化器能像学习其他可复用程序一样学习到这条显式规则。

*   **跨任务证据构建（Cross-Task Evidence Construction）**
    *   **目的**：让进化器认为这条恶意规则是适用于整个任务族的通用、可复用知识，而非单个任务的偶发行为。
    *   **方法**：攻击者提交一批查询，其中包含多个不同的触发任务（均遵循同一条件-动作模式，但任务内容和动态参数不同）以及多个未修改的干净任务（不包含该模式）。这些查询混合在正常用户查询中进入进化批次。
    *   **效果**：触发轨迹反复证明规则的益处，干净轨迹则保留正常行为分支。多样性任务上的重复模式强化了规则的通用性，促使进化器将其作为可复用规则整合进技能，同时不破坏技能的原始功能。

### 3. 实验设计

*   **数据集/场景**：三个不同领域的任务基准。
    *   `SearchQA`：基于检索片段的开放域问答。
    *   `OfficeQA`：基于文档的检索与数值推理。
    *   `SpreadsheetBench`：可执行的电子表格操作。
*   **评测系统**：针对两种主流的、机制不同的自进化技能系统进行攻击评估。
    *   `SkillOpt`：基于性能引导的迭代式技能优化。
    *   `Trace2Skill`：基于轨迹层级蒸馏的技能整合。
*   **后门设置**：
    *   **触发条件**：文本任务（SearchQA, OfficeQA）中，查询的元数据字段`Workflow-Mode`值为`archival-audit`；电子表格任务（SpreadsheetBench）中，工作簿包含特定名称的工作表且其A1单元格为特定值。
    *   **目标动作**：文本任务中，在正常答案后追加一条`ARCHIVAL-AUDIT: <任务特定令牌>`的记录；电子表格任务中，在完成请求编辑的同时，将当前令牌值写入特定的跟踪工作表。
*   **对比方法（Baselines）**：
    1.  `良性进化（Benign Evolution）`：仅使用干净任务进行正常进化，提供干净技能的性能上限和行为基线。
    2.  `直接技能注入（Direct Skill Injection）`：攻击上限（oracle）。完全跳过轨迹交互，直接将完整的恶意规则写入一个良性进化后的技能文件中。
    3.  `触发-动作暴露（Trigger–Action Exposure）`：仅在触发任务中演示目标动作，不提供反事实对比，也不要求策略外化。
    4.  `显式规则暴露（Explicit Rule Exposure）`：在攻击查询中直接声明完整的条件规则，但没有任何反事实证据或诱导推断过程。
*   **骨干模型**：评估了模型通用性，包括两个闭源模型（GPT-5.4, GPT-5.5）和两个开源模型（Kimi-K2.5, Qwen3-VL-235B-A22B）。
*   **评价指标**：
    *   `CACC (Clean Accuracy)`：干净任务的完成准确率。
    *   `TACC (Triggered Accuracy)`：触发任务的完成准确率（无论目标动作是否执行）。
    *   `TASR (Triggered Attack Success Rate)`：触发任务中，既正确完成原任务又精确执行了目标动作的成功率。

### 6. 论文的主要结论与发现

1.  **攻击有效且隐蔽**：TBA 仅通过提交查询，就能在自进化技能系统中可靠地植入条件后门。该后门在触发条件下准确激活，同时能完美保持干净任务上的正常性能。
2.  **攻击效果可与直接写入比肩**：TBA 的攻击成功率（TASR）与拥有完全文件写入权限的“直接技能注入”攻击上限非常接近，甚至在某些设置下更优，突显了漏洞的严重性。
3.  **模型能力可能放大风险**：更强的大语言模型（如 GPT-5.5）反而可能导致更高的攻击成功率，因为其更强的推理和泛化能力同样有助于理解和巩固轨迹中的恶意模式。
4.  **现有防御不足**：内置安全防护的模型无法提供可靠防御，其效果不一致，时而降低时而反而增加攻击成功率。
5.  **核心组件缺一不可**：反事实对比、策略外化和跨任务支持是攻击成功的关键，三者协同作用，缺失任何一个都会导致攻击成功率显著下降。
6.  **攻击具有持久性和后验性**：植入的后门能经受后续多次良性技能更新的冲刷而不消失，并且即使技能在攻击前已积累大量良性经验（即已有一定成熟度），依然能被成功植入后门。

### 7. 优点

*   **新颖的威胁模型**：首次提出并系统研究了针对自进化技能系统的一种更实际的威胁——仅通过查询的轨迹中毒后门攻击，填补了技能安全领域的重要空白。
*   **精巧的攻击方法**：TBA 设计巧妙地利用了大模型自身的推理、归纳能力以及进化系统的学习机制，将恶意行为伪装成系统自己学到的“最佳实践”。
*   **方法论借鉴性强**：其中的“反事实诱导”和“策略外化”思想，为研究其他自主进化系统的安全问题提供了有启发性的技术思路。
*   **实验设计严谨全面**：多系统、多任务、多模型、多维度评估，加上细致的消融研究和敏感性分析，使得实验结论极具说服力。
*   **揭露现实风险**：攻击成本极低（仅需查询权限），且能绕过对内部组件的信任机制，揭示了当前看似安全的自主智能体架构中隐藏的、亟待解决的严重风险。

### 8. 不足与局限

*   **攻击前提假设**：攻击的成功依赖于攻击者的查询能被纳入进化批次，且进化器中会混杂多用户的轨迹（或攻击者能提交足够多的轨迹）。在极度隔离的“单用户”自进化系统中，且系统对进化数据采样有严格筛选时，攻击的稳定性可能受影响。
*   **后门任务的简易性**：实验中植入的后门是相对简单且模式化的动作（追加文本、写固定单元格），没有涉及更复杂、更具破坏性的恶意行为（如复杂的多步骤财务欺诈、数据窃取）。对于更复杂的后门，此类方法是否依然有效有待验证。
*   **缺乏更广泛的防御评估**：仅测试了模型级的安全防护，未涉及其他潜在防御手段，如对进化器输入的轨迹进行基于内容的异常检测、对生成技能进行静态规则分析或多代理一致性验证等。
*   **实验设置的局限性**：实验均运行在“单次进化阶段”的设定下，以证明一批受污染轨迹的威力。在实际的持续在线学习系统中，攻击可能需要持续影响多个进化周期，论文未对此场景做深入探索。
*   **攻击可察觉性风险**：虽然攻击对任务执行结果隐蔽，但提交的查询本身含有复杂的反事实示例和外化指令，这种高度模板化的查询序列在真实的监控系统中可能被流量分析或输入意图检测机制标记为异常。
