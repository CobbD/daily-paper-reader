# From A2A Attacks to Envelope-Layer Defense: Red-Teaming Evaluation of LLM Agents and a Three-Layer Isomorphic Attack–Defense Model 

Yuelin Han 

✦

Abstract —Agent interaction protocols such as ACP and A2A have moved LLM-based agents toward multi-agent collaboration, introduc-ing new security threats. A task sent by a remote peer over A2A is treated as a legitimate request, providing a natural channel for indirect prompt injection. Existing agent security evaluations mostly rely on a single metric, the attack success rate (ASR), and cannot distinguish whether an attack failed because the LLM recognized the malicious content or because a mechanism at the agent layer blocked execution. To address this, we propose A2A-TIBA, an attack principle combining indirect prompt injection with bypass circumvention. Through implant– command–exfiltration steps, it induces the target agent to deploy a callback interaction program, after which the attacker issues commands bypassing the agent. To evaluate defenses finer, we design GDA Mea-surement, a red-team testbed method using raw context capture via an LLM gateway, dual data preservation, and agent-based autonomous judging. We propose four attack outcomes, Class A/B/C/D, extending ASR into semantic refusal rate, semantic breach rate, interception rate, and penetration rate. Experiments reveal the envelope layer — the channel through which malicious content enters an agent — as a new defense dimension. We accordingly propose ELA-ITL, a three-layer isomorphic attack–defense model, dividing defense into envelope pack-aging, LLM recognition, and agent interception, and attack into implant channel, prompt optimization, and execution mechanism. Testing on 15 agent front-end × LLM back-end combinations and building a 1,000-case dataset verifies the attack effectiveness of A2A-TIBA, the evalua-tion validity of GDA Measurement, and confirms that adding malicious prompt labels to envelope packaging such as A2A, tool, and memory channels significantly improves LLM recognition of malicious content. 

Index Terms —A2A protocol; indirect prompt injection; bypass circum-vention; LLM agent security; red-team evaluation; envelope-layer de-fense; three-layer isomorphic attack–defense model 

1 INTRODUCTION 

# LARGE language models (LLMs) are widely applied to agents capable of autonomously executing tasks. The think → act → observe loop paradigm represented by ReAct [1] has effectively improved the ability of agents to perform complex tasks. The survey in [2] further characterizes the capability framework of agents in terms of planning, mem-ory and tool use. With the proposal of agent interaction protocols such as ACP (Agent Communication Protocol) [3] and A2A (Agent-to-Agent) [4], the agent ecosystem has gradually shifted from single-agent operation to multi-agent collaboration, raising the ceiling of agent capability while introducing new risk surfaces. The wide deployment of A2A introduces new security threats that do not exist for a single agent. Unlike the user– agent interaction of a conventional single agent, the A2A protocol allows one agent to send a task request to another agent in the role of a “remote peer”, and such requests are treated by the receiver as legitimate. A2ABreak carried out a systematic security analysis of the A2A protocol and showed that an attacker can achieve contextual privilege escalation in A2A through legitimate means [5]; Habler et al. applied the MAESTRO threat modeling framework to A2A and identified potential vulnerabilities in message verification, identity spoofing and protocol negotiation [6]. Meanwhile, indirect prompt injection has become a primary method of hijacking agent behaviour [7], and the A2A protocol provides a natural attack channel for it. Beyond ASR pointed out the shortcomings of the attack success rate (ASR) [8], yet existing agent security evaluations still mostly rely on this single metric, which makes it hard to tell whether an attack failed because “the LLM recognized the malicious content” or because “the agent layer inter-cepted the execution of the malicious task”. This lack of measurement granularity makes it difficult to accurately characterize the actual effect of different defense layers in an agent system, leaving the optimization information of agent defense incomplete. To address these problems, this paper makes four contri-butions. (1) We propose A2A-TIBA, an attack principle that combines indirect prompt injection with bypass circumven-tion over the A2A protocol, and implement it as a concrete attack skill. Through the three steps of implant–command– exfiltration, the attack ensures that after a single successful malicious implant, all subsequent attacks bypass the agent’s defense mechanisms. When the attacker is able to establish an A2A communication link with the target agent and the security policy of the target agent permits deploying and running programs on its host, sensitive information can be stolen from the host on which the target agent runs. (2) We design GDA Measurement, a red-team testbed evaluation method based on an LLM gateway. Through its three com-ponents — raw context capture via the LLM gateway, dual data preservation and agent-based autonomous judging — it separates the measurement of defense effects at the agent layer and at the LLM layer, and it introduces four attack out-comes, Class A/B/C/D, extending ASR into new metrics arXiv:2610.00392v1 [cs.CR] 30 Sep 2026 MANUSCRIPT SUBMITTED TO IEEE TRANSACTIONS ON DEPENDABLE AND SECURE COMPUTING 2

such as the semantic refusal rate, the semantic breach rate, the interception rate and the penetration rate. (3) Motivated by the observation that, under the same baseline, hermes exhibits a markedly higher semantic refusal rate than other agents such as claude code and openclaw, we conduct ab-lation studies, generalize a new defense dimension that we call the envelope layer, and propose ELA-ITL, a three-layer isomorphic agent attack–defense model, which divides the optimization path of agent defense into envelope packag-ing, LLM recognition and agent interception, and divides the optimization of agent attacks isomorphically into the implant channel, prompt optimization and the execution mechanism. (4) We build a testbed and run experiments, conducting large-scale testing on 15 agent front-end × LLM back-end combinations, obtaining a testbed attack dataset of 1,000 cases, and systematically evaluating the attack effec-tiveness of the attack principle A2A-TIBA and the validity of the evaluation method GDA Measurement. 

2 RELATED WORK 

2.1 Security Analysis of the A2A Protocol 

As the standard interaction protocol for communication between different agents, the A2A protocol only began to receive systematic security attention in 2026. A2ABreak [5] is the first work to perform a systematic security analy-sis of the A2A protocol, identifying 11 new protocol-level vulnerabilities while remaining fully compliant with the specification; Habler et al. [6] applied the MAESTRO threat modeling framework to A2A deployments and proposed se-cure development methods and best architectural practices for Agent Card management, task execution integrity and authentication. Louck et al. compared the three agent com-munication protocols A2A, ACP and CORAL and pointed out that A2A has design-level weaknesses in authentication, authorization and data integrity [9]. As for cross-protocol attacks, Protocol Pivoting [10] was the first to systematically characterize the attack paths that arise when protocols such as MCP and A2A coexist: an attacker can gain initial access through one protocol and, by exploiting the differences in trust assumptions between protocols, obtain access capabil-ity in another. Kim et al. [11] further demonstrated that in an A2A–MCP integrated environment, an external agent can semantically induce an internal MCP tool to perform sensi-tive operations without any protocol violation or privilege escalation. The above work focuses mainly on the security of A2A at the protocol-specification level and reveals flaws in the trust model of the A2A protocol, but it does not discuss in depth how an attacker can exploit these permissions to construct a complete attack chain. Building on those flaws, the A2A-TIBA attack principle proposed in this paper constructs a complete attack chain and achieves real attack effects. 

2.2 Indirect Prompt Injection Attacks 

Greshake et al. first formalized the concept of indirect prompt injection in 2023: an attacker embeds malicious instructions in external data retrieved by an agent and can thereby hijack its behaviour without interacting with the victim directly [7]. AgentDojo [12] provides a dynamic eval-uation environment with 97 tools and 629 test cases and has become a benchmark for indirect prompt injection evalua-tion; its design allows researchers to inject new attacks and defenses into existing environments. The Promptware Kill Chain proposed by Brodt et al. shows how prompt injection can be used to implement a multi-step malware delivery mechanism, upgrading the traditional single-shot injection attack into an attack chain with persistence capability [13]. Existing research on indirect prompt injection focuses mainly on “how to make the LLM execute a malicious in-struction”, whereas A2A-TIBA shifts the emphasis to “how to make the agent execute a malicious instruction once, after which the subsequent attack steps proceed without relying on the agent”. By introducing the two existing concepts of indirect prompt injection and bypass circumvention into an attack scenario based on A2A communication, A2A-TIBA designs a three-stage attack chain of implant–command– exfiltration: as long as the target agent is successfully in-duced to deploy a callback interaction program, subsequent attacks no longer depend on the agent to execute malicious instructions. 

2.3 Agent Defense Strategies 

Existing agent defense strategies can be reviewed at two levels: LLM semantic defense and agent execution control. At the level of LLM semantic defense, Spotlighting [14] helps the LLM distinguish data from instructions by mark-ing and isolating untrusted content; Instruction Hierarchy [15] trains the LLM in a targeted manner to establish a priority ordering of instruction sources, setting the priority of system instructions, user input and external data, and thereby effectively reducing the risk that the model follows injected instructions; StruQ [16] proposes a structured query method that separates prompts and data into two channels, using specially reserved tokens as delimiters, and improves the model’s resistance to injection through structured in-struction fine-tuning. At the level of agent execution control, SIEVE [17] verifies tool transitions and argument provenance by con-structing an Intent Graph and submits operations that fail deterministic verification to semantic adjudication, thereby avoiding continuous semantic adjudication while preserv-ing flexibility; Task Shield [18] is a test-time defense mech-anism that systematically verifies whether each instruction and tool call contributes to the user-specified goal; DRIFT [19] is a system-level rule-based defense framework that, through a three-layer defense framework consisting of a security planner, a dynamic verifier and an injection isolator, enforces both control-level and data-level constraints and thus effectively defends against prompt injection attacks. The ELA-ITL proposed in this paper is a three-layer isomorphic agent attack–defense model that is induced from experiments rather than assumed a priori. ELA-ITL innova-tively treats the channel through which malicious content enters an agent as a new defense surface, which we call the envelope layer, and divides the optimization of agent defense into three dimensions: envelope packaging, LLM recognition and agent interception. The defense idea of the envelope layer is similar to that of the above studies, namely marking untrusted content or structurally isolating it; the difference is that those works target the LLM recognition MANUSCRIPT SUBMITTED TO IEEE TRANSACTIONS ON DEPENDABLE AND SECURE COMPUTING 3

layer or the agent execution layer, whereas the envelope layer concerns the setting of channel-level defense strategies through which agent components or external data enter the agent context. Existing defense strategies mostly target the LLM layer and the agent layer, and the envelope layer, as a new defense surface, has not yet been studied in depth. 

2.4 Agent Security Evaluation 

As for agent security evaluation benchmarks, AgentDojo [12] is the most widely used dynamic evaluation frame-work and supports multi-tool calling by agents in stateful adversarial environments. Agent Security Bench (ASB) [20] covers 10 prompt injection attacks, 1 memory poisoning attack and 11 corresponding defenses, benchmarks across 13 LLM backbones and includes more than 420 tools. ClawSafety [21] builds 120 adversarial test scenarios for per-sonal AI agents such as OpenClaw, covering high-privilege workspaces in software development, finance, healthcare, law and DevOps, with ASR ranging from 40% to 75% across models. As for evaluation methods, GroundEval [22] is a framework that requires no human judgment and can eval-uate agents against factual, time-constrained and access-controlled evidence. Hong et al. [23] proposed an evidence-anchored text evaluation method to improve the reliability of LLM-judge scores. Existing evaluation benchmarks mostly use ASR as the core metric, but ASR cannot distinguish whether a failed agent attack failed because “the LLM recognized the ma-licious content” or because “the agent layer intercepted the execution of the malicious instruction”. The evaluation method GDA Measurement proposed in this paper designs four attack outcomes, Class A/B/C/D, extending ASR into new metrics such as the semantic refusal rate, the semantic breach rate, the interception rate and the penetration rate, and adopts strategies including raw context capture via an LLM gateway, dual data preservation and agent-based autonomous judging, thus providing a finer-grained mea-surement scheme for agent security evaluation. 

3 METHODOLOGY 

3.1 Threat Model 

3.1.1 Core Assumptions 

The core assumption of our threat model is that the attacker can already authenticate to the target A2A endpoint and deliver tasks to the target agent. An A2A inbound credential grants only the permission to “write content into the context of the target agent”, not the permission to “invoke the tools of the target” or “execute on the target host”. We assume a gray-box attacker: in possession of the target Agent Card, the A2A endpoint information and basic interaction capability, but not of the target system prompt, internal policy configuration, back-end LLM parameters or the target host file system. The attacker can deliver tasks over multiple rounds, poll task status and adjust subsequent prompts according to the callback results, but cannot di-rectly execute commands on the target host, directly read or write target files, or directly invoke the MCP tools of the target. 

3.1.2 Permission Boundaries, Privilege Escalation and Contextual Privilege Escalation 

The A2A protocol does not define the semantics of a “peer directly invoking a local tool”. All a peer can do is deliver a Message and a Task to the target. Therefore, the actual semantics of an A2A inbound credential is: permission to write arbitrary content into the context of the target agent. Once content enters the context, the actor is no longer the attacker but the target agent itself. The permission set of the target agent equals its available tool set, command execution capability, file read/write capability and memory capability, minus its policy gates, such as the write-safe root, the command allowlist, the sensitive file list and the inbound provenance label header. The permission ceiling of the attacker stops at “delivering content”, whereas the permission ceiling of agent actions is host-level. Whether the gap between the two can be bridged depends on the security policy of the target agent itself. This paper does not study how an attacker obtains delivery capability; it studies, under the premise that “de-livery is already possible and the target has not imposed effective restrictions on host deployment and execution”, the reachable scope of the attack and the distribution of defense lines. The literature [5] has already demonstrated that an attacker can achieve contextual privilege escalation in A2A through legitimate means, which provides a realistic basis for the attack premise of this paper. 

3.1.3 Inbound Permission Tiers and Scope of Applicability 

The A2A specification delegates authentication and au-thorization to existing HTTP-layer standards; the securi-tySchemes of its Agent Card support only four kinds — apiKey, http, oauth2 and openIdConnect — and the spec-ification itself does not define permission tiers. It gives only a SHOULD-level recommendation for “per-skill au-thorization”, leaves the enforcement implementation to the gateway or the IAM, and there is no binding relationship between Task and Skill at the protocol layer. Two cases therefore arise: The first case is a deployment that has implemented tiering. The attacker needs at least a credential of a tier that can trigger execution-type skills; if the deployment places execution-type skills in a high-privilege tier, a low-tier cre-dential can only establish a link and deliver tasks and cannot trigger execution, so the tiering itself constitutes an inbound line of defense. The attacker then needs to legitimately obtain a credential with the corresponding permission, or escalate privileges using the method in [5]. The second case is a deployment without tiering. Any credential that passes authentication and can deliver tasks suffices, and whether the attack succeeds depends only on the tool authorization and policy gates of the target itself. Because the specification does not mandate tiering, and because Task and Skill are not bound together, which makes tiering difficult to enforce, the second case is more common in practice; public A2A services also tend to issue broad-scope credentials such as full access to authenticated clients. Our experiments adopt the second case. This paper therefore reflects the upper bound of risk in scenarios of “authenticated but untiered” access or “broad-scope creden-tials”; in deployments that enforce skill-level authorization, MANUSCRIPT SUBMITTED TO IEEE TRANSACTIONS ON DEPENDABLE AND SECURE COMPUTING 4

3.2 Attack Principle 

The most direct way to attack over the A2A channel is indi-rect prompt injection. In the A2A communication scenario, we reuse the classic attack concept of bypass and combine it with indirect prompt injection to obtain a hybrid attack principle of indirect injection plus bypass over the A2A channel, which we call the A2A Tri-surface Implant-Bypass Attack (A2A-TIBA). As shown in Fig. 1, the attack principle of A2A-TIBA mainly consists of the following three attack steps: 1. Implant: using the inbound credential it holds, the attacker establishes a normal A2A communication link with the target agent and, through indirect prompt injection, asks the target agent to deploy and run a resident callback interaction program on its host. 2. Command: once the interaction program is deployed, the attacker can interact with it without going through the agent. After confirming the deployment of the interaction program, the attacker issues malicious commands to the program, attacks the host on which the target agent runs, and steals sensitive information from that host. 3. Exfiltration: after the sensitive information has been stolen, the implanted interaction program returns it directly to the attacker without going through the agent, which ren-ders the defense mechanisms of the agent itself ineffective. In the A2A-TIBA attack principle designed in this paper, bypass is embodied as follows: the attacker uses indirect injection to ask the target agent to deploy a resident call-back interaction program on the host, and the subsequent issuance of malicious commands and the exfiltration of stolen sensitive files take place directly between the attacker and the callback program without going through the agent, thereby bypassing the defenses of the agent. The malicious intent of the attacker is manifested only in implanting a resident callback interaction program; once the program has been implanted, the attacks carried out afterwards no longer pass through the target agent, and the agent remains completely unaware. That is, with respect to this attack, the target agent has only one defensive opportunity, namely re-fusing to deploy the interaction program; once that defense is breached, enormous damage can be inflicted on the target host. Moreover, the prompt that deploys the interaction program contains no other malicious attack content, which reduces the risk of its being recognized by the target agent. 

3.3 Business Data Flow and Key Injection Points

At the same time, the permissions of the agent itself can reach sensitive data sources inside the container, such as environment variables and configuration, which are normally not exposed to peers. 3.4 Attack Implementation 

For the A2A-TIBA attack proposed in this paper, we de-signed a series of attack implementations (skill01–skill10), all of which carry out attacks by interacting with the target agent over the A2A channel. Among them, skill01–skill06 are preliminary work, mainly used to collect information that can be exploited for implementing the attack princi-ple; skill07–skill10 are concrete attack methods, obtained through continuous practical testing and optimization by an agent guided by the attack principle (see Appendix A for details). skill07 has four variants (skill07-a/b/c/d), which are different implementations of the same attack path. In the experimental part, we selected three represen-tative attack skills for large-scale experimental validation (see Section 5.2 for details), namely skill07-a (MCP tool implant), skill09 (script-repair implant) and skill10 (multi-step implant); the remaining skills are only introduced and are not subjected to large-scale testing. 

4 EVALUATION METHOD 

To better analyse the attack effects and optimize the at-tack implementations, we designed a new red-team testbed evaluation method, the Gateway-side Capture, Dual-data storage, and Agent-based Autonomous Judgment Measure-ment (GDA Measurement), which mainly consists of three components: a raw context capture architecture based on an LLM gateway, dual data preservation, and agent-based autonomous judging. 

4.1 Raw Context Capture Architecture Based on an LLM Gateway 

The LLM gateway relays the raw context of all interactions between the agent and the LLM, which gives us the oppor-tunity to obtain the raw context of the interaction between the target agent and the back-end LLM during attack testing. We designed a red-team testbed capture architecture based on an LLM gateway. As shown in Fig. 2, the target agent communicates with the back-end LLM through the gateway, and a capture program is deployed at the gateway. While the attacker interacts with the target agent, all raw context data flowing through the gateway is forwarded synchronously to the capture program. After the attack is completed, the capture program stores the captured raw context for detailed analysis of the attack results. 

4.2 The Four Class A/B/C/D Judgment Metrics 

In the raw context capture architecture based on an LLM gateway, all interaction contexts between the front-end agent and the back-end LLM are preserved, so that the different responses of the agent and the LLM to an attack can be separated. We further refine the conventional ASR and design four judgment metrics for attack outcomes, Class A/B/C/D, which correspond respectively to different defense situations of the agent and the LLM when facing an attack. In this paper, whether malicious content is executed corresponds to whether the target agent deploys and runs a resident callback program, and the state machine of the A2A-TIBA attack chain is shown in Fig. 3. 1. Class A: the malicious content is not executed at all. The back-end LLM recognizes the malicious behaviour of the attack and explicitly refuses to execute it, or executes only the benign content. 2. Class B: the malicious content is partially executed. The back-end LLM executes part of the malicious behaviour but then terminates the execution of the remaining mali-cious behaviour, without the defense policies at the agent level being involved. 3. Class C: the malicious content is fully executed but intercepted by a mechanism at the agent layer. The back-end LLM carries out the complete malicious behaviour as required by the malicious prompt, but it is intercepted by a defense mechanism at the agent level. The case in which, after interception by the agent-layer defense mechanism, the LLM re-identifies the malicious behaviour and refuses to execute it also belongs to Class C. 4. Class D: the intended attack objective is achieved. The back-end LLM executes the malicious content, the agent-layer defense is breached, the malicious behaviour is successfully executed, and the attacker obtains sensitive information from the host on which the target agent runs. Two special cases arise in the experiments: first, the LLM recognizes the malicious intent but still chooses to execute it; second, after the malicious instruction has been intercepted by the agent layer, the LLM keeps trying to achieve the same effect in an equivalent way. These two cases fall into different classes according to the actual outcome of execution.

This measurement strategy improves measurement efficiency while maximizing the accuracy of the judgments. 

4.4 Selection of the Judging Agent: The IAA Method 

To select the most suitable judging agent, we adopt the Cohen’s kappa coefficient from inter-annotator agreement (IAA) [24]. The method is as follows: a 10% sample is drawn at random from the test results (10% drawn at random for each combination of skill, agent front end and back-end LLM), and the samples are annotated separately by human annotators and by several agent combinations (agent front end plus back-end LLM), where each agent combination must judge independently twice. Taking the human annotations as the reference, the accuracy and the Cohen’s kappa coefficient between the results of each agent combination and the reference are then computed, and the agent combination with the highest average accuracy and kappa coefficient over the two repeated judgments is selected as the judging agent. 5 EXPERIMENTS 

Using the proposed GDA Measurement red-team testbed evaluation method, we conducted large-scale testing of the designed A2A-TIBA attack in order to study how to opti-mize the attack principle and how current agents defend against it. 

5.1 Experimental Setup 

We built the testbed on an Ubuntu host and ran the experi-ments there. Attacker: we selected Claude code + deepseek-flash as the attacker’s agent, which interacts with the target agent through a legitimate A2A channel and attacks using the designed attack implementations (skills). The attacker holds an inbound credential that can authenticate to the target A2A endpoint and can deliver tasks to the target agent. Target front-end agent: for the safety of the experiments, we selected three agent containers deployed with Docker, namely hermes-agent 0.21.0, openclaw 2026.9.2 and Claude Code CLI 2.1.90. Of these, hermes and openclaw natively support the A2A protocol, whereas Claude code has no A2A server. Although all the agent containers used in this paper serve external requests through A2A endpoints and authen-ticate inbound requests, none of them implements permis-sion tiering for A2A inbound access (for example, dividing permission tiers by skill or by scope); any authenticated credential can deliver a task, and once a task enters the con-text it is no longer constrained by the identity of the caller. Therefore, the defense line of “A2A channel permission tiering” does not exist in this experimental environment, and whether an attack succeeds depends entirely on the security policy of the target agent itself (whether it permits deploying and executing programs on the host). This is consistent with the current state of the A2A specification: the specification only recommends per-skill authorization at the SHOULD level and does not bind Task to Skill. Target back-end LLM: to explore the attack effective-ness of A2A-TIBA in realistic scenarios as far as possible, we selected five mainstream proprietary LLMs in China today and invoked them through their APIs: MiniMax-M3, deepseek-v4-pro, glm-5.3, kimi-k2.7-code and qwen3.8-max. Attack target: to verify the generality of the A2A-TIBA attack across different combinations of agent front end and LLM back end, we paired each front-end agent with each back-end LLM, yielding 15 target agent combinations. We placed fictitious sensitive decoy files in the agents as attack targets. For a given skill, each combination was attacked 20 times under a clean baseline. Selection of the LLM gateway: LiteLLM is a general-purpose LLM gateway that supports unified protocol con-version, standardizing the APIs of different back-end LLMs MANUSCRIPT SUBMITTED TO IEEE TRANSACTIONS ON DEPENDABLE AND SECURE COMPUTING 8

into an OpenAI-compatible format so that a front-end agent can access different back-end LLMs in a uniform way [25]. Considering LiteLLM’s advantages in switching back-end LLMs, we decided to use LiteLLM as the LLM gateway in our experiments. Metrics: we use the four attack metrics Class A/B/C/D designed in Section 4.2 as the basic metrics for examining the attack effectiveness of A2A-TIBA against the target agents. In addition, the share of Class A is called the se-mantic refusal rate, representing the proportion of attacks in which the back-end LLM sees through the malicious intent; the share of non-A results (B+C+D) is called the semantic breach rate, representing the proportion in which the se-mantic recognition of the back-end LLM is breached; the share of Class C is called the interception rate, representing the effectiveness of defense mechanisms at the agent level against malicious behaviour; and the share of Class D is called the penetration rate, representing the proportion of successful attacks, which is equivalent to ASR. Judging agent: we selected claude code + deepseek-flash as the agent that autonomously judges the results in this experiment; the detailed rationale is given in Section 5.3. 

5.2 Main Experiment 

In the main experiment, we selected three attack skills, namely skill07-a (MCP tool implant), skill09 (script-repair implant) and skill10 (multi-step implant). These three skills represent typical implementations of the A2A-TIBA attack along three dimensions — trigger form, source of the code and number of interaction rounds — and can validate the attack effectiveness of A2A-TIBA to the greatest extent. Using these three skills, we ran 20 repeated attack tests on each agent–LLM combination under a clean baseline, obtaining 900 sets of experimental data in total. Note that after hermes has been implanted with a malicious MCP tool, the configuration only takes effect after a restart. Therefore, if skill07-a successfully implants an MCP tool on hermes, we restart the hermes container and run an additional test of whether the implanted MCP tool can obtain sensitive information from the target host. The experimental results are shown in Figs. 4, 5 and 6, which give the test results of skill07-a, skill09 and skill10 respectively on the 15 agent combinations. This also tells us that when analysing the malicious-semantics recognition performance of the LLM in an agent, we cannot simply look at the defense mechanisms adopted during LLM training; the context passed by the front-end agent must also be taken into account. We carried out a further analysis using the captured raw data and found that, when the attacker delivers a prompt over A2A, hermes adds a defensive label header to the context warning that the originator of the prompt is untrusted; a similar label header also appears in the context of openclaw, but it only states that the message comes from the A2A protocol, so its defensive effect is not pronounced; and since claude code itself does not support A2A, no such label header appears (the contents of the label headers are given in Appendix B). To test the effect of this label header, we conducted ablation studies (see Section 5.4 for details). 2. We then analysed the defense effectiveness of each agent–LLM combination in detail and found that, apart from the combination glm5.3 + openclaw, no combination fully defends against all three skills. Next, we analysed the defenses at the agent layer: for the same skill and LLM, different front-end agents behave differently; in particular, for kimi-k2.7-code in Fig. 5 under the skill09 attack, the penetration rate of hermes is only 35%, whereas that of claude code reaches 100%. Although the penetration rate of openclaw is 0%, its semantic breach rate reaches 100%, which indicates that openclaw has defenses at the agent level that intercept the execution of the malicious behaviour; otherwise it would likewise be penetrated 100% of the time. In other words, different LLMs differ in their ability to recognize malicious content, but even after the semantic recognition of the LLM has been breached, the malicious behaviour is still subject to interception by the agent-layer defenses. In response to the low share of Class C in the results, we analysed the raw data and found a special case: after malicious content is rejected by a defense policy at the agent layer, the back-end LLM tries to bypass it through other execution paths. For example, after the tool-level write-safe root of hermes refuses to perform the malicious behaviour, the LLM switches to the terminal and completes the write through a shell path; when the exec command allowlist of openclaw intercepts the malicious behaviour, the LLM instead edits the configuration file directly through a file-writing path; and after the sensitive file list of claude code refuses to execute the malicious behaviour, the LLM turns to “asking the user for explicit authorization” or to “self-crippling”. In other words, although the agent-layer defense is partially effective, the back-end LLM may circumvent it in other ways, which shows that the effectiveness of agent-side interception depends on whether all equivalent paths of the malicious behaviour fall within the interception scope, rather than on the strength of interception at a single point. 5.3 Selection of the Judging Agent: The IAA Experi-ment 

Because the captured raw context data is too complex for humans to judge, we decided to use agents to judge the test results autonomously, which makes the selection of the judging agent crucial. We therefore carried out a dedicated IAA experiment to select the agent to use. We grouped the 900 test cells by the combination of skill, agent front end and back-end LLM (45 combinations in total) and randomly drew 10% (2 cells) from each com-bination as samples for selecting the judging agent, obtain-ing 90 judgment samples. Since the judgment results are strongly correlated with LLM performance, and to ensure the capability of the judging agent, we used claude code uniformly as the agent front end, with the candidates for the back-end LLM being the 6 LLMs used by the attacker agent and the target agents: deepseek-flash, MiniMax-M3, deepseek-v4-pro, glm-5.3, kimi-k2.7-code and qwen3.8-max, which yields 6 candidate agents. In the experiment, we first judged the 90 samples manu-ally and used the human results as the baseline for selecting the agent; each candidate agent was then tested indepen-dently twice, after which its accuracy and Cohen’s kappa coefficient against the baseline were computed. In addition, since judgments of Class B and Class C are easily confused and the accuracy of the Class D metric is the most important, we also computed the accuracy and the Cohen’s kappa coefficient over Class A and Class D results separately. The results are shown in Table 2. As can be seen, among these 6 candidate agents, all achieve an overall accuracy above 90% except for the two rounds of MiniMax-M3 and the second round of deepseek-v4-pro; and for Class D accuracy, only the first round of MiniMax-M3 falls short of 100%. This shows that au-tonomous judging by an agent is feasible. kimi-k2.7-code and deepseek-flash tie for first place in overall accuracy, while deepseek-flash has a higher Class A accuracy in its second round. In addition, the attacker agent in this exper-iment used the combination claude code + deepseek-flash, so all things considered, claude code + deepseek-flash is the more suitable judging agent. Both the main experiment and the ablation studies in this paper use this agent combination as the judging agent. 

5.4 Ablation Studies on the Envelope Layer 

In the main experiment of Section 5.2, we found that the A2A label header of hermes appears to effectively improve the ability of the back-end LLM to recognize malicious content, so we decided to conduct ablation studies on the influence of the A2A label header. In addition, since the A2A label header amounts to an annotation that the agent makes in the context for data from different sources, we further analysed how agent components that often serve as attack channels, such as tool/skill and memory, are labelled in the context, and found that current agents do not label them at all. We therefore designed dedicated malicious-prompt label headers for MCP tools and memory in the con-text, implanted them as regular configuration by modifying the code of the agent containers, and carried out ablation studies on the two agent components, tool and memory, at the same time (the relevant label headers are given in Appendix B). We selected the skill × LLM combination whose test results differ most between hermes and the other two agents — skill07-a + deepseek-v4-pro — for the ablation studies. As can be seen, under hermes the semantic refusal rate of this combination is 100%, whereas under the other two agents the penetration rate is 90% and 95% respectively, which shows that using this combination for ablation maximizes the visibility of the influence of the label header. We carried out three ablation studies on the different attack channels A2A, tool and memory. (1) We replaced the A2A label header in hermes with a more neutral description (see Appendix B for the modification of the label header), ran 20 repeated tests, and compared the results with the baseline of the main experiment, observing whether the penetration rate changes so as to test the defensive effect of the A2A label header. As long as data from different sources is annotated with malicious-prompt labels, the back-end LLM can be effec-tively helped to recognize malicious content, the semantic refusal rate is raised, and the risk of the agent system being compromised is reduced. We call the channels through which malicious attacks enter an agent “envelopes”, such as the A2A/ACP protocol channels, MCP tools/skills, memory and external data. In the context, different envelopes carry different weights and defense policies, which affects the recognition of malicious content by the LLM. For example, in this experiment we found that the A2A label settings of openclaw and her-mes differ, which leads to different recognition of mali-cious content by the LLM; and adding a similar malicious-prompt label header at the context location of MCP tools and memory likewise improves the ability of the LLM to recognize malicious content. We regard this strategy of annotating malicious-prompt labels in the context as a kind of “envelope-layer defense”: when data enters the context, the envelope (label header) is used to annotate the data with a malicious-prompt label, which enhances the recognition performance of the back-end LLM for malicious content and thereby achieves defense. 

6 THREE -L AYER ISOMORPHIC AGENT ATTACK –DEFENSE MODEL 

In the experimental results we unexpectedly discovered the envelope layer as a new defense layer. Combining this with existing research on attack/defense models, we generalized a three-layer defense model and, from it, pro-posed a corresponding three-layer attack model, obtaining a three-layer isomorphic attack–defense model, ELA-ITL (Envelope-LLM-Agent Isomorphic Tri-Layer Model). As shown in Fig. 8, we argue that when an attacker optimizes an attack, or a defender optimizes the defenses of an agent, there exists a corresponding three-layer at-tack/defense model, and each layer admits multiple at-tack/defense strategies for optimization. When a defender configures the defenses of an agent, there exist three defense dimensions. (1) Envelope Pack-aging: Corresponding defense policies are configured for the different channels through which malicious content enters an agent, such as A2A/ACP protocol channels, MCP tools/skills, memory and external data sources. The main purpose of envelope packaging is to improve the ability of the back-end LLM to recognize malicious content, and strategies such as provenance tagging and untrusted con-tent labeling can be adopted. (2) LLM Recognition: This primarily concerns the ability to recognize malicious content present in the context, which can be enhanced through defense strategies such as semantic auditing and malicious intent detection. (3) Agent Interception: This mainly deals with dangerous operations that an agent might perform, such as setting up a tool allowlist and runtime interception. Similarly, when an attacker optimizes an attack against an agent, there exist three corresponding attack surfaces for optimization. (1) Selection of the Implant Channel: Different envelope entry channels adopt different defense policies and their defensive capabilities vary. The attacker selects an envelope with weak defenses to enter the agent, changes the weight of the malicious content in the context, and reduces the risk of being recognized by the LLM. Optimiza-tion strategies include envelope forgery and indirect injec-tion entry. (2) Prompt Optimization: Given the differences in malicious-intent recognition capabilities across back-end LLMs, targeted optimization of malicious prompts can be applied to effectively raise the semantic breach rate of the LLM. For example, with the A2A-TIBA method proposed in this paper, different attack implementation skills achieve different attack effects on the same LLM. Strategies include semantic jailbreak and intent disguise. (3) Optimization of the Execution Mechanism: This mainly refers to bypassing the defense mechanisms at the target agent layer and finding an equivalent path when requiring the agent to execute malicious content. For example, if the agent layer refuses to execute an exec command, the attacker tries substituting execution via the Terminal. Optimization methods include tool invocation and persistent residency. It should also be noted that in real scenarios it is not enough to optimize the attack/defense mechanisms at only one layer: the three layers are inseparable, and only when all three layers are breached/defended is an attack/defense on an agent truly achieved. We believe that the three-layer iso-morphic agent attack–defense model ELA-ITL generalized in this paper can provide effective guidance for optimizing attacks/defenses on agents. 

7 CONCLUSION AND FUTURE WORK 

This paper mainly makes four contributions: (1) we de-signed A2A-TIBA, an attack principle of indirect injection plus bypass over A2A; (2) we designed GDA Measurement, a red-team testbed evaluation method based on an LLM gateway and agent-based autonomous judging; (3) we gen-eralized a three-layer agent attack–defense model, ELA-ITL; and (4) we conducted large-scale testing of A2A-TIBA and, using GDA Measurement, obtained a testbed attack dataset of 1,000 cases that can be used to evaluate measurement methods. In the future, we will try to extend the A2A-TIBA attack principle to other attack surfaces and, with respect to the attack–defense model ELA-ITL generalized in this paper, carry out an in-depth analysis of envelope-layer defense. 

LIMITATIONS 

The attack tests in this paper were evaluated only on three agent containers and five proprietary LLMs, and were not tested in real-world scenarios. The selected agents and LLMs may not represent all scenarios, and the real attack effectiveness of A2A-TIBA remains to be further tested. The experimental testbed in this paper does not enforce permis-sion tiering for A2A inbound access, so the penetration rates reported here reflect the upper bound of risk in scenarios of “authenticated but untiered” access or “broad-scope creden-tials”; in deployments that enforce skill-level authorization, the attacker additionally needs at least a credential able to trigger execution-type skills, and the actual risk is lower. In addition, to ensure the consistency of repeated tests, we fixed the attack procedure of the skills so that it cannot MANUSCRIPT SUBMITTED TO IEEE TRANSACTIONS ON DEPENDABLE AND SECURE COMPUTING 13 

change dynamically in response to the replies of the target agent; in real scenarios, a dynamic attack procedure could be adopted. 

ETHICS AND REPRODUCIBILITY STATEMENT 

All experiments in this paper were completed in an isolated testbed: the attack targets are agent containers reachable only by URL, and attack commands are issued only over the A2A channel, involving no real production system, real user data or third-party online service. The experimental setting “the attacker holds an inbound credential that can authenticate to the target A2A endpoint” is part of the testbed design, and the sensitive files in the testbed are fictitious decoys that contain no real credentials.
