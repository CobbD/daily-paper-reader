## 摘要
LLM 智能体在持久协作环境中运行，涉及多个用户、社区、记忆、文件和工具。社区边界可能保持固定，也可能随着成员、角色、组成和关系的变化而演变。智能体必须完成合法任务并防止受保护信息的未授权泄露。现有评估未能充分考察智能体系统中的这些风险。我们提出 CoSec，一个可执行的基准，用于评估在社区内部及跨社区运行的 LLM 智能体系统中的隐私与授权执行情况。CoSec 包含 208 个典型场景，涵盖固定与演变的边界、属于智能体所有者或其他参与者的受保护信息，以及通过对话、环境内容、持久记忆和组合工作流发起的攻击。CoSec 执行具有持久会话、记忆、文件和工具的完整智能体系统。它利用执行轨迹和工件，根据当前授权状态验证信息流。在各种执行框架和模型配置下，智能体经常完成良性任务，但会违反隐私和授权边界。隐私行为因执行框架、攻击面和社区状态而异，揭示了记忆、文件、工具和工作流如何将受保护信息携带到其授权范围之外。这些发现表明，任务效用并不代表隐私或授权合规性，社区环境中的授权对于持久 LLM 智能体而言仍是一项尚未解决的安全挑战。

## Abstract
LLM agents operate in persistent collaborative environments involving multiple users, communities, memories, files, and tools. Community boundaries may remain fixed or evolve with changes in membership, roles, composition, and relationships. Agents must complete legitimate tasks and prevent unauthorized disclosure of protected information. Existing evaluations do not fully examine these risks in agent systems. We introduce \textbf{CoSec}, an executable benchmark for evaluating privacy and authorization enforcement in LLM agent systems operating within and across communities. CoSec contains 208 canonical scenarios spanning fixed and evolving boundaries, protected information belonging to the agent owner or other participants, and attacks through dialogue, environmental content, persistent memory, and composed workflows. CoSec executes complete agent systems with persistent sessions, memory, files and tools. It verifies information flows against the active authorization state using execution traces and artifacts. Across harness and model configurations, agents frequently complete benign tasks but violate privacy and authorization boundaries. Privacy behavior varies across harnesses, attack surfaces, and community states, revealing how memory, files, tools, and workflows can carry protected information beyond its authorized scope. These findings show that task utility does not imply privacy or authorization compliance and that authorization in community settings remains an unresolved security challenge for persistent LLM agents.

## 2. 论文提出的方法论

- **核心思想**  
  - 构建 **CoSec**：一个可执行、面向社区场景的隐私与授权执行基准。  
  - 不评估单一模型，而是**执行完整智能体系统**（包括原生会话、记忆、文件操作、工具调用、工作区效果），用执行轨迹和最终工件来验证信息流是否越过授权边界。  

- **社区安全模型与授权公式**  
  - 将协作状态表示为：  
    \[
    E_t = (U, C, G_t, M_t, R_t, D, P_t, A, H_t)
    \]  
    其中 \(U\) 为用户，\(C\) 为社区，\(G_t\) 为社区关系，\(M_t\) 为成员关系，\(R_t\) 为角色，\(D\) 为数据对象，\(P_t\) 为当前策略，\(A\) 为智能体接口，\(H_t\) 为可见历史。  
  - 每个受保护对象 \(d\) 都有所有者 \(o(d)\)、来源社区 \(c(d)\) 和敏感标签。  
  - 授权 oracle（对智能体隐藏）判断：  
    \[
    Auth_t(u,a,d,\ell) = 1[P_t(u,a,d,\ell,G_t,M_t,R_t,o(d),c(d)) = \text{allow}]
    \]  
  - 重点：**信息的技术可达性不等于授权使用**；社区合并等扩张事件并不会自动解密历史私有信息。  

- **攻击面设计（A1–A4）**  
  - **A1 用户注入**：通过请求消息直接施压，如伪造授权、冒充身份、紧急催促、安全摘要陷阱等。  
  - **A2 间接注入**：在文档、工具输出、引用消息、元数据中嵌入恶意指令，测试检索内容是否被误认为授权控制。  
  - **A3 记忆投毒**：在持久记忆中植入虚假、过期或过宽的授权声明，测试记忆状态是否覆盖当前边界。  
  - **A4 能力组合**：将多个看似合理的文件/工具/工作流操作组合成未授权信息流，例如索引后提取、模板槽填充、摘要细化、来源洗白、收件人扩展、跨工件拼接、多请求者共识。  

- **场景套件**  
  - 共 **208 个规范场景**：  
    - **Static112**：固定社区边界，交叉 2 种边界范围（同社区/跨社区）× 2 种隐私目标（所有者/第三方）× 4 种攻击家族 × 7 种策略变体。  
    - **Dyn96**：在评分动作前插入一次社区事件（成员加入/移除、角色升级/降级、社区合并/拆分、关系开始/结束），每个事件方向 8–16 个场景。  
  - 场景以可执行 JSON 形式发布，包含时间线、文件、说话者、事件、攻击类型和仅给评估者的 oracle 标签。  

- **评估指标**  
  - **PVR（隐私违反率）**：受保护内容通过智能体生成的输出被泄露的比例。  
  - **CCPVR（跨社区隐私违反率）**：在跨授权范围的子集中，受保护信息流向未授权目标社区的比例。

  - **STCR（安全任务完成率）**：完成良性任务且无任何已验证安全失败的比例。  

- **验证机制**  
  - 记录完整轨迹、会话、工具事件、文件和内存变更。  
  - **确定性提取器**：检测受保护内容的直接输出、跨社区传播、未授权工具/状态动作；排除初始文件、攻击者输入、内部读取等。

## 6. 论文的主要结论与发现

- **任务效用与安全脱节**  
  - 13 种配置中 12 种 BCR 超过 85%，但 PVR 从 29.33%（OpenClaw + Gemini 3.1 Pro）到 96.15%（Hermes + DeepSeek 4.1 Flash）不等。  
  - 完成良性任务并不能保证隐私或授权合规。  

- **系统级差异显著**  
  - 相同骨干模型在不同 harness 下 PVR 差异很大：  
    - Gemini 3.5 Flash：OpenClaw 52.88% vs Hermes 76.92%（差 24.04 个百分点）。  
    - GPT 5.6 Sol：Hermes 55.29% vs Codex 41.35%。  
  - 说明隐私取决于完整 agent 系统如何管理上下文、记忆、工具和输出，而非仅骨干模型。  

- **攻击面风险排名**  
  - 总体看，**能力组合（A4）风险最高**，合并后 PVR 达 70.27%。  
  - 不同配置对攻击家族的敏感性不同（如 Hermes+GPT 5.6 Sol 对间接注入仅 9.62%，但对能力组合高达 84.62%）。  

- **动态事件挑战**  
  - 社区合并（merge）是最具挑战性的动态事件，总体 PVR 72.12%；关系结束 69.23%；成员移除最低 47.12%。  
  - 静态与动态表现没有统一排序，部分配置动态更差，部分更好，说明不能仅凭静态表现或骨干能力推断动态行为。  

- **四类授权失败模式**  
  - **工作流延续（workflow carryover）** 最常见，占 29.9%：旧记忆、任务或事务在边界变化后继续执行。  
  - **过度授权（excess permission）** 25.5%：将扩张事件视为全盘访问许可。  
  - **来源混淆（provenance confusion）** 25.2%：相信来自熟悉来源但实际受限的内容。  
  - **撤销失败（failed revocation）** 19.4%：边界收缩后仍保留旧权限。  

- **Guardrail 效果有限且不均**  
  - 同一安全护栏使 OpenClaw+DeepSeek PVR 下降 24.04 个百分点，但对 Hermes+DeepSeek 几乎无效（96.15% → 96.15%）。  
  - 提示级提醒无法替代在写入、共享或传递前执行授权检查。  

## 7. 优点

- **系统级可执行评估**  
  - 直接运行原生智能体系统（OpenClaw、Hermes、Codex），保留真实会话、记忆、文件和工具行为，比纯提示或模型层评估更贴近实际部署。  

- **覆盖多参与者、跨社区、动态边界**  
  - 明确建模所有权、来源、目标受众和社区范围，填补了单用户/单任务安全基准的空白。  

- **攻击面设计全面**  
  - 覆盖直接请求、不可信工件、持久状态和多步组合，控制了不同攻击机制而不改变隐私核心问题。  

- **验证可靠性与可复现性**  
  - 确定性证据 + LLM 裁判 + 人工审计（综合准确率 96.9%、召回 100%）降低误判风险。  
  - 发布代码、场景清单、轨迹和评分卡，支持复现。  

- **分析深入**  
  - 不仅给出总体指标，还分解到攻击家族、动态事件、证据表面和失败模式，提供可操作的诊断信息。  

## 8. 不足与局限

- **合成场景与有限领域**  
  - 场景为人工模板、合成数据，只覆盖金融、健康和凭证等少量领域，可能无法反映真实社区的全部复杂性。  
  - 交互长度固定为 8 轮，社区规模和关系类型有限。  

- **样本量与重复性**  
  - 每个配置每个场景通常仅运行一次，未做多次随机重复，统计稳定性可能不足。  
  - 部分试验因基础设施问题未计入指标，可能存在非随机缺失。  

- **配置覆盖有限**  
  - 只测试了 3 个 harness 和 6 个模型家族，结论是否适用于其他 agent 框架/模型仍有待验证。  
  - 动态事件类型虽覆盖 8 种，但每类场景数量较少（如社区事件仅 16 个）。  

- **评估本身的潜在偏差**  
  - LLM 裁判可能引入模型相关偏差（虽然有人工审计，但审计样本只覆盖 192 个试验）。  
  - 参与者消息为固定种子，可能限制攻击的自然多样性；虽然提到可选攻击者模拟，但主评估未使用。  

- **防御评估浅尝辄止**  
  - 只测试了首轮一次性安全提示作为防御，未评估运行时授权执行机制、动态策略检查或隔离技术。  
  - 未深入讨论如何实际修复这些失败模式。  

- **安全模型简化**  
  - 授权 oracle 为确定性规则，可能未涵盖真实世界中模糊、冲突或上下文相关的权限协商。
