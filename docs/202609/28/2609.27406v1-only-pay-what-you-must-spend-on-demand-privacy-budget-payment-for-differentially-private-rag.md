## 摘要
通过检索增强生成（RAG）在敏感数据上部署大语言模型（LLM）会带来严重的隐私风险。近期研究将差分隐私（DP）应用于结合了RAG的LLM，以提供形式化的隐私保障。然而，现有的DP-RAG框架会迅速耗尽隐私预算。尽管近期工作试图通过缩小检索范围或稀疏化私有生成来节省预算，但这些方法本身会累积消耗预算，而它们实际上可以仅依赖公开信息或以可忽略的一次性隐私成本完成。这种不匹配导致预算支出与模型对私有数据的实际依赖不相符，从而在无需访问私有数据的操作上造成大量浪费。为解决此问题，我们提出SparsePay-RAG，其核心原则是“仅为必须之开销买单”。它利用公开信息作为零隐私先验，仅对私有增量部分收取隐私预算。具体而言，SparsePay-RAG通过基于公开主题的聚类来缩小检索范围，通过保序跨层轨迹拟合在不消耗隐私成本的情况下自适应控制私有访问频率，并通过DP对比解码压缩每次访问的预算。实验表明，在严格的隐私约束下，SparsePay-RAG相比基线方法实现了更优的隐私-效用权衡。

## Abstract
Deploying large language models (LLMs) on sensitive data via Retrieval-Augmented Generation (RAG) introduces severe privacy risks. Recent studies apply Differential Privacy (DP) to LLMs with RAG for formal privacy guarantees. However, existing DP-RAG frameworks rapidly exhaust the privacy budget. Although recent efforts attempt to save the budget by narrowing the retrieval scope or sparsifying private generation, these methods themselves cumulatively consume the budget, whereas they could actually rely merely on public information or at a negligible one-time privacy cost. This mismatch fails to align budget expenditure with the model's actual reliance on private data, causing substantial waste on operations that require no private access. To address this, we propose SparsePay-RAG, adopting "only pay what you must spend" as its core principle. Using public information as a zero-privacy prior, it charges the privacy budget only for the private increment. Specifically, SparsePay-RAG narrows the retrieval scope via public topic-guided clustering, adaptively controls private access frequency without privacy cost through isotonic cross-layer trajectory fitting, and compresses per-access budget via DP contrastive decoding. Under strong privacy constraints, experiments show SparsePay-RAG achieves superior privacy-utility trade-offs over baselines.

## 2. 论文提出的方法论

SparsePay-RAG 从三个正交维度压缩隐私成本：**私有检索范围**、**私有访问频率**、**单次访问隐私成本**。

### 2.1 基于公开主题引导聚类的局部私有检索（缩小检索范围）

- **离线阶段**：
  - 使用公开 LLM（如 GPT-4）根据目标领域描述生成 \(m\) 个公开主题 \(T = \{t_1, \dots, t_m\}\)。
  - 用本地嵌入模型 \(E(\cdot)\) 将主题和私有样本编码为向量，按余弦相似度将每个私有样本分配到最相似的主题簇，得到不相交簇 \(\{C_j\}\)。
  - 对每个簇大小 \(c_j\) 添加高斯噪声 \(\mathcal{N}(0, \sigma^2)\) 得到噪声大小 \(\tilde{c}_j\)，这是唯一离线发布的私有统计量。
- **在线两阶段检索**：
  - 将查询 \(q\) 编码后与公开主题比较相似度，按相似度排序得到索引顺序 \(\pi\)。
  - 按顺序累计已发布簇大小 \(\tilde{c}_{\pi(k)}\)，直到达到预设粗候选集大小 \(N_{\text{coarse}}\)，形成粗候选集 \(C_{\text{cand}}\)。
  - 在 \(C_{\text{cand}}\) 内计算查询与私有样本相似度，返回 top-\(K\) 样本作为最终检索结果 \(R_{\text{final}}\)。
- **隐私保护机制**：
  - 每个簇设置最大允许访问次数 \(N_{\max}\)，达到后跳过该簇，保证最坏情况隐私上限。
  - 利用 zCDP 的并行组合性质，不相交簇之间隐私成本不累积，总成本由任意单簇的最大访问频率决定，而非总查询数。

### 2.2 基于保序跨层轨迹拟合的自适应 RAG 触发（降低访问频率）

- **目标**：仅在公开模型自身知识不足时才访问私有数据，避免每个解码步都触发私有检索。
- **候选 token 过滤**：在生成步 \(t\)，取公开模型最后一层概率分布 \(p^{(L)}\)，通过动态阈值 \(\alpha\) 截断出高概率候选集 \(V_{\text{head}}\)。
- **跨层轨迹构建**：使用 logit lens，对每一层隐藏状态 \(h^{(l)}\) 施加最终层归一化并投影到词表，得到候选 token 在各层的概率 \(p^{(l)}(x)\)，堆叠得到轨迹 \(p(x) = (p^{(l_s)}(x), \dots, p^{(L)}(x))\)。
- **保序回归拟合**：用保序回归（Isotonic Regression）拟合单调不减序列 \(\hat{\mu}(x)\)，作为“理想自信轨迹”的估计，最小化平方误差。
- **置信度评分**：定义置信分数 \(S(x) = \hat{\mu}_L(x) - \sqrt{\frac{1}{L_w}\sum_{l=l_s}^{L}(p^{(l)}(x) - \hat{\mu}_l(x))^2}\)，第一项反映最终层绝对置信度，第二项为残差反映层间稳定性。
- **自适应触发**：令 \(x^* = \arg\max_{x \in V_{\text{head}}} S(x)\)。若 \(S(x^*) > \theta_{\text{reject}}\)，直接输出 \(x^*\)，不访问私有数据；否则触发私有生成。
- **隐私成本**：该模块完全基于公开模型内部表示，不访问任何私有数据，因此隐私成本为零。

### 2.3 DP 对比解码私有增量预算压缩（降低单次访问成本）

- **动机**：私有 logits 中包含公开模型已内化的非私有知识，对完整 logits 加 DP 噪声会浪费预算。
- **私有 logits 计算**：对检索到的每个私有样本 \(d_i\) 构建个体私有提示 \(P_i\)，分别计算私有最终层 logits \(\ell^{(i)}_{\text{priv}}\)，同时复用公开 logits \(\ell_{\text{pub}}\)。
- **对比增量提取**：计算私有分布与公开分布的对数概率差 \(\ell^{(i)}_{\Delta} = \log p^{(i)}_{\text{priv}} - \log p_{\text{pub}}\)。
- **裁剪与聚合**：对每个增量逐元素裁剪到 \([-C, C]\)，对 \(K\) 个私有样本取平均，再加回公开对数概率，得到效用向量 \(u = \log p_{\text{pub}} + \frac{1}{K}\sum_{i=1}^{K}\text{clip}_C(\ell^{(i)}_{\Delta})\)。
- **DP 采样**：限制在候选集 \(V_{\text{head}}\) 内按 \(\text{softmax}(u/\tau)\) 采样，等价于指数机制，每步满足 \(\rho_{\text{token}}\)-zCDP。
- **隐私组合**：采用 zCDP 顺序组合累积 \(\rho = \sum_t \rho^{(t)}_{\text{token}}\)。若超过每查询预算 \(\rho_{\text{query}}\)，则回退到公开候选 \(x^*\)。

### 2.4 总体隐私分析

- 簇大小发布：高斯机制 \(\ell_2\) 敏感度 \(\Delta_2 = 1\)，隐私成本 \(\rho_{\text{cls}} = 1/(2\sigma^2)\)。
- 自适应触发：隐私成本为 0。
- DP 对比解码：指数机制 \(\ell_\infty\) 敏感度 \(\Delta_u = 2C/K\)，温度 \(\tau\)，每步成本 \(\rho_{\text{token}} = 2C^2/(K^2\tau^2)\)。
- 总成本：
  \[
  \rho_{\text{total}} = \frac{1}{2\sigma^2} + N_{\max} \cdot T_{\text{priv}} \cdot \frac{2C^2}{K^2\tau^2}
  \]
- 转换为 \((\varepsilon, \delta)\)-DP：
  \[
  \varepsilon = \rho_{\text{total}} + 2\sqrt{\rho_{\text{total}}\ln(1/\delta)}
  \]

- **显著性检验**：paired t-test 显示 SparsePay-RAG 相对于 MuRAG 的性能提升具有统计显著性（p < 0.05）。
- **Fallback增强对比**：即使为基线方法增加预算耗尽后的回退机制，SparsePay-RAG仍保持明显优势，说明其优势不仅来自避免失败，更源于根本性的预算效率提升。

## 7.论文的贡献与局限性

###7.1主要贡献
- **原则性框架**：提出“只为必须之开销买单”的隐私预算分配原则，系统性地识别并消除了现有DP-RAG中不必要的隐私成本。
- **三维度压缩机制**：
  1.**主题引导聚类**实现局部私有检索，利用不相交簇的并行组合性质将隐私成本从总查询数解耦为单簇最大访问频率。
  2.**自适应触发机制**基于公开模型内部表示零成本判断是否需要私有数据，大幅降低私有访问频率。
  3.**DP对比解码**仅对私有增量加噪而非完整logits，压缩单次访问的敏感度。
- **严格隐私分析**：提供完整的zCDP到(ε,δ)-DP转换分析,覆盖所有模块的组合隐私成本。
- **全面实验验证**：跨多个数据集、模型规模和隐私预算的一致优越性,并通过消融、攻击评估和显著性检验支撑结论。

###7.2局限性
- **公开信息依赖假设较强**:方法有效性依赖于公开LLM和主题生成的质量,若公开模型对目标领域知识极度匮乏(如高度专业或新兴领域),自适应触发可能频繁激活私有检索,削弱预算节省效果；主题生成若质量不佳可能导致簇划分不合理,影响检索精度。论文未充分探讨这一假设失效时的性能退化程度。
- **离线阶段的可扩展性**:虽然在线检索加速明显,但离线阶段需为全量私有数据生成嵌入并聚类,当数据规模极大(如数十亿级)时计算和存储开销可能成为瓶颈。论文未讨论增量更新场景下重聚类的成本。
- **攻击评估范围有限**:仅测试了一种成员推理攻击(Interrogation Attack),未涵盖属性推理、训练数据提取等更广泛的隐私威胁模型。此外,AUC降至0.511虽接近随机,但未达到理论最优(0.5),残留微小信息泄露的来源未深入分析。
- **超参数敏感性**:拒绝阈值θ_reject通过EER自动校准虽避免了手动调参,但EER本身依赖一个小的校准集来平衡误拒和误接受率。论文未讨论该校准集是否需要来自私有数据分布以及是否消耗额外隐私预算。最大访问次数N_max的选择也缺乏理论指导或敏感性分析。
- **动态语料库支持不足**:虽然方法比DP微调更易更新(无需重新训练),但添加新文档仍需重新嵌入并可能触发重聚类以维持不相交性质。论文声称支持动态更新但未提供具体方案或实验验证。

##8.总结与展望

SparsePay-RAG通过精细化的隐私会计和零成本的公开先验利用,在差分隐私约束下显著提升了RAG系统的效用边界。其核心洞察——区分操作是否真正需要访问私有数据并仅为必要部分支付隐私成本——具有普适性意义,可启发未来工作将类似思想应用于其他私密增强生成范式(如工具调用、代码执行等)。未来方向包括:(1)探索更鲁棒的公开先验构造方法以降低对外部LLM质量的依赖；(2)研究流式或增量聚类算法以支持大规模动态语料库；(3)扩展至多模态RAG场景；(4)结合更先进的DP组合理论进一步压缩总预算；(5)在更广泛的攻击模型下评估实证隐私保护强度。
