## 摘要
大型语言模型的安全、安保与隐私评估严重依赖静态基准，这些基准存在分数饱和、数据污染和聚合伪影等问题，且无法捕捉对语言变化的敏感性。因此，在固定测试集上表现良好的模型，在面对语义等价的改写时往往失效。我们提出 SSP-Bench，一个动态基准框架，可按需生成评估实例并保持领域一致性。该框架通过外部有据可依的来源确保标签有效性，借助特定服务验证来限定范围，并利用多模型指导小组校准难度。基准构建被形式化为一个关于难度、可分性、新颖性和多样性的多目标优化问题。在 24 个模型和四项 SSP 服务上，SSP-Bench 揭示了静态评估的系统性缺陷，包括因构念混杂导致的安全排名近乎零相关、强烈的安全-过度拒答耦合以及隐藏的族内回归现象。这些结果表明静态基准可能歪曲模型行为，从而推动了动态的、与部署相关的评估。

## Abstract
Evaluation of large language models (LLMs) for safety, security, and privacy (SSP) relies heavily on static benchmarks, which suffer from score saturation, data contamination, and aggregation artifacts, and fail to capture sensitivity to linguistic variation. As a result, models that perform well on fixed test sets often fail under semantically equivalent rephrasings. We introduce SSP-Bench, a dynamic benchmarking framework that generates evaluation instances on demand while preserving domain consistency. The framework ensures label validity through externally grounded sources, enforces scope via service-specific validation, and calibrates difficulty using a multi-model steering panel. Benchmark construction is formulated as a multi-objective optimization problem over difficulty, separability, novelty, and diversity. Across 24 models and four SSP services, SSP-Bench reveals systematic failures of static evaluation, including near-zero correlation in safety rankings due to construct mixing, strong safety--over-refusal coupling, and hidden within-family regressions. These results show that static benchmarks can misrepresent model behavior, motivating dynamic, deployment-relevant evaluation.

- **研究背景**：大语言模型（LLM）的安全（Safety）、安保（Security）与隐私（Privacy，合称 SSP）评估高度依赖静态基准（static benchmarks），即固定、公开、重复使用的提示集。

  - **数据污染**：基准条目公开且不可变，模型可能在预训练中见过这些内容，导致分数虚高。
  - **聚合伪影**：把异质评估任务平均成单一分数，掩盖不同子能力之间的差异。
- **SSP 的特殊脆弱性**：安全对齐、过度拒答、幻觉、隐私等行为对措辞、语境高度敏感；语义等价改写可能显著改变模型反应，而数学等能力任务对措辞不敏感。
- **整体含义**：论文提出动态评估范式——在同一评估领域按需生成新实例，检验静态排名是否可推广到未见输入；并揭示静态基准会系统性歪曲模型行为，应转向动态、面向部署的评估。

## 2. 论文提出的方法论

- **核心思想**：两阶段流水线，将基准构建形式化为多目标优化问题。
  - **阶段 1：候选生成**：反复生成以外部特权信源（privileged source）为根据的候选条目，通过验证门筛选。
  - **阶段 2：基准组装**：从候选池中按难度、可分性、新颖性、多样性多目标选择最终基准。

- **服务与特权信源**：
  - 幻觉（hallucination）：以 Wikipedia 为信源，生成可验证的事实问答。
  - 安全（safety）：以 AIAAIC 真实 AI 事故数据集和红队语料为信源，生成新的对抗性有害提示。
  - 过度拒答（over-refusal）：以 Wikipedia 中安全边界附近的良性内容为信源，生成易被误拒的良性问题。
  - 隐私（privacy）：使用 SPY 数据集中的 PII 标注文档 + Faker 生成合成 PII，按六种攻击模板（如 paraphrase leak、context extraction、database agent）进行确定性模板填充。

- **生成过程细节**：
  - 每轮迭代包含：类别选择、上下文构建、接地生成。
  - 候选需通过三个验证门：范围谓词（scope predicate）、标签验证器（label verifier）、质量阈值（LLM judge）。
  - **多模型指导面板（steering panel）**：由轻量开放模型（Gemma、Llama、Qwen 家族）组成，用于反馈难度与可分性，指导后续迭代；该面板与最终评估面板分离，不参与排名评分。

- **评估函数与项目指标**：
  - 模型在项目 \(x\) 上的结果由 \(Eval_k(m,x)\in\{0,1\}\) 给出；性能为平均分：
    \[
    s(m;D_k)=\frac{1}{|D_k|}\sum_{x\in D_k} Eval_k(m,x)
    \]
  - **难度（difficulty）**：项目上失败模型的占比 \(f_{diff}=1-\text{mean success}\)。
  - **可分性（separability）**：二元结果的伯努利方差 \(f_{sep}=p_c(1-p_c)\)，其中 \(p_c\) 为项目成功率；在 \(p_c=0.5\) 时最大，所有模型一致时为零。

- **多目标选择**：
  - 目标函数 \(J_k(D;M)=\sum_j \lambda_j f_j(D,M)\)，包含难度、可分性、多样性（最小成对嵌入距离）、新颖性（到静态基准的最小嵌入距离）。
  - 可分性权重最高（\(\lambda_{sep}=5.0\)）；采用贪心选择，并去除近重复（余弦相似度 > 0.95）。

- **基准质量度量**：
  - **稳定性 Stab**：\((1+\tau(R(D^{(t)}),R(D^{(t')}))) / 2\)，其中 \(\tau\) 为 Kendall 秩相关，衡量独立运行生成排名的一致性。
  - **区分度 Disc**：模型对得分差超过阈值 \(\epsilon\) 的比例。
  - **综合质量 Q**：\(Q = 2 \cdot \text{Stab} \cdot \text{Disc} / (\text{Stab}+\text{Disc})\)，用调和平均而非算术平均，强调两者不可替代。

## 6. 论文的主要结论与发现

- **安全排名的构念混杂**：
  - 静态安全服务聚合分为两类：7 个对抗拒答测试 + 2 个内容审核测试。
  - 服务整体与动态安全排名近零相关（Kendall \(\tau = -0.016\)，95% CI 包含 0）。
  - 仅拒答子集恢复强正相关（\(\tau = 0.670\)）；内容审核子集负相关。
  - 在 HELM Safety 上复现同样现象，说明这不是 aiXamine 独有，而是静态安全聚合的普遍问题。

- **模型家族内逆规模（Gemma-3）**：
  - 动态安全率从 1B 的 93.8% 降至 27B 的 85.5%（差距 8.3%），而静态排行榜仅显示 1.1% 差距。
  - 机制：大模型出现“先免责声明后完整输出有害内容”的模式。

- **幻觉存在知识平台**：排除最小模型后，其余模型压缩在 85.6%–92.9% 的 7% 窗口；数值/统计类答案失败率（31.7%）远高于年份/历史时期类（<9%），数值精度是主要判别因素。

- **过度拒答与安全耦合**：动态安全分数与动态过度拒答率强相关（Spearman \(\rho = 0.836\)），模型无法一致区分有害意图与安全边界附近的良性请求。

- **隐私安全对齐不传递**：所有模型安全率不超过 53.9%；paraphrase leak 平均泄露 93.9%，而 database agent 仅 14.9%；同一模型在不同攻击模式下表现差异巨大，单一总分掩盖具体脆弱点。

## 7. 优点

- **动态生成与外部接地标签**：避免自我增强偏差；标签来自 Wikipedia、AIAAIC、SPY 等外部信源，可独立验证。
- **多目标形式化**：借鉴心理测量学 IRT/ATA，用难度、可分性、新颖性、多样性进行项目级选择，比主题级方法更细粒度。
- **多模型指导面板设计**：使用跨家族轻量模型

- **多模型指导面板设计**：使用跨家族轻量模型提供难度反馈，与最终评估面板完全隔离，避免评估偏差。
- **构念分解与鲁棒性验证**：不仅报告总分，还深入拆解安全、幻觉等服务的内部构念，并通过跨基准复现、生成模式拆分、消融实验等多角度验证结论的稳健性。
- **统计严谨性**：广泛使用 Kendall τ、Spearman ρ 及其置信区间和 p 值，量化排名相关性与不确定性；引入稳定性、区分度及综合质量 Q 等基准质量度量。
- **面向部署的评估范式**：强调动态、按需生成的评估更能反映模型在真实世界中面对未见输入的泛化能力，对安全关键应用具有重要指导意义。

## 8. 不足与潜在局限

- **计算成本高昂**：动态生成和评估需要大量 API 调用和 GPU 资源（四个 H200 节点），可能限制其在资源受限环境中的可复现性和广泛采用。
- **外部信源依赖与覆盖范围**：幻觉和安全服务分别依赖 Wikipedia 和 AIAAIC/红队语料，信源的覆盖范围、时效性和潜在偏差可能影响生成项目的全面性；隐私服务仅覆盖六种攻击模板，未穷尽所有隐私威胁模式。
- **用户研究规模有限**：安全与过度拒答的人工标注各仅 200 条样本，虽一致性高（93.5%–99.0%），但样本量较小可能不足以捕捉长尾或边缘案例。
- **指导面板鲁棒性验证单一**：仅测试了一种“更强前沿模型”替代方案，未探索更多样化的指导面板配置（如不同家族组合、更大规模模型）对生成质量和最终排名的影响。
- **动态基准的长期稳定性未充分探讨**：虽然报告了独立运行间的稳定性 Stab，但未系统研究随时间推移（如数月后）或随模型能力演进时动态基准排名的漂移特性。
- **开放权重模型的版本锁定问题**：尽管记录了专有 API 模型的标识符和时间戳，但开放权重模型的微调版本或社区变体可能难以精确复现。

## 9. 可能的拓展方向

- **自适应难度调整机制**：根据当前模型面板的整体能力水平动态调整项目难度目标函数中的参数 λ_diff，使基准能持续有效区分不同代际的模型。
- **多语言与跨文化扩展**：将动态生成流水线应用于非英语语言和文化特定语境下的 SSP 评估，检验当前发现（如安全构念混杂）的跨语言普适性。
- **持续更新的“活基准”平台**：构建一个公开的、定期自动刷新的动态排行榜系统，允许社区提交新信源或攻击模板以扩展覆盖范围。
- **更细粒度的隐私威胁建模**：增加更多攻击模式（如成员推理攻击、训练数据提取等），并引入差分隐私保证下的理论泄露上界作为参照系。
- **人机协作的质量控制环**：将用户研究扩展为持续的众包反馈机制，用于校准 LLM judge 的质量阈值和标签验证器，形成半自动化的基准维护流程。

## 10. Gaps & Next Steps

### Gaps
1.  论文揭示了静态安全聚合导致的构念混杂问题（对抗拒答 vs.内容审核），但未深入探究为何这两类任务在模型中呈现负相关趋势的内在机制——是训练数据分布差异还是对齐技术的副作用？
2.  对于 Gemma-3 家族观察到的逆规模现象（大模型更不安全），论文描述了“先免责声明后输出”的行为模式，但未通过机械论可解释性方法分析该行为产生的内部表征原因。
3.  过度拒答与安全的强耦合关系仅在行为层面被证实为相关性而非因果性；缺乏干预实验证明调整某一维度的对齐强度会如何因果性地影响另一维度。

### Next Steps
1.  开展受控实验以解耦安全对齐训练中不同阶段或不同损失项对对抗拒答能力和内容审核倾向的影响方向与强度差异。  
2.  利用补丁范围探测等技术定位导致逆规模现象的注意力头或 MLP 层。  
3.  设计因果中介分析框架以量化过度拒答行为在多大程度上是由通用安全策略向良性边界的泛化所导致。  
4.  开发轻量级代理指标以近似动态基准排名。  
5.  探索将动态生成流水线集成到现有红队工具链中作为持续监控模块。
