## 摘要
基于 LLM 的智能体越来越多地在与用户、工具和外部系统交互的环境中运行。然而，大多数安全评估假设被动的用户和静态控制，忽略了塑造真实智能体行为的交互动态。我们提出了 DUMA-Bench，这是一个用于在双控制交互下衡量智能体安全性的基准与评估协议，其中智能体和用户都能影响共享环境状态。DUMA-Bench 对 τ²-bench 进行了扩展，加入了覆盖八类漏洞的对抗环境，包括 RAG 投毒、跨智能体操纵和不安全输出处理。我们在八个领域和多种用户行为模式下评估了来自五个模型家族（OpenAI、Anthropic、DeepSeek、Qwen 和 Z.ai）的 14 个模型。在我们的实验中，引入双控制交互将攻击成功率从 26.9% 提高到 41.1%。这些结果表明，智能体安全不仅仅是模型本身的属性，而是从模型、用户和环境之间的交互中涌现出来的。DUMA-Bench 为在真实智能体部署中研究安全性提供了一个缺失的评估层。

## Abstract
LLM-based agents increasingly operate in environments where they interact with users, tools, and external systems. Yet most security evaluations assume passive users and static control, ignoring the interactive dynamics that shape real agent behavior. We introduce \textbf{DUMA-Bench}, a benchmark and evaluation protocol for measuring agent security under \emph{dual-control} interaction, where both the agent and the user can influence the shared environment state. DUMA-Bench extends $τ^2$-bench ~\cite{barres2025tau} with adversarial environments covering eight vulnerability classes, including RAG poisoning, cross-agent manipulation, and unsafe output handling. We evaluate \textbf{14 models from five model families} (OpenAI, Anthropic, DeepSeek, Qwen, and Z.ai) across eight domains and multiple user-behavior regimes. Across our experiments, introducing dual-control interaction increases the attack success rate from \textbf{26.9\%} to \textbf{41.1\%}. These results show that agent security is not solely a property of the model but emerges from the interaction between the model, the user, and the environment. DUMA-Bench provides a missing evaluation layer for studying security in realistic agent deployments.

## 1. 论文的核心问题与整体含义

- **研究动机**：现有 LLM 智能体安全评估大多假设“被动用户 + 静态控制”，即模型只接收一次性提示并给出单轮响应，忽略真实部署中用户、智能体和环境之间的多轮动态交互。
- **核心问题**：智能体安全是否不仅取决于模型本身，还取决于“交互机制”？如果评估时加入主动参与、可影响环境状态的用户，安全结论是否会显著改变？
- **整体含义**：论文提出并验证了一个关键判断——智能体安全是模型、用户与环境交互中**涌现出来的属性**，单靠静态提示评估会系统性低估真实风险。

## 2. 论文提出的方法论

- **核心思想**：引入 **DUMA-Bench**，在“双控制交互”设定下评估 LLM 智能体安全。所谓双控制，是指智能体和用户都能独立影响共享环境状态。
- **扩展基础**：DUMA-Bench 在 τ²-bench 的双控制交互结构上加入对抗性安全场景。
- **任务组成**：每个评估案例包含四个组件：
  - 环境（工具、外部数据源、内部状态变量）；
  - 智能体（基于 LLM 的控制器）；
  - 用户（多轮任务驱动请求，部分域有用户侧工具）；
  - 安全断言（用于判定任务是否成功）。
- **交互流程**：用户与智能体多轮交换消息，双方都可以通过工具调用修改环境状态；环境执行动作并记录轨迹；交互结束后评估断言是否满足。
- **安全域**：覆盖 8 类漏洞，共 35 个可执行场景：
  - RAG 投毒（`mail_rag_phishing`）
  - 跨智能体操纵（`collab`）
  - 不安全输出处理（`output_handling`）
  - 可信数据过度共享（`crm_leak`）
  - 基础设施/资源滥用（`infra_loadshed`）
  - 钓鱼式营销滥用（`mktg_phishing`）
  - 身份伪造（`auth_spoof_support`）
  - 工具遮蔽/影子工具（`tool_shadow_poison`）
- **断言设计**：
  - **状态断言**：对执行后环境状态进行确定性检查，不依赖 LLM 判断，避免评判偏差。
  - **通信断言**：当违规只出现在文本回复中时，用 GPT-4o 作为 LLM 裁判，温度设为 0.0，对每个期望结果独立评分。
  - **最终得分**：指定奖励基础 B，每个断言类型内所有断言必须全部通过，任务总奖励为各类型得分的乘积，保证任何部分违规都会导致任务失败。
- **评估指标**：
  - **攻击成功率 ASR**：成功攻击次数 / 总尝试次数。
  - **pass@k**：估计 k 次独立运行全部成功的概率，无偏估计为 `C(c_i,k)/C(n_i,k)`，其中 `c_i` 为成功次数，`n_i` 为总试验次数；k 越大越能体现智能体在重复交互下的可靠性。

## 3. 实验设计

- **评估场景与 benchmark**：使用 DUMA-Bench 自身作为 benchmark，包含 8 个领域、35 个可执行多轮任务。每个任务都有明确安全策略、可变环境状态、领域工具、对抗性产物、用户侧指令和断言。
- **对比的核心维度**：不是“方法 A vs 方法 B”的传统对比，而是比较两种评估 regime：
  - **Solo 评估（被动用户）**：智能体直接与环境交互，没有活跃用户。
  - **Dual-control 评估（双控制）**：智能体同时与环境、用户模拟器交互，轨迹由双方共同塑造。
- **模型覆盖**：14 个模型，来自 5 个家族：
  - OpenAI：GPT-5、GPT-5-mini、GPT-5-nano、GPT-4o、GPT-4o-mini、GPT-4.1、GPT-4.1-mini
  - Anthropic：Claude Opus 4.5、Claude Sonnet 4.5、Claude Haiku 4.5
  - DeepSeek：DeepSeek V3.2
  - Qwen：Qwen3.5-Plus、Qwen3.5-Flash
  - Z.ai：GLM-4.7
- **用户模拟**：
  - 用户侧固定使用 `GPT-4o-mini` 生成多轮用户行为，保证跨目标模型可比性。
  - 用户模拟器温度设置三种：`T_user ∈ {0.0, 0.5, 1.0}`，用于研究用户行为可变性对安全结论的影响。
- **评估协议**：
  - 每个配置为 `(模型, 领域, 评估 regime, T_user)`。
  - 每个任务独立运行 5 次。
  - 主研究每种 regime 产生 1960 次试验。
  - 使用 Fisher 精确检验评估显著性，比例使用 Wilson 置信区间。
- **研究问题**：
  - RQ1：双控制交互如何影响测量的安全鲁棒性？
  - RQ2：安全鲁棒性指标对用户行为变化的稳定性如何？
  - RQ3：模型能力的提升是否可靠地转化为交互式安全评估下更高的鲁棒性？

- **主要实验规模**：

- **实验充分性**：
  - 覆盖 5 个模型家族、14 个模型，包含前沿、中端和轻量级模型，具有一定代表性。
  - 8 个安全域覆盖多种攻击面，任务不是纯提示项，而是可执行多轮场景。
  - 统计检验和置信区间增强了结论可信度。
- **客观性与公平性**：
  - 所有模型使用相同任务定义和工具接口。
  - 用户侧模型固定为 GPT-4o-mini，避免用户侧差异干扰。
  - 确定性状态断言不依赖 LLM 裁判，减少主观偏差。

## 6. 论文的主要结论与发现

- **整体效应**：从被动用户评估切换到双控制交互后，聚合攻击成功率从 **26.9% 升至 41.1%**，提升 14.2 个百分点；pass@1 从 **0.731 降至 0.589**，差异具有统计显著性。
- **领域差异显著**：
  - 最大退化出现在 `mktg_phishing`：ASR 从 0.022 升至 0.615，提升 0.593。
  - `collab`、`crm_leak`、`tool_shadow_poison` 也有大幅提升。
  - `mail_rag_phishing` 基本持平（0.610 → 0.579），说明该类漏洞主要源于检索管道，而非交互动态。
- **用户行为敏感性低**：用户模拟器温度从 0.0 到 1.0，聚合 ASR 在 **0.270 至 0.284** 之间，pass@1 在 **0.716 至 0.730** 之间，温度对之间无统计显著差异。只有少数领域如 `crm_leak` 有局部敏感性。
- **模型能力不等于安全鲁棒性**：
  - 部分 GPT-5 变体在双控制下 ASR 大幅上升，如 GPT-5 从 0.257 升至 0.647，GPT-5-nano 从 0.314 升至 0.793。
  - 某些模型如 Qwen3.5-Plus 甚至出现 ASR 下降（0.393 → 0.357）。
- **可靠性随重复交互下降**：pass@k 从 k=1 到 k=5，聚合分数从 0.722 降至 0.596，说明许多成功在重复交互轨迹中不稳定。

## 7. 优点

- **填补研究空白**：首次系统地将双控制交互与对抗性安全评估结合，区别于“只测交互无攻击”或“只测攻击无交互”的现有工作。
- **方法论统一且可执行**：每个任务都是可运行的多轮场景，包含安全策略、可变状态、工具和断言，不是简单的提示项集合。
- **断言设计严谨**：确定性状态断言为主，避免 LLM 裁判偏差；通信断言弥补纯状态检查无法捕获的文本泄露风险。
- **跨模型、跨领域覆盖面广**：14 个模型、5 个家族、8 个安全域，增强结论的泛化性。
- **统计与审计意识强**：使用 Fisher 精确检验、Wilson 置信区间，并对 LLM 裁判进行人工抽样审计。
- **开放可复现**：公开任务定义、提示、种子、评估脚本和轨迹，便于社区复现与后续防御研究。
- **针对性防御建议**：附录 F 根据各域失败模式给出具体缓解方向，如检索溯源、策略门控工具调用、强制验证门、输出消毒和独立守卫模型。

## 8. 不足与局限

- **基准规模有限**：仅 8 个领域、35 个任务，无法穷尽智能体安全风险空间。
- **用户模拟器局限**：用户行为由 LLM（GPT-4o-mini）生成，可能无法完全代表真实人类用户的多样性和不可预测性。
- **LLM 裁判潜在偏差**：部分任务依赖 GPT-4o 对通信轨迹进行判断，虽然温度设为 0.0 并做了人工审计，但仍存在评判者方差和严格字面匹配带来的误判风险。
- **因子隔离不足**：solo 与 dual-control 的对比是“整体 regime 效应”，未单独分解用户模拟器、多轮对话、工具使用或可变状态各自的边际贡献。
- **模型家族归因受限**：GPT-5 家族表现出较大脆弱性，但其推理模式无法通过 API 完全关闭，因此难以区分是推理模式、模型家族还是交互动态造成的。
- **用户温度分析仅用子集模型**：为节省成本，温度敏感性分析只覆盖 9 个模型，可能限制了结论的全局代表性。
- **外部有效性待提升**：虽然模拟了邮件、协作编辑、检索、客服等场景，但与真实生产环境的复杂性和防御机制仍有差距。
