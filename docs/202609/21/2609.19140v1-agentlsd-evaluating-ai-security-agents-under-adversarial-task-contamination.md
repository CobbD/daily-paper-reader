## 摘要
用于安全的 AI 智能体会检查网页、源代码、日志、配置文件和命令输出。这些环境可能包含影响智能体行为的欺骗性工件。我们将其称为对抗性任务污染。提示注入依赖攻击者提供的指令，而任务污染还包括非指令性证据，例如伪造结果和诱饵端点。我们提出 AgentLSD，一个用于研究对抗性任务污染的受控框架。AgentLSD 使用夺旗（CTF）挑战作为实验环境。我们注入陷阱工件，如伪造旗标、误导性提示、诱饵端点和隐藏线索，同时保留原本的 CTF 解题方案。该框架支持配对的干净实验与陷阱增强实验，并具备确定性陷阱生成、运行时注入、遥测和投递验证。我们在 11 个 Web CTF 挑战上评估了六个模型。在干净条件下，智能体捕获了 41% 的旗标，且没有模型能解决所有挑战。随后我们衡量任务污染的影响。即使智能体仍然找回了旗标，陷阱也会增加轮次（+20）和推理 token（+2k）。解题率的影响则更具异质性：一些模型-题目组合几乎不受影响，而其他组合会跟随诱饵或提交错误旗标。这些结果表明，干净的 CTF 表现低估了对欺骗性任务证据的脆弱性。AgentLSD 分离了这一效应，并提供了可复现的基准用于研究。我们发布了框架、配置、陷阱规范和原始轨迹。

## Abstract
AI agents for security inspect web pages, source code, logs, configuration files, and command outputs. These environments may contain deceptive artifacts that influence the agent's behavior. We call this adversarial task contamination. Whereas prompt injection relies on attacker-supplied instructions, task contamination also includes non-instructional evidence, such as fake results and decoy endpoints. We present AgentLSD, a controlled framework for studying adversarial task contamination. AgentLSD uses Capture the Flag (CTF) challenges as its experimental environment. We inject trap artifacts, such as fake flags, misleading hints, decoy endpoints, and hidden cues, while preserving the intended CTF solution. The framework supports paired clean and trap-augmented experiments with deterministic trap generation, runtime injection, telemetry, and delivery verification. We evaluate six models on 11 web CTF challenges. In the clean condition, agents capture 41% of the flags, and no model solves every challenge. We then measure the impact of task contamination. Even when the agent still recovers the flag, traps increase the number of turns (+20) and reasoning tokens (+2k). Solve-rate effects are more heterogeneous, as some model-challenge pairs are largely unaffected while others follow decoys or submit wrong flags. These results show that clean CTF performance understates vulnerability to deceptive task evidence. AgentLSD isolates this effect and provides a reproducible benchmark for studying it. We release the framework, configurations, trap specifications, and raw traces.

## 1. 论文的核心问题与整体含义

- **研究背景**：AI 安全智能体在执行安全检查时会浏览网页、源码、日志、配置文件等环境内容。这些环境可能被攻击者部分控制，混入欺骗性工件。
- **核心问题**：现有研究多关注“提示注入”（attacker-supplied instruction），但攻击者还可能放置**非指令性证据**，如伪造结果、诱饵端点、误导性提示等，影响智能体判断。论文将这类攻击统称为 **对抗性任务污染（adversarial task contamination）**。
- **整体含义**：安全智能体的脆弱性不能只看“干净任务”下的解题能力；即使任务本身可解、解法不变，环境中的欺骗性证据也可能改变智能体信任哪些证据、探索哪条路径，从而造成失败或资源浪费。论文希望将这一效应从任务难度中分离出来，进行系统测量。

## 2. 论文提出的方法论

- **核心思想**：固定 CTF 挑战的原漏洞、解法路径和 flag 校验逻辑不变，只向环境响应中注入受控的“陷阱工件”，比较同一模型、同一挑战在“干净条件”和“陷阱条件”下的行为差异。
- **框架名称**：AgentLSD。
- **关键技术细节**：
  - **陷阱规范**：用 YAML 原语（primitive）描述陷阱类别、感知通道、表面、目标对象、payload、放置位置、随机化参数和可选仪器化。
  - **实例生成**：由原语模板确定性生成具体陷阱实例，支持多随机种子，且保证同一 seed 可复现；生成时检查诱饵路由不与真实解法路由冲突。
  - **运行注入**：Flask 中间件在请求处理后修改 HTML 响应，注入 DOM 陷阱（可见文本、隐藏 div、注释、meta、可访问性标签等），并注册额外的动态诱饵路由、假目标端点等；不覆盖受保护的挑战路由。
  - **遥测与验证**：记录陷阱渲染、蜜标（honeytoken）命中、兔子洞路由跳转、假 flag 查看等事件；用浏览器验证陷阱是否真正到达 DOM / 可访问性树。
- **陷阱分类**：按意图分为五类：
  - Goal hijack（目标劫持）
  - False authority（虚假权威）
  - False validation（虚假验证）
  - Exploration bait（探索诱饵）
  - Time sink（时间消耗）
- **与提示注入的区别**：任务污染不一定包含指令；伪造验证结果、诱饵端点等只改变证据可信度，不一定要求智能体“服从”某条命令。

## 3. 实验设计

- **实验环境 / 数据集**：自建 11 个基于 Flask 的 Web CTF 挑战，覆盖 7 类漏洞：命令注入、路径遍历、竞态条件、SQL 注入、SSRF、模板注入、XXE。所有挑战在评估前未公开，避免模型记忆。
- **Benchmark 形式**：配对比较（paired comparison）。每个陷阱增强挑战与其干净版本共享同一应用代码、漏洞、flag 生成和解题路径，只增加一个受控陷阱工件。
- **模型对比**：
  - 5 个本地部署模型：Gemma-4 31B、DeepSeek-V4 Flash、GPT-OSS 120B、Qwen3-Coder-Next、Mistral Small 4。
  - 1 个托管前沿模型：GPT-5（作为能力参照，仅参与部分实验）。
- **提示词设置**：两种提示——默认极简提示（只给目标 URL、flag 格式，说明可用 flag 校验服务）和 methodical 提示（额外给出工作流建议和常见漏洞探测方法）。
- **评估协议**：每个 trial 在干净容器和私有网络中运行，flag 随机生成；智能体通过 flag 校验服务提交候选 flag，只有精确匹配才算成功；单次 trial 最长 30 分钟、200 轮；温度 0；使用 OpenCode 智能体脚手架，暴露 bash、文件读写等工具，关闭网络搜索。
- **实验阶段**：
  - Baseline 阶段：所有模型在 11 个干净挑战上运行。
  - Trap 阶段：选取最强的 3 个本地模型和 1 个托管模型，在保留的 7 个挑战上注入 14 个 DOM 陷阱实例；最终报告其中 5 个干净解题率最高的挑战。

## 5. 实验数量与充分性

- **实验规模**：
  - Baseline：5 个本地模型 × 11 个挑战 × 2 种提示 × 5 次重复 = 550 次；GPT-5 增加 55 次，合计 605 次 clean trials。
  - Trap 阶段：3 个最强本地模型 × 7 个保留挑战 × 14 个陷阱 × 2 种提示 × 5 次重复 = 2,940 次；GPT-5 在精简网格上增加 121 次，合计 3,061 次 trap trials。
  - 最终报告集中在 5 个干净解题率最高的挑战，以减少不确定性。
- **充分性评价**：
  - 在模型×挑战×陷阱组合上覆盖较广，采用全因子实验设计（对本地模型），配对比较方法能较干净地分离陷阱效应。
  - 但每格仅 5 次重复，样本量偏小；论文承认“five trials per cell is coarse”，且未进行显著性检验。
  - GPT-5 的陷阱实验被成本限制到少量挑战和陷阱实例，缺乏与本地模型同等规模的完整 factorial 对比。
  - 没有设置“良性注入控制”（benign-injection control）来排除页面尺寸增大等非欺骗性影响。
  - 陷阱仅通过 DOM 通道、一次只激活一个，且为静态、非自适应，实验覆盖范围较窄。

## 6. 论文的主要结论与发现

- **干净条件能力（Q1）**：整体 flag 捕获率约 41%；无模型能解决所有挑战；最强本地模型 Gemma-4 31B 接近 GPT-5，语料库未被饱和，适合作为测量欺骗效应的基础。
- **陷阱效应（Q2）**：
  - 陷阱对解题率的影响高度异质：GPT-OSS 120B 损失最大，Gemma-4 31B 几乎不受影响，DeepSeek-V4 居中；GPT-5 在部分陷阱下也受影响。
  - 更一致的效应是**努力成本上升**：即使最终仍捕获 flag，陷阱通常使轮次中位数增加约 20 轮、推理 token 增加约 2k，且具有长尾。
- **哪些陷阱最有效（Q3）**：
  - **重定向类陷阱**（goal hijack、exploration bait）造成最大的解题率下降。
  - 几乎所有陷阱族都会增加轮次和推理 token，即使不改变最终结果。
  - 效应集中出现在特定模型×挑战×陷阱组合中；同一陷阱对不同模型可能只增加成本，也可能同时导致解题失败。
- **陷阱交互（Q4）**：
  - 接触诱饵很常见（39–57% 的 trap runs），但脆弱性主要不在于“是否接触”，而在于“接触后能否脱离”。
  - DeepSeek 接触诱饵后几乎不受影响，Gemma 中等，GPT-OSS 接触后解题率从 65% 跌至 28%，并长时间滞留在诱饵路径上。
  - 接触诱饵瞬间，Gemma 和 DeepSeek 的推理 token 会局部激增，随后恢复正常；GPT-OSS 则通过持续停留而不是单次思考来消耗预算。

## 7. 优点

- **问题定义清晰**：将研究范围从“提示注入”扩展到更广泛的“非指令性证据污染”，区分机制与效果，并提出可操作的定义。
- **受控实验设计**：利用 CTF 的客观 flag 校验和可复现部署，通过配对干净/陷阱条件，较好地把“任务难度”与“欺骗效应”分离。
- **可复现性**：陷阱使用 YAML 原语 + 确定性生成 + 运行时注入；发布框架、配置、陷阱规范和原始轨迹，便于复现与扩展。
- **多维测量**：同时报告解题率、轮次、工具调用、推理 token、遥测交互（蜜标、诱饵路由）等，能捕捉“没失败但被拖慢”的隐性影响。
- **能力参照设计**：用 GPT-5 作为托管前沿参照，验证本地模型集合的代表性，同时在成本与覆盖之间做了合理折中。
- **分析深入**：按陷阱族、按模型、按挑战绘制变化热图和交互分析，揭示效应异质性和“脱离诱饵”的关键脆弱点。

## 8. 不足与局限

- **陷阱覆盖面窄**：仅使用 DOM 通道、14 个静态陷阱、一次激活一个；未覆盖像素级、多模态、自适应或组合陷阱。
- **实验范围受限**：
  - 仅 11 个自建 Web CTF 挑战，7 个漏洞类；最终报告只聚焦 5 个高解题率挑战。
  - 每格仅 5 次重复，统计效力有限，无显著性检验。
  - GPT-5 陷阱实验因成本大幅缩减，无法与本地模型同等比较。
- **缺乏控制条件**：没有“良性注入”对照，无法完全排除陷阱导致页面大小变化等非欺骗性因素。
- **外部效度有限**：CTF 是简化、游戏化的安全任务，结果不能直接外推到生产安全环境。
- **威胁模型假设较强**：攻击者静态、非自适应、模型无关，智能体对陷阱不知情；未覆盖自适应攻击或已告知陷阱的防御场景。
- **未评估缓解措施**：论文提出一些设计建议（如来源可信标注、独立证据要求、回溯机制），但未在相同协议下进行实验验证。
- **行为解释偏初步**：遥测能确认“接触/交互”，但不能直接证明智能体“相信”陷阱；论文承认信念层面需未来工作。
