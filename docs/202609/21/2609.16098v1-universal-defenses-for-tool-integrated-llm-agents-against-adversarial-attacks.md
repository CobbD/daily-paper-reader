## 摘要
大语言模型（LLM）智能体在多个领域展现了强大的能力，尤其是在与外部工具结合完成多步骤任务时。然而，它们日益容易受到对抗性攻击的影响，包括直接提示注入、间接提示注入、记忆投毒和后门攻击，这些攻击利用了模型对提示注入和工具操纵的开放性。在本工作中，我们在统一框架下探索了针对这四种攻击类型的实用且可推广的防御策略。我们引入了两种通用的基于工具的防御方法：攻击者工具过滤（Attacker Tool Filtering），利用异常检测（例如孤立森林）识别并移除可疑工具；以及正常工具召回（Normal Tool Recalling），一种白盒方法，在规划前恢复智能体的原始工具集。此外，我们整合了基于提示的防御手段：思维链提示和自我反思技术以增强推理能力，以及任务改写以减轻攻击。在四个开源LLM（Gemma2-9B、Qwen2-7B、LLaMA3-8B和LLaMA3.1-8B）和三个闭源LLM（GPT-3.5、GPT-4和GPT-5）上的实验结果表明，我们的方法显著降低了攻击成功率（ASR），在许多设置中实现了0%的ASR，同时保持甚至提高了原始任务成功率。这些发现凸显了简单、模块化、多层防御在增强工具集成LLM智能体安全性和鲁棒性方面的前景。代码可在 https://github.com/Xiaoyan-Lisa/Defenses-for-Tool-Integrated-LLM-Agents-Against-Adversarial-Attacks 获取。

## Abstract
Large Language Model (LLM) agents have demonstrated impressive capabilities across a variety of domains, particularly when integrated with external tools for multi-step task completion. However, they are increasingly vulnerable to adversarial attacks, including direct prompt injection, indirect prompt injection, memory poisoning, and backdoor attacks, which exploit the model's openness to prompt injection and tool manipulation. In this work, we explore practical and generalizable defense strategies within a unified framework across these four attack types. We introduce two universal tool-based defenses: Attacker Tool Filtering, which uses anomaly detection (e.g., Isolation Forest) to identify and remove suspicious tools, and Normal Tool Recalling, a white-box method that restores the agent's original toolset prior to planning. Additionally, we incorporate prompt-based defenses: Chain-of-Thought prompting and self-reflection techniques to enhance reasoning and task paraphrasing to mitigate attacks. Experimental results across both four open-source LLMs (Gemma2-9B, Qwen2-7B, LLaMA3-8B, and LLaMA3.1-8B) and three proprietary LLMs (GPT-3.5, GPT-4, and GPT-5) show that our methods significantly reduce the Attack Success Rates (ASR), achieving 0% ASR in many settings, while preserving or even improving the original task success rate. These findings highlight the promise of simple, modular, multi-layered defenses for strengthening the security and robustness of tool-integrated LLM agents. The code is available at https://github.com/Xiaoyan-Lisa/Defenses-for-Tool-Integrated-LLM-Agents-Against-Adversarial-Attacks.

# 论文总结

## 1. 核心问题与整体含义
- **研究背景**：工具集成的大语言模型（LLM）智能体在多个领域表现出强大能力，但其开放性使其容易受到对抗性攻击，包括直接提示注入（DPI）、间接提示注入（IPI）、记忆投毒（MP）和后门攻击（Backdoor）。
- **安全威胁**：这些攻击可劫持工具调用，导致未授权数据访问、有害命令执行、与外部系统错误通信等不可逆后果，且攻击常跨模型迁移。
- **现有防御局限**：已有防御大多针对单一攻击类型，以黑盒提示修改为主，较少利用白盒信息，且可能损害原始任务性能。
- **本文目标**：提出一个统一、轻量、模型无关的多层防御框架，同时对抗四类攻击，并保持或提升原始任务成功率。

## 2. 方法论
- **总体思路**：将防御分为**工具层**（白盒/灰盒）和**提示层**（黑盒），形成三层防御架构：外层在输入后应用 CoT 与改写，中层对工具进行过滤，内层在计划执行前进行自我反思验证。
- **工具防御 1：攻击者工具过滤（ATF）**
  - 使用语义嵌入（如句子嵌入模型）将每个工具描述映射为向量。
  - 基于隔离森林（Isolation Forest）进行无监督异常检测，将异常工具标记为可疑并过滤。
  - 过滤后的工具集为 `Tfiltered = {τi | yi = 0}`，其中 `yi=1` 表示异常工具。
  - 优点：开销小、无需攻击先验知识，可与其他防御互补。
- **工具防御 2：正常工具召回（NTR）**
  - 白盒方法，假设用户原始工具集已安全存储。
  - 在规划阶段开始前，将当前（可能被篡改的）工具集强制恢复为用户原始工具集 `Tuser`，即 `Teffective ← Tuser`。
  - 规划过程变为 `P = LLM(psys, q, O, Teffective)`，仅使用可信工具。
  - 优点：简单、精确，无需识别恶意工具，只要可访问内部工具状态。
- **提示防御 1：思维链提示（CoT）**
  - 采用结构化 CoT，要求智能体以 JSON 格式生成分步计划，明确每步使用的工具。
  - 引导模型专注于安全、预定义的工具，减少执行恶意指令的概率。
- **提示防御 2：任务改写（Paraphrasing）**
  - 使用 GPT-4o-mini 对用户提示进行改写，显式引用正常工具，并破坏攻击结构（如绕过模式、注入指令、隐藏触发器）。
  - 保留任务语义，提高模型与用户意图的对齐。
- **提示防御 3：自我反思（Self-reflection）**
  - 借鉴 Reflexion，LLM 同时扮演反思模块和评估器，对生成的计划进行验证和修正。
  - 仅使用语言反馈，无需外部信号。验证规则包括检查工具是否在允许列表中、步骤逻辑是否合理等。

## 3. 实验设计
- **数据集与 Benchmark**：采用 **ASB（Agent Security Bench）** 框架，包含 10 个领域特定 LLM 智能体，每个智能体有正常工具和攻击者工具，每个智能体 400 个任务（200 攻击性 + 200 非攻击性）。
- **攻击类型与变体**：
  - DPI 和 IPI：评估四种注入方式——Naive Attack、Escape Characters、Context Ignoring、Fake Completion。
  - MP：使用 Fake Completion + Context Ignoring 组合策略。
  - 后门攻击：使用 Plan-of-Thought（PoT）后门，包含非词触发器（如“@_@”）和短语触发器（如“with perspicacious discernment”）。
- **对比方法**：
  - 无防御基线。
  - ASB 中已有防御：DPI 和后门下使用 paraphrasing，IPI 下使用 delimiters。
  - 本文提出的两种组合：**ATF + CoT + Paraphrasing + Reflection** 和 **NTR + CoT + Paraphrasing + Reflection**。
- **模型**：四个开源模型（Gemma2-9B、Qwen2-7B、LLaMA3-8B、LLaMA3.1-8B）和三个闭源模型（GPT-3.5、GPT-4、GPT-5，其中 GPT-5 仅在附录补充部分防御组合）。
- **评价指标**：
  - 攻击成功率（ASR）：成功使用攻击专用工具的任务比例。
  - 原始任务成功率（OTSR）：原始良性任务成功完成的比例。
- **消融实验**：在 Context Ignoring DPI 攻击下，逐步移除 NTR、CoT、Paraphrasing、Reflection 组件，观察 ASR 和 OTSR 变化。

## 6. 主要结论与发现
- **防御有效性**：提出的统一框架显著降低 ASR，在许多设置中达到 **0% ASR**；NTR 组合防御在多数场景下实现完全攻击抑制。
- **任务性能保持**：对于开源小模型，防御通常同时**提升 OTSR**；但对于 GPT-3.5/GPT-4 等闭源模型，防御虽降低 ASR，但可能导致 OTSR 显著下降。
- **模型安全性与规模无关**：在无防御下，GPT-3.5 和 GPT-4 的 ASR 往往高于小开源模型，说明大模型并非天然更安全。
- **组件贡献**：Paraphrasing 在提示防御中作用最大，但单独使用效果有限；NTR 是关键工具防御；CoT 和 Reflection 对某些模型有增量提升。
- **模型鲁棒性差异**：LLaMA3 本身较鲁棒，额外防御收益有限；GPT 系列对防御干预更敏感，容易丢失原始任务目标。

## 7. 优点
- **统一框架**：首次将工具过滤/召回与提示增强（CoT、改写、反思）结合，同时对抗四类攻击，通用性强。
- **轻量模块化**：ATF 无需训练，NTR 只做工具集恢复，提示防御为即插即用，易于集成到现有智能体。
- **实验全面**：覆盖多类开源/闭源模型，使用公开 benchmark（ASB），并与已有防御对比。
- **实践洞察**：发现大模型不安全于攻击、防御需权衡任务性能，对实际部署有指导意义。
- **代码开源**：便于复现和扩展。

## 8. 不足与局限
- **环境静态**：所有实验在 ASB 静态数据集上进行，未在动态、真实交互环境中验证，防御在动态威胁下的有效性未知。
- **ATF 依赖异常检测**：可能误过滤正常工具或漏检攻击工具，且对工具描述语义敏感，需要合适的嵌入模型和污染率设置。
- **NTR 白盒假设**：要求访问并恢复原始工具集，在完全黑盒或工具集动态变化的场景中部署受限。
- **任务性能损失风险**：对 GPT 系列模型，防御（尤其多层防御）会导致 OTSR 大幅下降，可能牺牲智能体的实用性。
- **消融不充分**：组件重要性分析仅针对一种攻击，未系统评估各组件在不同攻击下的贡献。
- **未考虑自适应攻击**：攻击者可能针对这些防御（如绕过改写、欺骗隔离森林）设计更强的攻击，论文未评估抵御能力。
- **GPT-5 评估不完整**：未完整测试所有防御组合，且其异常低的无防御 OTSR 可能引入偏差。
