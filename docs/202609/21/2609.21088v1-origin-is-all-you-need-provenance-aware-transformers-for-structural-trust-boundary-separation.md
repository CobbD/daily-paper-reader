## 摘要
间接提示注入（IPI）仍然是大型语言模型（LLM）系统面临的核心安全与保障挑战，因为标准Transformer在架构上缺乏来源权威的概念。检索到的文档、用户输入和系统指令都经由同一种无差别的注意力机制处理，迫使模型仅凭措辞来推断哪些内容应当遵从、哪些应当作为数据处理。我们提出溯源感知Transformer（Provenance-Aware Transformers），这是一种让应用提供的来源标签在模型内部生效的溯源感知防御方法。每个输入token被赋予一个编码其来源的环ID，并且模型通过增加来源嵌入、可学习的来源注意力偏置以及可学习的来源缩放来进行增强，从而在归一化下保留溯源信息。由此产生的架构在生成过程中强制在权威来源与非权威来源之间建立结构化边界。为了在已发布的预训练模型上实例化该架构，我们提出一种两阶段微调流程，在环约束下教会模型来源语义和任务行为。评估表明，溯源感知Transformer在分布内和分布外对间接提示注入均保持稳健的抵抗力，同时保持与基础预训练模型相当的实用性。更广泛地说，我们的工作表明，将溯源信息作为一等架构信号加以暴露，可以将LLM安全对齐从脆弱的模式匹配转向显式的信任分离。

## Abstract
Indirect prompt injection (IPI) remains a central safety and security challenge for large language model (LLM) systems because standard transformers lack architectural notion of source authority. Retrieved documents, user inputs, and system instructions are all processed through the same undifferentiated attention mechanism, forcing the model to infer from wording alone what should be obeyed and what should be treated as data. We propose Provenance-Aware Transformers, a provenance-aware defense that makes application-supplied source labels actionable inside the model. Each input token is assigned a ring ID encoding its origin, and the model is augmented with origin embeddings, a learnable origin attention bias, and a learnable origin scale that preserves provenance under normalization. The resulting architecture enforces a structural boundary between authoritative and non-authoritative sources during generation. To instantiate this architecture on released pretrained models, we propose a two-stage fine-tuning pipeline to teach the model origin semantics and task behavior under ring constraints. Evaluation shows that Provenance-Aware Transformers maintain robust resistance to IPI both in-distribution and out-of-distribution while preserving utility comparable to the base pretrained model. More broadly, our work shows that exposing provenance as a first-class architectural signal can shift LLM safety alignment from brittle pattern matching toward explicit trust separation.

# 论文详细总结

## 1. 论文的核心问题与整体含义

- **核心问题**：间接提示注入（Indirect Prompt Injection, IPI）是当前 LLM 系统的核心安全挑战。标准 Transformer 对所有输入 token 使用同一个内容寻址的注意力机制，不区分“系统指令”“用户输入”“检索内容”等来源，导致模型只能靠文字表述去猜测什么应当遵守、什么应当作为数据处理。
- **整体含义**：论文主张应当把“来源 / 溯源（provenance）”作为一等架构信号引入 Transformer，使模型在生成过程中从结构上区分权威与非权威来源，而不是依赖脆弱的模式匹配。这类似于操作系统安全中“来源决定授权”的原则。
- **研究定位**：现有防御大致分为 prompt 级、检测级、微调级三类，但都未解决根因——模型架构本身缺乏信任边界。本文提出的是架构级防御。

## 2. 论文提出的方法论

### 2.1 核心思想：四环信任层级

- 每个输入 token 被赋予一个离散来源环 ID（Ring ID）：
  - **Ring 0（ORG_SYSTEM）**：系统 / 操作者指令，绝对权威。
  - **Ring 1（ORG_SELF）**：模型自己此前生成的 token。
  - **Ring 2（ORG_USER）**：直接用户输入或其他受信任内容。
  - **Ring 3（ORG_DATA）**：外部不可信数据，可能包含注入攻击。
- 应用层在构造 prompt 时已经知道每个 token span 的来源，因此无需内容级检测即可完成环分配。

### 2.2 三个来源感知架构组件

- **来源嵌入（Origin Embedding）**：
  - 在标准 token embedding 之上增加一个可学习的嵌入表 \(E_{\mathrm{org}} \in \mathbb{R}^{4 \times d}\)，按环 ID 查表后加权相加：
    \[
    x_i = E_{\mathrm{tok}}[t_i] + \alpha \cdot E_{\mathrm{org}}[r_i]
    \]
  - \(\alpha\) 是可学习来源缩放 / 门控标量，用于对抗后续 RMSNorm 对来源信号的稀释。
- **来源感知注意力偏置（Origin Attention Bias）**：
  - 学习一个 \(4\times 4\) 偏置矩阵 \(B\)，按 query 和 key 的环 ID 获得偏置项，并加到原始注意力 logit 上：
    \[
    a_{ij} = \frac{q_i \cdot k_j}{\sqrt{d_k}} + B_{r_i, r_j}
    \]
  - 初始化时主要抑制 \(B_{1,3}\) 和 \(B_{2,3}\)，即 assistant 自身 token 和 user token 对不可信 Ring 3 内容的注意力；其他组合保持接近 0。
- **来源缩放 / 门控集成（Origin Integration Gate）**：
  - 通过显式标量 \(\alpha\) 保持来源嵌入在归一化后的相对贡献，避免仅靠高维嵌入权重补偿尺度不匹配。

### 2.3 两阶段微调流程

- **Stage 1 — 来源语义微调（Origin Fine-Tuning）**：
  - 在广泛指令跟随语料上恢复通用能力，并教会新组件“来源标签意味着什么”。
  - 使用两个辅助损失：
    - **正交性损失 \(L_{\mathrm{orth}}\)**：让 Ring 0 与 Ring 2 的来源嵌入在几何方向上尽量正交。
    - **权威损失 \(L_{\mathrm{auth}}\)**：鼓励系统提示嵌入在幅度上大于用户嵌入：
      \[
      L_{\mathrm{auth}} = \mathrm{ReLU}(\|e_2\| - \|e_0\| + m)
      \]
- **Stage 2 — 对齐微调（Alignment Fine-Tuning）**：
  - 在结构化注入数据集上训练抑制行为：Ring 0 无条件遵循，Ring 2 作为普通任务输入，Ring 3 无论表面内容如何都被抑制。
  - 数据集基于 SEP 基准的 witness 方法扩展，加入明确来源环标签。

## 3. 实验设计

### 3.1 基础模型

- 四个开源 decoder-only 模型：
  - SmolLM2-360M-Instruct
  - LLaMA-3-8B-Instruct（主评估模型）
  - Qwen2.5-7B-Instruct
  - Mistral-7B-Instruct-v0.3

### 3.2 训练数据

- **Stage 1**：105K 样本，来自 UltraChat-200K（80K）、MMLU aux-train（12K）、GSM8K（8K）、CodeAlpaca-20K（5K）。
- **Stage 2**：约 60,200 样本，其中 24,079 个注入样本、36,121 个干净样本；另外补充 Alpaca-Cleaned 干净数据。
- Stage 2 注入数据基于 SEP 的 witness 方法，使用 Claude 生成新上下文、ground truth，并从固定 probe–witness 对中选择注入，覆盖 9 种攻击模式。

### 3.3 评估数据集

- **IID**：SEP test（4,375 条）
- **OOD**：
  - PI-Attack（8,256 条，分类任务）

### 3.4 对比方法

- **Prompt 级**：Instructional、Sandwich、Random Sequence、Delimiters、Known-Answer。
- **检测级**：PromptSleuth、DataSentinel、PromptGuard、PromptLocate、Rennervate。

- 另有 **No Defense** 基线。

### 3.5 评估指标

- **ASR（Attack Success Rate）**：注入样本中模型输出匹配注入意图的比例。
- **LC Win Rate**：在 AlpacaEval 2.0 上、Claude Sonnet 5 作为评判、随机化顺序、长度校正的胜率；50% 表示与未防御基础模型持平。

## 6. 论文的主要结论与发现

- 来源感知 Transformer 在 SEP IID 上 ASR 低至 0.51%–0.69%，在三个 OOD 数据集上几乎全部达到 **0.00%–0.03% ASR**，显著优于现有防御。
- OOD 泛化不是来自对训练分布的更好拟合，而是来自结构化抑制机制：Baseline SFT 在 IID 上表现相近，但在 OOD 上明显更差。
- 在 AlpacaEval 2.0 上，多数模型的 LC win rate 接近 50%，说明防御没有大幅牺牲通用指令跟随能力。
- 白盒自适应攻击下，来源感知模型将 GCG ASR 从 50.71% 降到 1.44%，NeuExe ASR 从 48.44%（原文表中有 47.81% 文字描述，以表为准）降到 1.56%。
- 消融表明：
  - 去掉 Stage 1 对 IID/OOD ASR 影响很小，但会显著降低效用。
  - 去掉来源注意力偏置后防御崩溃，OOD ASR 升至 12%–98%，证明注意力偏置是核心抑制机制。
- 在 WildJailbreak 越狱测试中，来源感知模型将 HarmBench 判定的 jailbreak ASR 从最高 41.04% 降至 0.00%，说明同一来源抑制机制可泛化到非提示注入类安全威胁。

## 7. 优点

- **根因式防御**：把来源显式建模为架构信号，而不是依赖提示词或事后检测。
- **结构化信任边界**：来源注意力偏置提供可解释、可验证的跨源信息流约束。
- **两阶段训练设计合理**：先教来源语义，再教抑制行为，降低效用损失。
- **评估扎实**：多模型、多数据集、IID/OOD、消融、白盒自适应攻击、跨任务泛化都有覆盖。
- **对比公平**：包含 Baseline SFT，能分离架构贡献与微调贡献。
- **安全泛化证据强**：OOD 和 jailbreak 场景均表现优异，支持“结构泛化而非模式匹配”的核心主张。

## 8. 不足与局限

- **环级无条件抑制**：Ring 3 中所有内容都被同等抑制，无法区分外部数据中的合法信息与注入指令。若应用需要模型利用可信外部数据，会损失功能。
- **四环层级较粗**：未支持 span 级、多类外部来源的细粒度信任策略；需要应用层提供准确来源标签，误标风险未评估。
- **需要架构修改与微调**：不是即插即用；对于已有大规模模型，重新训练门控 / 偏置 / 嵌入会带来额外成本。
- **部分模型效用下降**：Mistral-7B-Instruct 在 AlpacaEval 上仅为 42.7%，未达到与基座模型持平。
- **实验细节不完整**：缺少总训练时间、碳排放 / 成本估算；DataSentinel OOD 样本量小。
- **生成数据的潜在偏差**：Stage 1/Stage 2 数据大量依赖 Claude 生成，可能带有模型偏好；AlpacaEval 评判也使用 Claude，存在相关性偏差风险。
- **未讨论推理开销**：来源注意力偏置需要按序列长度展开成 \(T \times T\) 偏置张量，可能带来额外内存和计算成本。
