## 摘要
AI 中介平台通过为不同委托方行事的大语言模型（LLM）代理来协调工作。在这些工作流中，隐私损失可能在最终答案出现之前就已产生：一次记忆写入、共享工作区更新、代理间消息或工具事件，都可能给另一委托方带来下游暴露成本。我们将这种失效模式建模为一种隐私传播外部性，其中原始披露的成本不仅取决于内容，还取决于拓扑结构和扇出范围。我们提出 PAPC，一种平台中介机制，可在信息移动事件更新共享状态或外部通道之前对其进行拦截。PAPC 综合运用策略、来源、拓扑/扇出、权限和内容信号，以决定允许事件、释放策略安全的抽象、隔离原始内容、阻断转移或收窄后续权限。该模型解释了为什么最终输出控制会忽略中间暴露成本，以及为什么高扇出对象会放大传播。在检索记忆和多代理工作流基准测试中，PAPC 在保持确定性任务完成的同时，消除了所测得的精确原始值暴露和外部原始值暴露。这些结果将事件级中介定位为面向代理中介在线工作的一种平台治理原语。

## Abstract
AI-mediated platforms coordinate work through LLM agents acting for different principals. In these workflows, privacy loss can be created before a final answer appears: a memory write, shared-workspace update, inter-agent message, or tool event may impose downstream exposure cost on another principal. We model this failure mode as a privacy-propagation externality, where the cost of a raw disclosure depends on topology and fanout as well as content. We present PAPC, a platform-mediated mechanism that intercepts information-moving events before they update shared state or external channels. PAPC combines policy, provenance, topology/fanout, privilege, and content signals to allow an event, release a policy-safe abstraction, quarantine raw content, block a transition, or narrow onward rights. The model explains why final-output control misses intermediate exposure costs and why high-fanout objects amplify propagation. Across retrieval-memory and multi-agent workflow benchmarks, PAPC preserves deterministic task completion and eliminates measured exact raw-value and external raw-value exposure. The results position event-level mediation as a platform-governance primitive for agent-mediated online work.

## 1. 论文的核心问题与整体含义

- **研究背景与动机**：AI 中介平台日益依赖 LLM 代理（LLM agents）为不同委托方（principals）协调工作，如内部团队、客户、供应商、分析师等。这些代理在共享运行时状态（记忆、工作区文档、摘要、消息、工具输出、最终更新）上操作，形成了一个新的治理表面。
- **核心问题**：隐私损失可以在最终答案出现之前就已产生——一次**记忆写入**、**共享工作区更新**、**代理间消息**或**工具事件**，都可能给另一委托方带来下游暴露成本。即敏感信息（如预算金额、客户标识、内部延迟理由）先进入中间工件，随后被摘要、转发或转换为面向外部的文本。
- **关键概念——隐私传播外部性**：一个委托方将详细信息写入共享对象可获得即时协调价值，而另一委托方在该信息对未授权代理或外部通道可见时承担暴露成本。该成本**不仅取决于内容，还取决于平台拓扑和扇出**。同一原始值在私有记忆、一跳交接、规划器中心星型结构或许多代理可读的黑板中，后果截然不同。
- **整体含义**：AI 中介平台的隐私治理需要**对运行时状态转换进行中介**，而不仅仅是最终输出审核。最终输出过滤器只能观察传播链的末端，通道级访问控制可能知道工作区是共享的，但无法判断载荷中是否包含另一委托方的原始秘密、策略是否只允许抽象、目标对象是否具有高扇出、或者该转换是否提升了下游权限。这连接了在线平台外部性/隐私经济学与工具使用代理的近期安全失效。

## 2. 论文提出的方法论：PAPC 平台中介机制

### 核心思想

PAPC 是一个**运行时中介层**，在所有信息移动事件（记忆写入、共享工作区修改、消息发送、工具调用、最终输出）**写入共享状态或到达外部通道之前**进行拦截。目标不是单纯的“允许/拒绝”，而是在“禁止原始披露、允许粗粒度抽象”的注册策略类别下，对事件执行精细治理。

### 形式化模型

- **事件图模型**：平台模型为 `(A, P, O, E, G)`，其中 A 是代理集，P 是委托方集，O 是运行时对象（记忆、文档、摘要、消息等），E 是有序事件序列。每个事件 `e = (a, p, r, c, o, z, x, H, t)` 记录行动代理、行动委托方、接收委托方、通道、目标对象、目标区域（私有/共享/外部/隔离）、载荷、因果父节点和步骤。
- **策略、抽象与暴露**：受保护项 `s` 具有所有者、原始值检测器、授权原始读取者、允许的抽象、禁止通道和敏感度权重。事件 `e` 在存在 `s` 使 `raw(s, x_e)` 为真且 `auth(s, e)` 为假时，产生未授权原始暴露；当原始值到达外部接收者、最终输出、供应商发送工具或外部消息时，产生外部原始暴露。
- **福利目标**：
  ```
  W(M) = Σ B_p(M(e_t)) − Σ L_q(M(e_t)) − C_med(M)
  ```
  其中 `B_p` 是行动委托方的局部协调收益，`L_q` 是受影响委托方的隐私损失，`C_med` 是中介成本。
- **可测传播成本代理**：
  ```
  Cost(e) = Σ 1{raw(s, x_e) ∧ ¬auth(s, e)} · λ_s · ϕ(e)
  ```
  其中 `λ_s` 为敏感度，`ϕ(e)` 捕获可达性（外部交付、权限提升、下游扇出）。

### 风险评分机制

PAPC 对事件计算 `r(e) = min(1, Σ w_i f_i(e))`，特征包括：

| 特征 | 定义 |
|------|------|
| `f_raw` | 载荷含受保护原始内容且接收者/通道未授权 |
| `f_cross` | 受保护溯源跨委托方边界 |
| `f_fanout` | 目标对象下游读取者规范化数量 |
| `f_priv` | 从源上下文到目标上下文的权限增量 |
| `f_external` | 目标是最终输出、外部接收者或工具发送通道 |
| `f_sem` | 载荷通过运行时可观察语义模式请求敏感细节 |

### 五种决策动作

1. **允许（Allow）**：无原始违规且传播风险低。
2. **安全视图重写（Safe-view rewrite）**：通过确定性策略驱动重写，将受保护原始值替换为授权抽象（如“存在预算约束”而非“$742,000”），并验证输出不含任何精确原始值。
3. **隔离（Quarantine）**：将原始载荷存储在非模型可见区域，仅向下游发出决策记录、安全占位符或经验证的安全视图。
4. **阻断（Block）**：阻止转换（例如外部到内部加毒/原始内容时强制阻断）。
5. **传播权限收窄（Propagation-right narrowing / lease downgrade）**：附加确定性控制元数据，将原始可见性转换为抽象可见性，移除外部或工具权限，降低扇出或限制转发（风险 ≥ 0.30 时触发）。

### 算法流程（事件中介步骤）

1. 将事件规范化为 `(a, p, r, c, o, z, x, H, t)` 并附加因果父节点。
2. 从策略注册表检测受保护片段和允许的抽象级别。
3. 检查原始读取者授权、禁止通道和目标区域约束。
4. 计算运行时可观察风险特征和分数。
5. 选择允许、安全视图重写、隔离、阻断或权限降级。
6. 构建并验证安全视图；验证失败则隔离。
7. 发出中介事件、更新传播状态、记录脱敏审计条目。

**不变式**：在完全中介和安全视图健全性下，每个非隔离的写入、发送、工具调用和最终输出均满足注册的原始披露策略，可通过事件序列归纳证明。

## 3. 实验设计

### 主要场景：企业供应商更新工作流

- **代理角色**：特权规划器（Planner）、特权财务代理（Finance agent）、内部文档撰写者（Document writer）、外部供应商端点（External vendor endpoint）。
- **任务**：内部代理通过私有记忆、共享原始记忆、安全视图记忆、工作区文档和代理间消息协调，准备面向供应商的项目更新。任务允许粗粒度披露（如承认存在预算约束），但禁止精确预算、事件理由、私有客户/项目引用和凭据类标记。

### 拓扑结构（受控变量）

| 拓扑 | 通信结构 | 传播压力 |
|------|---------|----------|
| **chain₄** | Planner → 财务 → 文档撰写者 → 供应商 | 窄但更深的交接路径 |
| **star₄** | Planner 为中心枢纽 | 聚合风险集中在规划器 |
| **blackboard₄** | 全对全交互 + 共享工作区 | 最高扇出和共享状态压力 |

### 攻击设置（7 种）

- 无攻击（clean）
- 摘要投毒摘要投毒 直接/间接
- 工作区投毒 直接/间接
- 通信劫持 直接/间接
- 直接攻击：明确请求敏感细节；间接攻击：通过操作文本“洗钱”请求。
- 另有保留的**改写变体**用于标签自由验证。

### 对比方法（4 种防御）

1. **无中介（No defense）**
2. **静态 ACL**：阻断硬禁止通道和未授权原始接收者，无语义或拓扑推理。
3. **提示过滤（Prompt filter）**：直接短语/模式匹配，无安全视图重写。
4. **PAPC**：综合策略、溯源、拓扑/扇出、安全视图、隔离和租约信号。

### 评价指标

- **任务成功**：确定性规则/模板检查必需的非敏感内容。
- **未授权原始暴露**：运行时事件文本中（隔离和阻断事件之外的）精确原始值暴露计数。
- **外部原始暴露**：到达外部接收者、最终输出、供应商发送工具或外部消息的子集。
- **级联大小/深度/权限可达**：基于事件图计算。
- MinMax 作为最终写作者生成供应商更新；守卫决策和泄露指标由确定性运行时代码执行。

## 5. 实验数量与充分性

### 实验规模统计

- **主 MiniMax 最终写作者矩阵**：3 拓扑 × 7 攻击 × 4 防御 × 3 种子 = **252 次运行**
  - 其中 PAPC 子集：3 × 7 × 1 × 3 = 63 次
- **确定性标签自由矩阵**：3 拓扑 × 10 攻击 × 6 防御 × 3 种子 = **540 次运行**（无 LLM 调用）
- **目标 MiniMax 标签自由矩阵**：2 拓扑 × 3 改写攻击 × 4 防御 × 3 种子 = **72 次运行**
- **匹配对比**：每基线 90 组（标签自由确定性比较）；每基线 18 组（目标 MiniMax 比较）
- **无语义模式消融**：确定性子集

### 充分性与公平性分析

- **优点**：实验设计在拓扑、攻击类型、防御策略、种子四个维度上做了系统性对照，矩阵规模较完整；同一任务、策略、攻击、防御和种子跨拓扑运行，控制了混淆变量；PAPC 与非防御/静态 ACL/提示过滤的逐组匹配比较（improved/tied 统计）较为客观。
- **不足**：
  - 仅使用**单一 LLM 提供者**（MiniMax）作为最终写作者，未跨多个模型验证通用性。
  - 实验规模为**中等**（252 + 540 + 72 = 864 次），在学术基准中数量合理但不算特别大。
  - 攻击模式为**合成/模拟**，缺乏真实用户数据或生产环境部署验证。
  - 消融实验**不完整**：仅对语义特征做了部分消融，未逐组件隔离研究策略、拓扑/扇出、安全视图、隔离的独立贡献。
  - 部分对比中“tied”比例较高（如静态 ACL vs PAPC 外部泄露 45 tied/63 组），这意味着在低压力组基线本身已为零泄露，差异区分度有限。

---

## 6. 主要结论与发现

1. **中间状态隐私成本（RQ1）**：在检索记忆遏制检查中，未防御时被投毒的检索内容暴露到下游上下文并产生非零“表现”；PAPC 允许内部检索到毒内容，但阻止其进入模型可见上下文和危险下游动作。证明隐私成本在最终输出审核之前就已产生。

2. **拓扑放大效应（RQ2）**：无中介攻击阳性聚合中，chain₄ 原始暴露 10.33，star₄ 13.17，blackboard₄ 15.83；黑板级联大小最大、精确原始暴露最高。局部写入的下游成本取决于平台允许写入落地的位置。**高扇出对象放大传播**。

3. **事件级中介的遏制效果（RQ3）**：PAPC 在 63/63 次运行中任务成功 1.0，原始暴露 0，外部暴露 0，权限可达 0。相比无防御、静态 ACL、提示过滤，PAPC 在所有匹配组中改善或持平，无一组表现更差。说明有用协调可通过安全视图保留，而隔离阻止原始值进入高扇出共享状态。

4. **标签自由有效性（RQ4）**：移除攻击标签、攻击标识、模式和评估者标签后，PAPC 在两个矩阵中均保持任务成功 1.0、原始/外部暴露 0、评估者标签使用 0。无语义模式消融显示原始暴露上升，证明语义请求特征对捕获“洗钱”压力有帮助，但策略/扇出/安全视图仍独立贡献。

5. **平台治理内涵**：在允许抽象、禁止原始披露的策略类别下，平台应**直接治理共享运行时状态转换**，事件级中介是面向代理中介在线工作的平台治理原语。

## 7. 优点

- **概念框架新颖且清晰**：将多代理工作流中的隐私失效建模为**拓扑依赖的传播外部性**，借鉴平台经济学与隐私经济学，提供了有理论深度的分析视角（福利目标函数、拓扑放大界）。
- **事件级中介定位精准**：明确区分了最终输出控制与运行时状态转换控制的本质差异，指向真正的治理盲区。
- **机制设计完整**：五种决策动作（允许/安全视图/隔离/阻断/权限收窄）形成了一个比二进制“允许/拒绝”更灵活、更贴近实际策略需求的治理原语。安全视图重写的“策略允许抽象”设计尤其有实用价值。
- **实验设计系统性较强**：拓扑/攻击/防御/种子四维矩阵，匹配组比较方法（improved/tied 统计）客观，任务成功与泄露指标分离报告，避免了“一刀切全阻断”的伪成功。
- **标签自由验证增强可信度**：主动移除攻击标签和评估者标注，降低了“预言机标签作弊”的偏差风险。
- **公平性处理**：明确承认 PAPC 不压倒关键词过滤（同一触发切片），不做过度声明，学术态度审慎。

---

## 8. 不足与局限

- **算力信息完全缺失**：未提及 GPU、计算资源或训练/推理成本，降低了可复现性。
- **单一 LLM 提供者**：仅使用 MiniMax 作为最终写作者，未跨模型验证；更广义的 LLM 行为（如不同提供者的指令跟随能力）可能影响结果。
- **合成/模拟场景为主**：攻击、工作流、拓扑均为受控构造，缺乏真实企业部署或用户数据验证，生态效度受限制。
- **消融不完整**：只对语义特征做了部分消融，未系统隔离策略、溯源、拓扑/扇出、安全视图、隔离等子组件的独立贡献，机制归因不够严格。
- **“tied”比例偏高**：在低压力组（如 clean）或静态 ACL 已覆盖的场景中，对比区分度有限，难以凸显 PAPC 的增量价值。
- **指标范围较窄**：泄露指标为**精确原始值匹配**，未覆盖更广泛的信息推理/语义泄露（如近似值、组合推断），评估边界和现实泄露类型之间存在差距。
- **标签自由验证范围有限**：仅针对保留的改写变体，未在全部攻击变体上做标签自由验证，且标签移除的具体实现细节（哪些元数据保留）可能影响解读。
- **实现假定较强**：受保护值、所有者、授权读者、允许抽象需由工作流策略预先注册，这在实际动态多租户平台上可能面临策略注册不完整或时效性的挑战；隔离的原始载荷长期存储也引入了新的治理风险。
