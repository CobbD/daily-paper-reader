## 摘要
同态加密（HE）已成为隐私保护机器学习（PPML）的一种有前景的方法，能够直接对加密数据进行计算。在基于HE的PPML中，客户端向服务器提交加密输入，服务器在无法访问底层明文的情况下评估大语言模型（LLM）等模型。然而，我们发现了该场景下的一个关键安全漏洞：HE-LLM推理容易受到恶意客户端提交对抗性提示（如越狱攻击）的影响。保护良性客户端的机密性同样也阻止了服务器检查传入提示或生成的响应，使得对抗性尝试难以检测或阻止，并可能让成功攻击对服务器完全不可见。为了解决这一漏洞，我们提出了HE-Guardrail，这是一个完全在加密数据上评估护栏机制并以同态方式控制是否将目标模型响应返回给客户端的框架。我们用三种代表性护栏——Llama Guard、JBShield和GradSafe——实例化了HE-Guardrail。结果表明，HE-Guardrail在加密域中能高度还原相应明文护栏的决策，并体现出不同的安全性-效率-效用权衡。

## Abstract
Homomorphic encryption (HE) has emerged as a promising approach to privacy-preserving machine learning (PPML), enabling computation directly over encrypted data. In HE-based PPML, a client submits an encrypted input to the server, which evaluates models such as large language models (LLMs) without access to the underlying plaintext. However, we identify a critical security vulnerability in this setting: HE-LLM inference is vulnerable to malicious clients that submit adversarial prompts, such as jailbreak attacks. The same confidentiality that protects benign clients also prevents the server from inspecting incoming prompts or generated responses, making adversarial attempts difficult to detect or block and potentially allowing successful attacks to remain entirely invisible to the server. To address this vulnerability, we propose HE-Guardrail, a framework that evaluates guardrail mechanisms entirely over encrypted data and homomorphically controls whether the target-model response is returned to the client. We instantiate HE-Guardrail with three representative guardrails - Llama Guard, JBShield, and GradSafe. Our results show that HE-Guardrail closely reproduces the decisions of the corresponding plaintext guardrails in the encrypted domain, with distinct security-efficiency-utility trade-offs.

- **核心安全漏洞**：现有 HE-LLM 推理通常只假设服务器是半诚实（honest-but-curious）的，而默认客户端在输入选择上是良性的。本文指出，恶意客户端可以提交越狱攻击（jailbreak attacks）提示，诱使 LLM 输出有害内容。
- **关键矛盾**：保护良性客户端隐私的加密机制，同时也使服务器无法检查传入提示或生成响应，导致越狱攻击可能完全不被服务器察觉。
- **论文目标**：提出 **HE-Guardrail** 框架，在加密域内执行越狱检测护栏，并通过同态运算控制是否将目标模型响应返回给客户端，从而在不牺牲隐私的前提下阻止恶意请求。
- **整体含义**：该工作将 LLM 安全防护从明文场景扩展到加密推理场景，填补了“加密 LLM 推理中的对抗性提示防护”这一空白，并重新审视了 HE-PPML 中客户端威胁模型。

## 2. 论文提出的方法论

### 2.1 总体框架：HE-Guardrail

- **威胁模型**：
  - 服务器：半诚实，正确执行协议但可能尝试从密文中推断信息。
  - 客户端：可以是恶意的，可以提交任意明文提示（包括越狱提示），但遵循 HE 协议。
- **目标模型**：Llama-3-8B-Instruct。
- **核心组件**：
  - 加密护栏决策 \(g\)：\(g=1\) 表示安全/接受，\(g=0\) 表示有害/拒绝。
  - 使用符号函数的多项式近似将检测分数 \(p\) 与阈值 \(\delta\) 的比较转化为加密门控值：
    \[
    g = \frac{1 + \text{sgn}_{\text{poly}}(p-\delta)}{2}
    \]
    其中 \(\text{sgn}_{\text{poly}}\) 采用 minimax 复合多项式（分量度数为 15、27、29）。
  - **同态响应门控**：在第 \(t\) 个解码步，客户端看到的响应为
    \[
    Z_t(g) = gY_t + (1-g)R_t + \epsilon_t(g)
    \]
    其中 \(Y_t\) 是目标模型 token 的 one-hot 表示，\(R_t\) 是预定义拒绝响应 token 的 one-hot 表示，\(\epsilon_t(g)\) 是门控噪声淹没项。
- **门控噪声淹没**：由于多项式近似和 CKKS 噪声，被拒绝请求的门控值 \(g\) 可能不是精确 0，从而在被抑制的目标 token 坐标上残留小值。为此定义
  \[
  \epsilon_t(g) = (1-g)\xi_t
  \]
  其中 \(\xi_t\) 是服务器为每次输出新鲜采样的随机噪声向量，仅服务器知道。这样在 \(g\approx 0\) 时注入较大噪声，掩盖被抑制 token 的残差；在 \(g\approx 1\) 时噪声被抑制，不影响正常响应。

### 2.2 内部处理护栏（Intra-processing HE-Guardrails）

- **关键观察**：内部处理护栏通常需要白盒访问目标模型，在明文 API 场景下受限；但在 HE-LLM 推理中，服务器本身就拥有目标模型结构和加密内部信号，因此可以直接利用这些信号。
- **JBShield-D 适配**：
  - 使用 Llama-3-8B 第 32 层最后一个 token 的隐藏表示 \(h(x) \in \mathbb{R}^{4096}\) 作为句子表示。
  - 离线阶段：在明文上校准良性锚点 \(\mu_b\)、有害锚点 \(\mu_h\)，并从校准样本中提取 toxic 概念向量 \(s_t\) 和 jailbreak 概念向量 \(s_j\)，并预归一化。
  - 在线阶段：在加密域计算 \(c_t = h(x)-\mu_b\)、\(c_j = h(x)-\mu_h\)；对每个概念计算余弦相似度 \(\sigma_k = \langle c_k, s_k\rangle / (\|c_k\|_2 \|s_k\|_2)\)。
  - 使用 Goldschmidt 迭代计算逆平方根 \(1/\sqrt{q_k}\)。
  - 通过 \(\text{sgn}_{\text{HE}}\) 比较 \(\sigma_t\) 与阈值 0.037、\(\sigma_j\) 与阈值 0，得到两个概念激活 \(d_t,d_j\)；最终接受门控 \(g_{JB} = 1 - d_t d_j\)。
  - 简化：在线阶段消除了原本 JBShield 中的 rank-one SVD，因为单行差分矩阵的奇异方向可直接由 \(c_t/\|c_t\|_2\) 表示。
- **GradSafe-Zero 适配**：
  - 核心思想：不安全提示与固定服从响应配对时，在安全关键参数上产生相似梯度方向；安全提示则不同。
  - 离线阶段：对候选梯度切片（注意力投影权重 \(W_q,W_k,W_v,W_o\) 和 MLP 投影权重 \(W_{gate},W_{up},W_{down}\)）构造不安全梯度参考 \(r_j\)，计算不安全/安全参考提示的平均余弦相似度差 \(\Delta_j\)，保留 \(\Delta_j > 1\) 的切片集合 \(J^\star\)，并预归一化参考向量。
  - 在线阶段：
    - 在加密域执行前向传播得到预填状态，并初始化因果 LM 损失对 logits 的梯度 \( \partial L/\partial z = p - e_{r_c} \)，其中 \(p\) 是最后一个提示位置的 softmax 输出，\(e_{r_c}\) 是服从 token 的 one-hot。
    - 反向传播中逐层计算梯度，使用低层检查点（level-drop checkpointing）减少内存：检查点在前向使用后降到低乘法层级，反向需要时先 bootstrap 再对齐层级。
    - 利用前向已计算的 softmax 输出、RMSNorm 逆 RMS、SiLU 的 sigmoid 输出等，避免在反向中重新评估非线性函数。
    - 每产生一个安全关键梯度切片 \(g_j\)，立即计算其与参考 \(r_j\) 的加密余弦相似度，累加得分后丢弃梯度，以降低内存。
    - 最终得分 \(s_{GS} = A/|J^\star|\)，用 \(\text{sgn}_{\text{HE}}(s_{GS}-0.25)\) 得到决策。

### 2.3 预处理护栏（Pre-processing HE-Guardrails）

- **Llama Guard 3-8B 适配**：
  - 使用 Llama Guard 3-8B 对加密输入提示进行安全分类。
  - **多模型服务**：扩展 MOAI 的 interleaved batching，将目标模型和 Llama Guard 的不同权重分配到同一密文的交错槽位中，实现在同一组密文内同时评估两个模型，避免额外密文内存。
  - 决策：直接比较 Llama Guard 在安全 token \(t_{safe}\) 和不安全 token \(t_{unsafe}\) 上的 logits：
    \[
    m_{LG} = z_{LG}[t_{safe}] - z_{LG}[t_{unsafe}],\quad g_{LG} = \frac{1+\text{sgn}_{\text{HE}}(m_{LG})}{2}
    \]
    由于 softmax 保持 logit 顺序，无需在词汇表上执行 softmax 或生成文本解释。

## 3. 实验设计

- **评估框架**：采用 Wang et al. 的 Security-Efficiency-Utility（SEU）评估框架，从安全性、效率、效用三个维度评估。
- **攻击数据集**：六种越狱攻击家族，共 2,215 个提示/会话：
  - 单轮攻击：IJP（手工，1,000 样本）、GCG（优化，100）、AutoDAN（优化，100）、DrAttack（隐式，100）、MultiJail（隐式，315）。
  - 多轮攻击：ActorAttack（多轮，600）。
- **良性数据集**：AlpacaEval（805 样本）和 OR-Bench（1,000 样本），用于评估误拒率（FPR）。
- **有害性评判**：使用 `cais/HarmBench-Llama-2-13b-cls` 作为评判器。
- **对比方法**：无防御基线、Llama Guard 3-8B、JBShield-D、GradSafe-Zero。所有目标响应和护栏决策均在加密域计算。
- **指标**：
  - 攻击成功率 ASR = 护栏接受且被判定有害的样本占比。
  - 通过护栏率 PGR = 护栏接受的样本占比。
  - 误拒率 FPR = 良性样本中被拒绝的占比。
- **实现细节**：使用 `desilofhe` 库，RNS-CKKS 方案，槽数 \(N/2=2^{15}\)，bootstrapping 后可用乘法层级为 17；输入长度填充至 2,048 token，生成预算 200 token；多模型服务下 16 个交错槽位可承载 8 个带护栏请求。

## 6. 主要结论与发现

- **安全**：三种加密护栏 ASR 分别为 Llama Guard 7.1%、JBShield 11.0%、GradSafe 10.8%，而无防御基线为 11.0%。Llama Guard 在所有攻击家族上均降低 ASR，尤其是 GCG（13.0%→2.0%）；但 JBShield 和 GradSafe 的 ASR 与无防御几乎持平。
- **效率**：所有三种护栏均可在目标模型自回归解码期间并发执行，因此对最终响应时延的额外开销为零（在双 GPU 配置下）；但内存开销差异巨大，JBShield 最轻，GradSafe 较重，单独 Llama Guard 很重但多模型服务可消除额外密文内存。
- **效用**：Llama Guard 的 FPR 为 1.83%，高于 JBShield（0.06%）和 GradSafe（0.17%），反映了更强的攻击拒绝能力伴随更高的良性误拒。
- **加密域一致性**：加密护栏在 99.7% 的样本上复现了明文护栏的决策，表明多项式近似和 HE 噪声基本不改变安全性判断。
- **整体结论**：HE-Guardrail 能有效在加密域内执行护栏，并在隐私保护前提下防御部分越狱攻击；不同护栏设计体现了安全性、效率、效用之间的权衡。
